# Mechanical checks that keep comments and docs from going stale

Researched 2026-11-01 for #478, for the M3.5 rules ticket (map #475, decision 11) to weigh. Every number about praxis was measured on `main` at `732e58c7`; the scripts are described under Exposure so the counts can be re-run.

## Summary

The checks that hold up in practice are structural and run by a compiler or a diff: a doc link resolves, a code block compiles, a generated reference matches the build. Praxis can take the first one for free by writing a doc comment's identifiers as ``[`name`]`` links and running `cargo doc` with `-D warnings` in verify and CI; the compiler then fails on a renamed or removed name. Today 1 of 1,069 backticked doc-comment lines is a link, so the lint sees nothing, and `cargo test` never runs it (a planted broken link passed `cargo test --doc` and failed `cargo doc`). No tool checks a number in a comment against a measurement, so the practical check for numbers is a rule in `tests/conventions.rs` that flags µs, ms and % in shipping comments and sends them to `docs/performance.md`: 71 comment lines carry a unit number, 25 of them a timing or a ratio, 13 of those in shipping code. Exposure to stale identifiers is zero: of 772 distinct backticked identifiers at 1,683 sites, 30 match no code token in `src/` or `tests/`, and all 30 are external vocabulary.

Unreal's coding standard has no mechanical check: "Make sure to update comments when you change the intent of a piece of code" and "Do not contradict the code" ([standard](https://dev.epicgames.com/documentation/en-us/unreal-engine/epic-cplusplus-coding-standard-for-unreal-engine)). Bevy's lints are `missing_docs = "warn"` and `clippy::doc_markdown = "warn"` in the workspace ([Cargo.toml](https://raw.githubusercontent.com/bevyengine/bevy/main/Cargo.toml)), with `cargo doc` under `-D warnings` in CI (check 1).

## Exposure

Read-only scan of the 70 `.rs` and 16 `.wgsl` files under `src/` and `tests/` on `main` at `732e58c7`. A comment is what follows the first `//` outside a string literal on a line, the `///` and `//!` markers included; 5,690 lines carry one (3,113 under `src/render/`, 2,158 elsewhere in `src/`, 419 in `tests/`). The script lives outside the repo; its patterns, Python `re` syntax:

- Unit number: `(?<![\w.])\d[\d,_]*(?:\.\d+)?\s?(?:ms|µs|us|ns|bytes?|B|KB|KiB|MB|MiB|GB|GiB|px)\b` or `\d[\d,_]*(?:\.\d+)?\s?%`.
- Count: `(?<![\w.,`#])([2-9]|[1-9]\d+)(?:,\d{3})*\s+([A-Za-z][A-Za-z_-]+)\b`, the second word not in a stop list (of, to, and, in, per, times, x, …), on lines with no unit number.
- Identifier: each `` `…` `` span; a span with a `/` and no space is a path, checked on disk; otherwise its `[A-Za-z_][A-Za-z0-9_]*` tokens, less Rust and WGSL keywords, primitives and builtins, are looked up as whole tokens (`(?<![A-Za-z0-9_])name(?![A-Za-z0-9_])`) in the non-comment part of every `src/` and `tests/` line, then in every other file of the tree.

The 30 unmatched identifiers: glTF property names (`emissiveTexture`, `occlusionTexture`), Metal, D3D12 and Vulkan API names (`MTLIndirectAccelerationStructureInstanceDescriptor`, `D3D12_RAYTRACING_INSTANCE_DESC`, `VkAccelerationStructureInstanceKHR`, `VK_KHR_swapchain_mutable_format`, `VK_VENDOR_ID_MESA`, `currentAllocatedSize`, `maxStorageBufferRange`, `standardSampleLocations`, `SURFACE_VIEW_FORMATS`, `QUERY_USER_NOTIFICATION_STATE`, `pci`), wgpu's environment variables and options (`WGPU_DEBUG`, `WGPU_VALIDATION`, `WGPU_DX12_COMPILER`, `retain_command_buffer_references`, the `Performance` memory hint), Bevy's `lux::DIRECT_SUNLIGHT`, meshoptimizer's `meshopt_buildMeshletsScan`, tools and features (`rustfmt`, `shasum`, the `multi_threaded` Cargo feature), notation (`xyzw`, a `d7` hash prefix, `ID` as the glossary term), glam's `Affine3A` named as what a type replaced, and the two planted test strings `NdotV` and `NoV`. Nineteen of them appear in `docs/references.toml` or another document; eight appear nowhere else in the tree.

The 13 shipping timing lines: `src/bench/mod.rs` 129, 130, 139 (the noise floor), `src/capture/mod.rs` 283, `src/gpu/mod.rs` 12, `src/render/acceleration_structures.rs` 64, `src/render/targets.rs` 315, `src/render/tonemapping_pass.rs` 16, `src/render/shaders/main.wgsl` 209, `src/render/shaders/shading.wgsl` 110 and 182, `src/assets/material.rs` 25, `src/transform/mod.rs` 20. Most of the 44 size lines state a layout a test already pins: `src/render/shader_tests.rs` compares the structs' sizes with their WGSL twins and `tests/frame_stats.rs` asserts the buffers' bytes.
