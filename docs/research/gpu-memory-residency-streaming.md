# GPU memory, residency and streaming: state of the art

Researched 2026-10-12 for ticket #46; it feeds #21 (GPU memory and residency) and the cooked format (#23). Sources: SIGGRAPH Advances and GDC slides and session pages; papers (SIGGRAPH 1998, I3D 2001, ECRTS 2004, IEEE Visualization 2004 and 2005, id Software 2012, a 2020 Fraunhofer Singapore paper, Proc. ACM CGIT July 2024); vendor documentation (Microsoft Learn, DirectX-Specs `a610933`, Vulkan-Docs `193ebe1`, Apple developer documentation and WWDC22 session 10104, and Epic's Unreal Engine 5 documentation read through web.archive.org snapshots because dev.epicgames.com did not resolve from this machine); source code (wgpu at tag v29.0.1 and its v30.0.1 changelog, Bevy v0.20.0, and the GitHub repositories linked at the commits named); vulkan.gpuinfo.org (default "Recent (1y)" filter, share of devices, cited as gpuinfo W/L); and a Swift scratch program, not in the repo, that read `MTLDevice` properties on the M4 Pro under macOS 27.0.1. Boundaries: culling and rasterization of virtual geometry are #45, upload threading, barriers and queues are #47, codecs, ratios and codec IP are #48; this note covers memory, residency, page sizes, request feedback and where decompression sits.

Praxis moved to wgpu 30.0.1 on 2026-10-12 ([#55](https://github.com/gariasf/praxis/issues/55)); the After 29.0.1 row below lists what changed. wgpu links point at tag v29.0.1 and reuse the [capability matrix](wgpu-capability-matrix.md) labels: `mtl`, `vk`, `dx` are wgpu-hal `{metal,vulkan,dx12}/adapter.rs`; a `-dev`, `-cmd`, `-conv`, `-mod`, `-sub` suffix is that backend's `device.rs`, `command.rs`, `conv.rs`, `mod.rs`, `suballocation.rs`; `hal` is wgpu-hal `lib.rs`; `core-*`, `wgt-*` and `wgpu-*` are wgpu-core, wgpu-types and wgpu files; `cap` is the capability matrix and `cl30` the [CHANGELOG at v30.0.1](https://github.com/gfx-rs/wgpu/blob/v30.0.1/CHANGELOG.md). Slide and paper links open a PDF page (`#page=N`), not the printed slide number.

## Techniques

**1. Mip streaming from CPU heuristics.** Titanfall 2 precomputes, per 16 ft² world column, each material's pixel coverage per mip from GPU-rendered probes (at most 8 per column), stores the 512 most important records per column, groups 4×4 columns into ~32 KiB pages, and each frame loads the most valuable mips and drops the least, never dropping mips under 64 KiB ([TF2 p6](https://media.gdcvault.com/gdc2017/Presentations/Barb_Chad_EfficientTextureStreaming.pdf#page=6), [p10](https://media.gdcvault.com/gdc2017/Presentations/Barb_Chad_EfficientTextureStreaming.pdf#page=10), [p12](https://media.gdcvault.com/gdc2017/Presentations/Barb_Chad_EfficientTextureStreaming.pdf#page=12)); it reads in 64 KiB chunks and queues drops for 3 frames, and on Windows it first resized a texture by creating a new one and copying old and new mips on the GPU, later by loading into a heap passed to texture creation ([p19](https://media.gdcvault.com/gdc2017/Presentations/Barb_Chad_EfficientTextureStreaming.pdf#page=19), [p18](https://media.gdcvault.com/gdc2017/Presentations/Barb_Chad_EfficientTextureStreaming.pdf#page=18)); wgpu offers the first, or a full re-upload through staging, but cannot load file data straight into texture memory. Unreal derives a "wanted" resolution from the distance to each texture instance's bounding box, computed at build time, and the mesh's texture-coordinate size per world unit, inside a texture pool sized by `r.Streaming.PoolSize` ([UE build data](https://web.archive.org/web/20250403154235/https://dev.epicgames.com/documentation/en-us/unreal-engine/building-texture-streaming-data-in-unreal-engine), [UE configuration](https://web.archive.org/web/20250810013810/https://dev.epicgames.com/documentation/en-us/unreal-engine/texture-streaming-configuration-in-unreal-engine)). The only research since 2019 found is Zhang et al. (2020), who allocate cache memory in Vulkan sparse images "based on mesh visibility weightings and estimated GPU bandwidth" (row 4, [p1](https://www.fraunhofer.sg/content/dam/singapur/documents/Publications/High%20Performance%20Texture%20Streaming%20and%20Rendering%20of%20Large%20Textured%203D%20Cities.pdf#page=1)). The published CPU figure (0.8 ms, console) is small against ADR 0013's 6 ms; in Praxis the open costs are bind-group rebuilds and the Material pool's texture arrays, which hold one size and mip count per array.

**2. Hardware sampler feedback.** D3D12 sampler feedback records, per mip region, the finest mip a sample wanted; for streaming the spec pairs it with an application-owned MinMip texture that clamps sampling to what is resident and recommends tiled resources tier 2 ([SF spec L10](https://github.com/microsoft/DirectX-Specs/blob/a610933eac2103cd502bacfb5193ae7f02c6fa54/d3d/SamplerFeedback.md#L10-L30), [L81](https://github.com/microsoft/DirectX-Specs/blob/a610933eac2103cd502bacfb5193ae7f02c6fa54/d3d/SamplerFeedback.md#L81-L112)). Intel's MIT sample streams 64 KB tiles (256×256 texels for BC7) of reserved resources; feedback is read after drawing, so loads land in a later frame, evictions wait one or two frames, a 16k² BC7 texture (350 MB) needs a 4 KB residency texture, and GPU time is mostly feedback resolves, which the sample caps per frame because resolving "adds up when there are 1000 objects" ([SFS L161](https://github.com/GameTechDev/SamplerFeedbackStreaming/blob/714e144df957336fa36022acabaa19e826f9850c/README.md#L161), [L175](https://github.com/GameTechDev/SamplerFeedbackStreaming/blob/714e144df957336fa36022acabaa19e826f9850c/README.md#L175-L183), [L221](https://github.com/GameTechDev/SamplerFeedbackStreaming/blob/714e144df957336fa36022acabaa19e826f9850c/README.md#L221), [L253](https://github.com/GameTechDev/SamplerFeedbackStreaming/blob/714e144df957336fa36022acabaa19e826f9850c/README.md#L253-L259)). Microsoft's Xbox One X analysis found that the GPU "often accesses less than 1/3 of the texture data required to be loaded in memory" ([Xbox 2020](https://web.archive.org/web/20201216073533/https://news.xbox.com/en-us/2020/07/14/a-closer-look-at-xbox-velocity-architecture/)). wgpu 29 exposes no sampler feedback, and the Apple documentation read offers sparse-texture access counters for this purpose instead (row 4).

**3. Software virtual texturing.** The shader translates a virtual address through a page table into a fixed physical page cache that feedback fills; clipmaps ([Tanner et al. 1998](https://doi.org/10.1145/280814.280855)) are the foundation and Barrett's GDC 2008 demo is in the public domain ([SVT](https://silverspaceship.com/src/svt/)). id Tech 5 (RAGE) used 128×128 pages carrying 120×120 texels inside a 4-texel border, 4096² physical textures, an 80×60 feedback buffer, 8 to 16 pages transcoded per frame, and frame-old feedback ([vW p10](https://mrelusive.com/publications/papers/Software-Virtual-Textures.pdf#page=10), [p14](https://mrelusive.com/publications/papers/Software-Virtual-Textures.pdf#page=14), [p22](https://mrelusive.com/publications/papers/Software-Virtual-Textures.pdf#page=22), [p24](https://mrelusive.com/publications/papers/Software-Virtual-Textures.pdf#page=24)). Far Cry 4's adaptive variant covers a 10 km by 10 km world, ADR 0013's Game world size, at 10 texels/cm ([GDC 2015 abstract](https://gdcvault.com/play/1021760/Adaptive-Virtual-Texture-Rendering-in)). In Unreal Engine 5 a virtual sample costs at least two fetches, the default 4-texel border limits anisotropic filtering, mips below the tile size are missing so noisy textures can alias or show moiré, and streaming "is reactive by nature", so tiles pop in ([UE SVT](https://web.archive.org/web/20251201111137/https://dev.epicgames.com/documentation/en-us/unreal-engine/streaming-virtual-texturing-in-unreal-engine)). Research since 2019 is thin; the closest found is Zhang et al. (row 4). In WGSL the level must be computed from `dpdx` and `dpdy` and passed to `textureSampleGrad` or `textureSampleLevel`; nothing accumulates over frames, but the missing low mips are a stability risk under ADR 0008.

**4. Hardware sparse textures.** The API reserves address space and commits memory per tile: D3D12 reserved resources in 64 KB tiles, at tier 2 or higher on every feature level 12_0 adapter ([MS tiers](https://learn.microsoft.com/en-us/windows/win32/api/d3d12/ne-d3d12-d3d12_tiled_resources_tier)); Vulkan sparse residency with 64 KB standard block shapes bound by `vkQueueBindSparse` ([sparsemem L417](https://github.com/KhronosGroup/Vulkan-Docs/blob/193ebe195f47ffc5004683d1659e71c725658c4d/chapters/sparsemem.adoc#L417-L423)); Metal sparse textures in a sparse heap from Apple6, mapped asynchronously by a resource state encoder, 16 KB tiles plus 64 and 256 KB since Metal 3 ([Apple sparse](https://developer.apple.com/documentation/metal/assigning-memory-to-sparse-textures), [WWDC22](https://developer.apple.com/videos/play/wwdc2022/10104/)). Mapping is the cost: Zhang et al. found bind time growing quadratically with every block bound, "especially when memory blocks are sparsely bound across more than thirty sparse image layers", and Intel saw `UpdateTileMappings` CPU time grow with heap fragmentation on non-Intel GPUs, working around it with 127 heaps of 32 MB ([SFS L154](https://github.com/GameTechDev/SamplerFeedbackStreaming/blob/714e144df957336fa36022acabaa19e826f9850c/README.md#L154-L157)). Metal adds `sparse_sample` and `min_lod_clamp` in MSL and cache-miss access counters that tell which unmapped tiles were sampled; Apple demoed streaming with them on an M1 Pro ([Apple counters](https://developer.apple.com/documentation/metal/estimating-how-often-a-texture-region-is-accessed), [Apple sparse sampling](https://developer.apple.com/documentation/metal/reading-and-writing-to-sparse-textures), [WWDC22](https://developer.apple.com/videos/play/wwdc2022/10104/)). Metal residency sets do not cover sparse heaps ([MTLResidencySet](https://developer.apple.com/documentation/metal/mtlresidencyset)), and placement sparse buffers need macOS 26 ([makeBuffer](https://developer.apple.com/documentation/metal/mtldevice/makebuffer%28length:options:placementsparsepagesize:%29)).

**5. Mesh LOD and HLOD streaming.** LOD chains and hierarchical proxies ([Erikson et al. 2001](https://doi.org/10.1145/364338.364376)) stream per region into shared buffers; Unreal's World Partition replaces unloaded grid cells with HLOD proxy meshes whose layers set their own cell size and loading range ([UE HLOD](https://web.archive.org/web/20250825185139/https://dev.epicgames.com/documentation/en-us/unreal-engine/world-partition---hierarchical-level-of-detail-in-unreal-engine)), and Ghost of Tsushima's GDC 2021 abstract describes "switching to a fine-grained streaming model" ([abstract](https://gdcvault.com/play/1027205/Zen-of-Streaming-Building-and); slides members-only). No memory or millisecond figures were found. On wgpu this is ADR 0002: offsets into the vertex and index mega-buffers, sub-allocated as in row 7. Praxis today doubles each mega-buffer and re-uploads a CPU shadow copy of all geometry ([pools.rs](../../src/assets/pools.rs)); growth by GPU copy would need `COPY_SRC` on those buffers.

**6. Virtual geometry.** Quick-VDR ([Yoon et al. 2004](https://doi.org/10.1109/VISUAL.2004.86)) and Batched Multi-Triangulation ([Cignoni et al. 2005](https://doi.org/10.1109/VISUAL.2005.1532797)) are "the prior work we primarily build upon" for Nanite ([Karis p44](https://advances.realtimerendering.com/s2021/Karis_Nanite_SIGGRAPH_Advances_2021_final.pdf#page=44)). Nanite packs cluster groups (8 to 32 clusters of ~2 KB) into fixed 128 KB pages "to avoid memory fragmentation", keeps the root page and the full culling hierarchy resident, stores resident pages in one GPU buffer, and has the culling pass emit page requests with LOD-error priority that the CPU reads back asynchronously to load and evict ([Karis p123](https://advances.realtimerendering.com/s2021/Karis_Nanite_SIGGRAPH_Advances_2021_final.pdf#page=123) to [p127](https://advances.realtimerendering.com/s2021/Karis_Nanite_SIGGRAPH_Advances_2021_final.pdf#page=127)); Unreal documents 14.4 bytes per input triangle on disk for Valley of the Ancients and a streaming pool sized by `r.Nanite.Streaming.StreamingPoolSize` ([UE Nanite](https://web.archive.org/web/20251221042229/https://dev.epicgames.com/documentation/en-us/unreal-engine/nanite-virtualized-geometry-in-unreal-engine)). Outside memory, Nanite relies on TAA to smooth sub-pixel LOD switches instead of geomorphing or cross-fading ([p67](https://advances.realtimerendering.com/s2021/Karis_Nanite_SIGGRAPH_Advances_2021_final.pdf#page=67)) and does not support MSAA (UE Nanite). Bevy's implementation on wgpu needs 64-bit texture atomics (Apple9, so the M4 Pro), is "not compatible with" MSAA, and at v0.20.0 uploads whole meshlet assets into range-allocated buffers that grow by doubling and a GPU copy ([mod.rs L94](https://github.com/bevyengine/bevy/blob/v0.20.0/crates/bevy_pbr/src/meshlet/mod.rs#L94-L126), [persistent_buffer.rs L51](https://github.com/bevyengine/bevy/blob/v0.20.0/crates/bevy_pbr/src/meshlet/persistent_buffer.rs#L51-L53), [L94](https://github.com/bevyengine/bevy/blob/v0.20.0/crates/bevy_pbr/src/meshlet/persistent_buffer.rs#L94-L106)). AMD's DGF (Proc. ACM CGIT 2024; tests on a Radeon 7900 XT) stores clusters in 128-byte blocks of at most 64 triangles and 64 vertices, with a provisional Vulkan extension ([DGF p3](https://gpuopen.com/download/publications/DGF.pdf#page=3), [p9](https://gpuopen.com/download/publications/DGF.pdf#page=9), [VK_AMDX_dense_geometry_format](https://github.com/KhronosGroup/Vulkan-Docs/blob/193ebe195f47ffc5004683d1659e71c725658c4d/chapters/VK_AMDX_dense_geometry_format/dense_geometry_format.adoc#L11-L19), [IP status](https://github.com/KhronosGroup/Vulkan-Docs/blob/193ebe195f47ffc5004683d1659e71c725658c4d/appendices/VK_AMDX_dense_geometry_format.adoc#L9-L12)); NVIDIA's RTX Mega Geometry sample streams cluster groups within a budget and grows cluster acceleration-structure storage through a sparse buffer because host-side size estimates are "often 3-5x bigger than actual" ([vk_lod_clusters L177](https://github.com/nvpro-samples/vk_lod_clusters/blob/20352f04a5bce46938ca63871c1389b0fac921fa/README.md#L177-L182)). wgpu-types 29 has no cluster acceleration-structure or DGF feature.

**7. Sub-allocation.** TLSF ([Masmano et al. 2004](https://doi.org/10.1109/EMRTS.2004.1311009)) has been VMA's default since 3.0.0 ([VMA L132](https://github.com/GPUOpen-LibrariesAndSDKs/VulkanMemoryAllocator/blob/bfb2ca99e1e7e9684dc06546b552ee3eff4b10aa/CHANGELOG.md#L132)); Aaltonen's OffsetAllocator (MIT, 2023) bounds waste with 256 floating-point size bins. Bevy's slabs use a Rust port of it, start at 1 MiB, grow by 1.5x through a new buffer and a GPU copy up to 512 MiB, and give objects over 256 MiB their own buffer ([slab_allocator L46](https://github.com/bevyengine/bevy/blob/v0.20.0/crates/bevy_render/src/slab_allocator.rs#L46-L50), [L145](https://github.com/bevyengine/bevy/blob/v0.20.0/crates/bevy_render/src/slab_allocator.rs#L145-L195), [L855](https://github.com/bevyengine/bevy/blob/v0.20.0/crates/bevy_render/src/slab_allocator.rs#L855-L906)). Compaction is the application's job: VMA's defragmentation returns moves, and the application re-creates each resource, copies it and re-points descriptors ([VMA defragmentation](https://gpuopen-librariesandsdks.github.io/VulkanMemoryAllocator/html/defragmentation.html)). Inside wgpu, Vulkan and DX12 already sub-allocate through gpu-allocator 0.28 (best-fit free lists, [free_list_allocator L24](https://github.com/Traverse-Research/gpu-allocator/blob/0.28.0/src/allocator/free_list_allocator/mod.rs#L24)), while Metal creates one native object per wgpu buffer or texture (next section). No peer-reviewed allocator work since 2019 was found.

**8. Budget-driven residency.** D3D12 reports the budget through `QueryVideoMemoryInfo`; unified-memory adapters have one pool, destroying heaps frees residency more reliably than `Evict`, and default priorities favour render targets ([MS residency](https://learn.microsoft.com/en-us/windows/win32/direct3d12/residency)). Vulkan has `VK_EXT_memory_budget` (gpuinfo 89.54 % W, 93.14 % L), `VK_EXT_memory_priority` (76.51 %, 55.61 %) and `VK_EXT_pageable_device_local_memory` (49.17 %, 27.69 %), the last letting the OS page device-local memory instead of failing allocations ([budget](https://github.com/KhronosGroup/Vulkan-Docs/blob/193ebe195f47ffc5004683d1659e71c725658c4d/appendices/VK_EXT_memory_budget.adoc), [pageable](https://github.com/KhronosGroup/Vulkan-Docs/blob/193ebe195f47ffc5004683d1659e71c725658c4d/appendices/VK_EXT_pageable_device_local_memory.adoc), [gpuinfo](https://vulkan.gpuinfo.org/listextensions.php?platform=windows)). Metal residency sets (macOS 15, up to 32 per command buffer or queue, no hazard tracking) replace per-encoder `useResource` calls, which "require CPU overhead for each resource or heap, which scale up with each one you add" ([MTLResidencySet](https://developer.apple.com/documentation/metal/mtlresidencyset), [guide](https://developer.apple.com/documentation/metal/simplifying-gpu-resource-management-with-residency-sets)); the OS may discard volatile (purgeable) resources under memory pressure, and on iOS and tvOS they do not count toward the app's memory limit ([Apple footprint](https://developer.apple.com/documentation/metal/reducing-the-memory-footprint-of-metal-apps)). On the M4 Pro `recommendedMaxWorkingSetSize` reads 19,069,665,280 bytes (17.76 GiB, computed) out of 25,769,803,776 bytes of physical memory (measured), above ADR 0013's 8 GB, so the engine ledger is the binding limit. Engines evict by their own priority: Titanfall 2 drop lists, Nanite low-priority pages, Intel's reference counts.

**9. Render-graph transient aliasing.** Frostbite's FrameGraph allocates transient resources at first use and releases them after last use; in the frame the talk shows, transient memory fell from 147 MB to 80 MB at 720p on DX12 PC (77 MB on PS4, 76 MB on Xbox One) and from 1042 MB to 472 MB at 4K, with aliasing barriers and a discard or clear as each resource's first operation ([FG p42](https://media.gdcvault.com/gdc2017/Presentations/ODonnell_Yuriy_FrameGraph.pdf#page=42), [p47](https://media.gdcvault.com/gdc2017/Presentations/ODonnell_Yuriy_FrameGraph.pdf#page=47), [p48](https://media.gdcvault.com/gdc2017/Presentations/ODonnell_Yuriy_FrameGraph.pdf#page=48), [p49](https://media.gdcvault.com/gdc2017/Presentations/ODonnell_Yuriy_FrameGraph.pdf#page=49), [p56](https://media.gdcvault.com/gdc2017/Presentations/ODonnell_Yuriy_FrameGraph.pdf#page=56), [p57](https://media.gdcvault.com/gdc2017/Presentations/ODonnell_Yuriy_FrameGraph.pdf#page=57)). Unreal's RDG transient allocator reports "a significant reduction in the GPU memory watermark" without a figure and keeps resource pooling as its fallback ([UE RDG](https://web.archive.org/web/20251112072340/https://dev.epicgames.com/documentation/en-us/unreal-engine/render-dependency-graph-in-unreal-engine)); AMD's RPS SDK (open beta 2022, MIT since 2024) ships an aliasing memory scheduler ([RPS](https://github.com/GPUOpen-LibrariesAndSDKs/RenderPipelineShaders/blob/f3330f5306d15af8529a310f6255225c864b0961/README.md#L5-L24)). The native mechanisms are D3D12 placed resources with aliasing barriers ([MS aliasing](https://learn.microsoft.com/en-us/windows/win32/direct3d12/memory-aliasing-and-data-inheritance)) and Metal heaps, whose resources are untracked by default ([Apple hazard tracking](https://developer.apple.com/documentation/metal/mtlheapdescriptor/hazardtrackingmode)). wgpu has neither, so the safe-API option is pooling textures with identical descriptors; peak transient bytes then equal the sum of the live pooled textures.

**10. Memoryless attachments.** Apple: "most render passes don't store depth attachments and multisample attachments to memory. You can significantly reduce your memory usage by creating these attachments as memoryless resources" ([Apple memoryless](https://developer.apple.com/documentation/metal/mtlstoragemode/memoryless)). At 2560×1440 one 4x MSAA RGBA8 or Depth32Float attachment is 58,982,400 bytes (computed: 3,686,400 pixels × 4 bytes × 4 samples). wgpu maps `TextureUsages::TRANSIENT` to memoryless storage on Metal (`transient_saves_memory` is true from Apple1, cap) and resolves MSAA through `MultisampleResolve` ([mtl-conv 312](https://github.com/gfx-rs/wgpu/blob/v29.0.1/wgpu-hal/src/metal/conv.rs#L312-L319)); on Vulkan it saves memory only where a lazily allocated memory type exists (6.24 % W, 3.43 % L), and on DX12 never. The ADR 0013 ledger counts created textures, so a memoryless attachment adds bytes to it unless the ledger reads `transient_saves_memory`.

**11. GPU decompression and direct I/O.** DirectStorage 1.1 (2022-11-07) runs GDeflate decompression on a compute queue next to two copy queues, through vendor metacommands or a DirectCompute fallback on any D3D12 Shader Model 6.0 GPU; GDeflate splits a DEFLATE stream into 32 sub-streams and tiles that decompress to 64 KiB ([DS 1.1](https://devblogs.microsoft.com/directx/directstorage-1-1-now-available/), [GDeflate L15](https://github.com/microsoft/DirectStorage/blob/c53f1499d5f67a61b69a1a348d22dcd2b4cb4ede/GDeflate/GDeflate/README.md#L15)). Ratchet & Clank: Rift Apart on PC uses GPU decompression "at high graphics settings" and Portal: Prelude RTX uses GDeflate through Vulkan extensions ([NVIDIA 2023](https://www.nvidia.com/en-gb/geforce/news/rtx-io-for-geforce-gpus-available-now/)); `VK_NV_memory_decompression` (31.01 % W, 22.2 % L) and `VK_EXT_memory_decompression` (2025; 19.82 % W, 11.44 % L) take GDeflate 1.0 in 64 KB blocks ([VK_EXT appendix](https://github.com/KhronosGroup/Vulkan-Docs/blob/193ebe195f47ffc5004683d1659e71c725658c4d/appendices/VK_EXT_memory_decompression.adoc#L28-L38)). Metal 3's fast resource loading queues file-to-buffer and file-to-texture loads with priorities, cancellation and "inline decompression" of chunked LZ4, zlib, LZBitmap, LZFSE or LZMA files, 64 KB chunks in Apple's example ([WWDC22](https://developer.apple.com/videos/play/wwdc2022/10104/)). Nanite transcodes its disk format on the GPU at ~50 GB/s on PS5 after hardware LZ ([Karis p138](https://advances.realtimerendering.com/s2021/Karis_Nanite_SIGGRAPH_Advances_2021_final.pdf#page=138)). wgpu has no I/O queue or decompression API; the GDeflate HLSL reference builds its vote, shuffle and scan from wave intrinsics when `USE_WAVE_INTRINSICS` is defined and from workgroup shared memory otherwise ([GDeflate.hlsl L76](https://github.com/microsoft/DirectStorage/blob/c53f1499d5f67a61b69a1a348d22dcd2b4cb4ede/GDeflate/shaders/GDeflate.hlsl#L76-L140)), so a WGSL port could use Tier 1 subgroups (cap) or neither.

**12. Residency feedback and readback.** Every feedback system in the sources reads GPU-written requests on the CPU later: id Tech 5 uses frame-old feedback, Nanite reads page requests back asynchronously, Intel's sample serves a frame's requests in a later frame, and vk_lod_clusters downloads its request list at the end of each frame and loads within per-frame limits and the memory budget ([streaming.md L65](https://github.com/nvpro-samples/vk_lod_clusters/blob/20352f04a5bce46938ca63871c1389b0fac921fa/docs/streaming.md#L65-L83)). Eviction waits for the GPU too: Intel's sample delays it one or two frames and Titanfall 2 three. In wgpu the request buffer is copied into a `MAP_READ | COPY_DST` buffer, or mapped directly with `MAPPABLE_PRIMARY_BUFFERS` (on every backend, cap), and `map_async` calls back after the submission completes.

## Options (no recommendation)

Today the Material pool holds 5 Channels × 8 Layers as RGBA8 2048² texture arrays without mips, 640 MiB allocated eagerly ([material.rs](../../src/assets/material.rs), ADR 0011), and the Mesh pool sub-allocates one vertex and one index mega-buffer ([pools.rs](../../src/assets/pools.rs)). Allocation (row 7) and transient memory (rows 9 and 10) combine with any option. Every option is judged against the ADR 0013 ledger, which counts what the engine creates: memoryless attachments only count as zero if the ledger reads `transient_saves_memory`, and sparse textures only count as their mapped tiles if the ledger tracks mappings. Each option ends with its image-quality consequences, which the owner ranks first ([map decision](https://github.com/gariasf/praxis/issues/17#issuecomment-6128603845)).

- **A. Mip streaming in the safe API.** Rows 1, 5, 7, 8, 10, and 11 with CPU decompression on worker threads; row 12 is not required; at its coarsest, whole textures per Chunk with no mip changes at runtime. Material pool: Layers stop being slices of fixed 2048² arrays; each Channel becomes a binding array of individually sized textures indexed by the Material (Tier 1 `TEXTURE_BINDING_ARRAY` and `PARTIALLY_BOUND_BINDING_ARRAY`, cap) or one array per size and format class with its own Layer capacity, and every mip change rebuilds that Channel's bind group. Mega-buffers: fixed arenas sized from the Budget with an offset allocator, growth by GPU copy at load points or never, in place of ADR 0002's interim CPU re-upload. Cooked format (#23): mips as separately loadable blobs with a resident tail (Titanfall 2 kept mips under 64 KiB resident and read 64 KiB chunks), mesh LODs per Chunk. Needs from wgpu: Tier 1 only. Image quality: every texture stays an ordinary mip chain, so hardware trilinear and anisotropic filtering are unchanged; a mip that arrives late shows as blur until it lands, and the worst case is the always-resident tail; nothing accumulates over frames.
- **B. Software virtual texturing with mesh LOD streaming.** Rows 3 and 12 for textures, 5 and 7 for geometry, 9 as pooling, 10. Material pool: each Channel becomes a virtual texture space backed by one fixed physical page cache (a texture or texture array per Channel format); a Layer becomes a region or per-texture page table in that space, the fixed count of 8 disappears, and Layer 0's neutral default becomes a page that never leaves. Mega-buffers as in A. Cooked format: per-mip tiles of one texel size with borders (id Tech 5: 128×128 including a 4-texel border), block-compressed per tile (#48), plus a tile index per texture. Needs from wgpu: core storage buffers, `textureSampleGrad`, derivatives and `map_async`; the shader computes its own level and pays at least two fetches per sample (Unreal). Image quality: the border caps anisotropy (a 4-texel border allows up to 8x, [vW p10](https://mrelusive.com/publications/papers/Software-Virtual-Textures.pdf#page=10); Unreal's default of 4 "allows for less anisotropic filtering than is typical"), mips smaller than a tile are missing, so noisy textures can alias or show moiré, and tiles arrive a frame or more after they were needed (rows 3 and 12); nothing accumulates over frames.
- **C. Virtual geometry pages, with A or B for textures.** Rows 6 and 12 for geometry. Mega-buffers: ADR 0002's growing vertex and index buffers become a fixed page pool for cluster data plus a sub-allocated buffer for meshes that are not virtualized; one storage binding stops at 2^31-1 bytes on Vulkan and DX12, and storage-buffer binding arrays are Vulkan-only until v30.0.0 adds Metal (cap). Cooked format: cluster groups packed into fixed pages (Nanite: 128 KB) with page-range dependencies and an always-resident hierarchy; the in-memory cluster encoding (DGF's 128-byte blocks or another) is #48's. Material pool: as in A or B. Needs: the rasterization path (#45). Image quality: Nanite keeps LOD error under a pixel and relies on TAA to smooth the switches that remain ([p67](https://advances.realtimerendering.com/s2021/Karis_Nanite_SIGGRAPH_Advances_2021_final.pdf#page=67)), so without TAA nothing smooths them; neither Nanite nor Bevy supports MSAA, which leaves SMAA as ADR 0008's only anti-aliasing for that geometry.
- **D. Hardware sparse and native residency through wgpu-hal.** Row 4, with row 2 on D3D12 or Metal access counters for feedback, 8 with residency sets or D3D12 priorities, 9 with native heaps, 11 with DirectStorage or Metal fast resource loading; ADR 0007 allows wgpu-hal for a subsystem that exceeds the safe API. Material pool: Layers could stay array slices committed per tile (Metal sparse texture arrays not verified). Mega-buffers: unchanged, or sparse buffers where available (Metal placement sparse buffers need macOS 26). Cooked format: tiles follow the API (64 KB on D3D12 and Vulkan standard blocks; 16, 64 or 256 KB on Metal), so one layout for every backend means 64 KB tiles on Metal. Needs: per-backend code that creates native sparse textures, wraps them with `create_texture_from_hal` and records mappings on the raw command buffer (Metal, [mtl-cmd 153](https://github.com/gfx-rs/wgpu/blob/v29.0.1/wgpu-hal/src/metal/command.rs#L153)) or queue (Vulkan, [vk-dev 767](https://github.com/gfx-rs/wgpu/blob/v29.0.1/wgpu-hal/src/vulkan/device.rs#L767)); wgpu-core does not know about mappings, and v30.0.0 adds queue hooks that make a submit wait on a foreign fence, semaphore or shared event, such as one signalled by an I/O queue. None of these paths was tried. Image quality: textures keep hardware filtering, and sampling clamps per region to what is resident (MSL `min_lod_clamp`; D3D12 MinMip maps, [SF spec L101](https://github.com/microsoft/DirectX-Specs/blob/a610933eac2103cd502bacfb5193ae7f02c6fa54/d3d/SamplerFeedback.md#L101-L112)); Intel's sample shows cracks where anisotropic sampling reaches unmapped tiles, which read black, "sometimes" visible when a fast object enters the view ([SFS L159](https://github.com/GameTechDev/SamplerFeedbackStreaming/blob/714e144df957336fa36022acabaa19e826f9850c/README.md#L159-L169)).
