Praxis

Field guides

Praxis is a 3D engine in Rust for large open-world games. Each guide teaches the ideas behind one part of it through the tickets and pull requests that built that part, with live demos. Each is dated: it names the commit it describes and says what has changed on main since.

Suggested reading order

Start with Instance Buffer Explained. The path it follows, from the ECS World through prepare and upload to the GPU, still holds, but its map of the frame is from 2026-10-19, when one render pass issued a draw call per Primitive of each Renderable; the frame on main, after the guides, lists its passes now. Each card names its milestone, tickets and pull requests.

  21. Meshlet Culling Explained

    M3 · ticket #347 · PRs #363, #371

    Follows #347's two parts. The culling pass now writes the frame's packed indices with a workgroup per Meshlet record, dispatched indirectly with a count the GPU sums.   22. MSAA Fragment Merging Explained

    M3 · tickets #348, #369 · PRs #370, #373

    Follows #348's finding. The frame on main

One frame as the main branch runs it at commit 270c5e4 (2026-10-26), with the guide that explains each step. On the CPU, prepare reads the ECS World into Frame data, and upload writes the frame's uniforms, lights and Instance writes into per-frame staging (Instance Buffer Explained). Upload records their copies into GPU buffers at the head of the frame's commands, with the static TLAS's rebuild in a frame that writes or frees a static Instance (Acceleration Structures Explained). The GPU receives the steps below in this order, though on Metal a step can run beside the steps around it, or even start before an earlier one, where neither writes what the other binds:

  1. The dynamic TLAS's build over the frame's Moving Instances, in frames that have any and once more, empty, when the last one goes, in a command buffer submitted ahead of the frame's commands (Dynamic TLAS Explained).
  2. The bend pass, in frames that bend Meshes, which only the crowd scene does: each figure bent from its rest Mesh (Crowd Shadows Explained). With the crowd's refit form, chosen by a Render switch and available on Metal only, the frame's commands up to the bend pass are submitted first, with the refit of each figure's BLAS, and the dynamic TLAS's build follows them (BLAS Refit Explained).
  3. Phase one of the culling pass, which builds the draw of the Instances in view that were visible the frame before (Instance Culling Explained).
  4. The Froxel pass, which lists for each Froxel the point lights that may reach it (Froxel Lights Explained).
  5. The depth pre-pass, which draws phase one's Instances into the 4x MSAA depth target, and with shadow rays on each sample's surface normals beside it (Instance Culling Explained; the normals since #350).
  6. The depth pyramid pass, which reduces that depth, level by level, to the farthest depth over each texel's share of the screen (Depth Pyramid Explained).
  7. Phase two of the culling pass, which builds the draw of the other Instances in view that the pyramid does not hide (Instance Culling Explained).
  8. With shadow rays on, as Praxis ships: phase two's depth pass, which draws phase two's Instances into depth and the surface normals, then the shadow mask pass, which traces each pixel's shadow rays against both TLAS into the shadow mask (Shadow Rays Explained).
  9. The lit pass, which shades both phases' Instances, reading each pixel's point lights from its Froxel's list and its shadows from the shadow mask, and resolves its 4x MSAA colour into the HDR target (Lit Pass Explained).
  10. The tonemapping pass, which maps the HDR target through GT7, encodes it as sRGB and dithers it into the 8-bit target (Tonemapping Pass Explained).
  11. With the count_point_lights Render switch on, which ships off: the light count pass, which counts each lit pixel's point lights for the GPU stats (Town Explained).

Four guides explain what these passes rest on: Distant Textures Explained and Anisotropy Explained, how Praxis cooks and samples textures; HDR Pipeline Explained, the survey behind the light units, the HDR target and the tonemapping; and GPU Ordering Explained, why a frame that loads Meshes first waits for their BLASes to be compacted.
