Praxis · the frame · src/render/prepare.rs

Prepare

Once a frame, after the Ticks, prepare reads the ECS World into Frame data: an owned value holding the camera, the Environment, the lights, the Instances whose slots this frame writes, the Moving Instances for the dynamic TLAS and the bends for the bend pass, which the Renderer uploads and draws without reading the World.

Describes main at 36fc1060 (2026-11-13), with held and unloaded Chunks and the pools' frees as their changes leave them, its capacities as the Budget split leaves them and the compute pool as the preparer's own. A change to prepare or to what Frame data holds rewrites this page and moves the commit; nothing is appended. Read first: the frame overview for where prepare sits among the passes, The Instance buffer for what a slot holds.

Interface

Called
By State::update, once a frame, after the Ticks and the frame's own schedule and before Renderer::upload, as FramePreparer::prepare. It ends the World's change window, so it is the frame's last read of the World.
Reads
The Camera, Environment and FixedTime resources; each directional and point light's World transform; each light's previous World transform; each Renderable's World transform, Mesh Handle, Material Handle and previous World transform; each loaded Chunk in the LoadedChunks resource, its Placements' World transforms and Handles, its point lights and whether it is held; each Bend; from the Mesh pool's LoadedMeshes, whether a Mesh Handle finds a Mesh, whether that Mesh needs a Material Handle and where its vertices lie in the vertex Arena; from the Material pool's Generations, whether a Material Handle finds a Material; how many entries either pool has freed; the target's aspect ratio.
Writes
FrameData, which it keeps and refills: the camera and light uniforms, the background colour, the lights, the Instances this frame writes in runs of consecutive slots, instance_slot_count, the Moving Instances and the bends. Across frames it keeps the slot table, each Renderable's slot and each Chunk's range, its queries and the Frame data's memory.
Sized
By the Renderer's RenderCapacities, which FramePreparer::new takes from Renderer::capacities: the Instance slots it hands out and the lights it lists, both derived from the GPU memory Budgets at device creation.
Buffers
None of its own. Renderer::upload copies Frame data into the camera and light uniforms, the light buffer, the bend pass's bends, the Instance buffer and the culling pass's instance_slot_count, and reads it for the static TLAS's entries and the dynamic TLAS's fill.
Counted
prepare_frame in CPU time, which also holds the check for lost writes before it; renderables_refused, lights_overflowed, moving_instances_left_out and bends_left_out in every frame. Upload counts instances_written and uploaded_bytes.
Where in the code
src/render/prepare.rs: FrameData, FramePreparer, the slot table InstanceSlots, fill_instances, write_chunk, prepare_lights and prepare_bends; LoadedChunks is in src/streaming/chunks.rs. Its caller is in src/state.rs, its consumer in src/render/renderer.rs.

1 · State::update, src/state.rs

The frame, end to end

Praxis renders by pulling. Each frame the State runs the simulation, prepare reads the ECS World into Frame data, and upload copies Frame data to the GPU. The Renderer reads Frame data only, never the World (ADR 0004).

One frame on the main thread, in order

  1. the Ticks the frame delta completes
  2. the frame's schedule
  3. prepare
  4. upload
  5. render
fn advance(&mut self, frame_delta: Duration, settle: bool) -> anyhow::Result<()> {
    self.recorder.begin();
    self.recorder.counters.dropped_time = self.simulation.simulate(frame_delta);

    let started = Instant::now();
    let streamed =
        self.streaming
            .update(&mut self.simulation.world, &mut self.renderer, settle)?;
    self.recorder.counters.late_chunks = streamed.late_chunks;
    self.recorder.counters.chunks_loaded = streamed.chunks_loaded;
    self.recorder.counters.chunks_unloaded = streamed.chunks_unloaded;
    self.recorder.counters.bytes_read = streamed.bytes_read;
    self.recorder.counters.uploaded_bytes += streamed.written_bytes;
    self.recorder.counters.pool_entries_freed = streamed.pool_entries_freed;
    self.recorder.stage("stream_chunks", started);

    let started = Instant::now();
    // Writes a failed upload lost are written again, with every Instance.
    if self.renderer.take_lost_instance_writes() {
        self.preparer.rewrite_all_instances();
    }
    let frame = self.preparer.prepare(
        &mut self.simulation.world,
        self.renderer.mesh_pool.meshes(),
        self.renderer.material_pool.generations(),
        self.renderer.aspect_ratio(),
    );
    self.recorder.stage("prepare_frame", started);

    self.renderer.upload(frame, &mut self.recorder);
    self.recorder.counters.renderables_refused = self.preparer.renderables_refused();
    self.recorder.counters.lights_overflowed = self.preparer.lights_overflowed();
    self.recorder.counters.moving_instances_left_out =
        self.preparer.moving_instances_left_out();
    self.recorder.counters.bends_left_out = self.preparer.bends_left_out();
    Ok(())
}

State::advance, which update and a capture's update_settled call, src/state.rs. render, which follows, draws the same Frame data through FramePreparer::frame.

The simulation runs the fixed schedule once per Tick the frame delta completes, then the frame's own schedule, which moves the camera. Prepare then reads what they left. It blends whatever the fixed schedule moves between its two newest Ticks, by the blend weight FixedTime holds (ADR 0022), and composes nothing camera-relative: positions leave it as an Anchor and an f32 offset (ADR 0014).

/// Everything the renderer draws in one frame, owned, so it holds no borrow
/// into the ECS World and can cross to another thread (ADRs 0004, 0016). It
/// lists no draws: the GPU builds the frame's draw from the Instances.
#[derive(Default)]
pub struct FrameData {
    pub camera: CameraUniform,
    pub light: LightUniform,
    /// The light buffer's lights, directional lights first, at most its
    /// capacity.
    pub lights: Vec<LightData>,
    /// The colour the lit pass clears to: the scene's background luminance,
    /// pre-exposed as the lit pass exposes what it draws.
    pub background: wgpu::Color,
    /// Slots the Instance buffer holds: one past the highest a Renderable or
    /// a Chunk's range has taken. The GPU draws each, but a freed one.
    pub instance_slot_count: u32,
    /// The Instances this frame writes, in `instance_writes` order; every
    /// other slot keeps what an earlier frame wrote (ADR 0003).
    pub instances: Vec<InstanceData>,
    pub instance_writes: Vec<InstanceWrite>,
    /// The Moving Instances the dynamic TLAS holds, at most
    /// `DYNAMIC_TLAS_CAPACITY`, those in the lowest slots, in no order. Each
    /// is written every frame, so each is among `instances`.
    pub moving_instances: Vec<MovingInstance>,
    /// The Meshes the GPU bends this frame (`Bend`), at most
    /// `BEND_CAPACITY`, in the order of their ranges of the vertex Arena.
    pub bends: Vec<BendData>,
}

FrameData, src/render/prepare.rs. The constant at the end fails the build if Frame data ever holds a borrow or anything that cannot cross threads.

Frame data is owned, so it holds no borrow into the World, and a render thread, if one is ever split off, receives it through a channel (ADR 0016). It lists no draws: the GPU builds the frame's draw from the Instance buffer, so Frame data carries only the slots this frame changes, beside what every frame sends whole. FramePreparer keeps one Frame data and refills it, so its vectors keep their memory from frame to frame.

2 · FramePreparer::prepare

The camera and the Environment

The camera reaches Frame data as a view-projection with no translation, its position as an Anchor and an offset, and its exposure. The Environment, the light of a Scene's surroundings, reaches it as the lit pass's clear colour, pre-exposed, and as the ambient illuminance in the light uniform.

let camera = world.resource::<Camera>();
let camera_position = camera.position;
let view_proj = projection_matrix(aspect_ratio) * camera.view_matrix();
let (anchor, offset) = anchor_and_offset(camera_position);
let exposure = camera.exposure();
frame.camera = CameraUniform {
    view_proj: view_proj.to_cols_array_2d(),
    anchor,
    exposure,
    offset,
    ..CameraUniform::default()
};
let environment = *world.resource::<Environment>();
let background = environment.background_luminance * exposure;
frame.background = wgpu::Color {
    r: background.x.into(),
    g: background.y.into(),
    b: background.z.into(),
    a: 1.0,
};

FramePreparer::prepare, src/render/prepare.rs.

Camera::view_matrix looks from the origin along the camera's forward axis, so the view-projection rotates and projects but does not translate: every position reaches the GPU relative to the camera, which the shaders compose from the two Anchors and offsets (ADR 0014). The camera uniform's TLAS fields stay at their defaults here; upload fills them.

The Environment resource holds two of ADR 0023's quantities: the ambient illuminance every surface receives from all around, and the luminance of the background, seen wherever nothing is drawn. Its default is dark, and every Reference scene sets the same one, scaled to the sun. Prepare reads it in every frame. The background becomes a wgpu::Color multiplied by the camera's exposure, as the lit pass exposes what it draws, and the targets module clamps it to fp16's largest finite value and weights it for the resolve when the lit pass clears to it. The ambient illuminance goes into LightUniform unexposed, beside the light counts (section 3), and the lit pass exposes it with the luminance it adds to.

3 · prepare_lights

The lights

In every frame prepare lists every directional light, then every point light, the entities' and then the loaded Chunks', each blended between its two newest Ticks, up to the light buffer's capacity; past it the point lights farthest from the camera are counted and not drawn, and the rest keep their order.

let room = capacity - directional_light_count;
if point_light_count > room {
    point_light_distances.select_nth_unstable_by(room, |left, right| {
        left.0.total_cmp(&right.0).then(left.1.cmp(&right.1))
    });
    point_light_distances.truncate(room);
    point_light_distances.sort_unstable_by_key(|&(_, index)| index);
    for (kept, &(_, index)) in point_light_distances.iter().enumerate() {
        lights[directional_light_count + kept] = lights[directional_light_count + index];
    }
    lights.truncate(capacity);
}
*overflowed = (directional_lights_overflowed + point_light_count.saturating_sub(room)) as u32;
directional_light_count as u32

prepare_lights, src/render/prepare.rs.

A directional light shines along its entity's forward axis, the World transform's rotation and scale applied to −Z and normalised; one scaled to nothing has no direction left and is not drawn, nor counted. Its offset carries that direction, its Anchor stays 0. A point light's position is split into an Anchor and an offset, as an Instance's is, with its range beside it. Each light's intensity is its colour times its lux or its candela (ADR 0023). Directional lights take their places first, so a full buffer leaves out point lights before any sun. Each point light's squared distance from the camera, between f64 World positions (ADR 0014), goes into point_light_distances beside its index in query order; when they do not all fit, a selection keeps the nearest that do, ties to the lower index, and the kept lights move down in query order. Under capacity nothing moves, so the buffer's order is the query's whether a light was cut or not: the lit pass sums lights and the shadow mask gives them its bits in buffer order, and a cut that reordered them would change pixels that no cut light reaches. The light buffer's layout, and what the Froxel pass and the lit pass read from it, are The Froxel pass's.

frame.light = LightUniform {
    ambient_illuminance: environment.ambient_illuminance.extend(0.0).to_array(),
    directional_light_count,
    point_light_count: frame.lights.len() as u32 - directional_light_count,
    ..LightUniform::default()
};
if *lights_overflowed > 0 && !*warned_of_overflowed_lights {
    tracing::warn!(
        lights_overflowed = *lights_overflowed,
        capacity = *light_capacity,
        "Lights past the light buffer's capacity are not drawn"
    );
}
*warned_of_overflowed_lights = *lights_overflowed > 0;

4 · InstanceSlots

Slots, and the free list

Each Renderable keeps one slot of the Instance buffer for as long as it is a Renderable, and each loaded Chunk a range of slots, one per Placement, with no entity behind them, until it unloads (ADR 0003). A slot a Renderable leaves, or a range an unloaded Chunk leaves, is written Instances with no Mesh, which the GPU skips, and is handed out again from the next frame: slots the most recently freed first, ranges by first fit.

/// Each Renderable's slot in the Instance buffer, kept until it stops being a
/// Renderable, and each loaded Chunk's range of slots, kept until it unloads
/// (ADR 0003); a slot or range freed in an earlier frame is taken again
/// before a fresh one, and once all `capacity` are taken a Renderable is
/// refused one.
#[derive(Default)]
struct InstanceSlots {
    capacity: u32,
    by_entity: bevy_ecs::entity::EntityHashMap<u32>,
    by_chunk: HashMap<AssetId, ChunkSlots>,
    free: Vec<u32>,
    /// Ranges unloaded Chunks gave back, in slot order, none touching
    /// another.
    free_ranges: Vec<Range<u32>>,
    /// Ranges freed this frame, which take Instances with no Mesh before
    /// they join `free_ranges`.
    freed_ranges: Vec<Range<u32>>,
    /// Slots freed this frame, which take an Instance with no Mesh before
    /// they join `free`.
    freed: Vec<u32>,
    /// One past the highest slot taken.
    end: u32,
    /// Renderables refused a slot and not yet given one, each warned about
    /// once.
    refused: bevy_ecs::entity::EntityHashSet,
    /// Chunks refused a range and not yet given one, each warned about once.
    refused_chunks: HashSet<AssetId>,
}

impl InstanceSlots {
    /// `entity`'s slot, taking one if it has none; None when none is left,
    /// warned about the first time `entity` is refused.
    fn get_or_take(&mut self, entity: Entity) -> Option<u32> {
        if let Some(&slot) = self.by_entity.get(&entity) {
            return Some(slot);
        }
        let fresh = (self.end < self.capacity).then_some(self.end);
        let Some(slot) = self.free.pop().or(fresh) else {
            if self.refused.insert(entity) {
                tracing::warn!(
                    ?entity,
                    capacity = self.capacity,
                    "Renderable refused: the Instance buffer is full"
                );
            }
            return None;
        };
        self.end = self.end.max(slot + 1);
        self.by_entity.insert(entity, slot);
        self.refused.remove(&entity);
        Some(slot)
    }

    /// A range of `count` slots for the Chunk `chunk`: the start of the first
    /// free range long enough, else fresh slots past the highest slot taken;
    /// None when the Instance buffer has no room for it, warned the first
    /// time `chunk` is refused.
    fn take_range(&mut self, chunk: AssetId, count: u32) -> Option<Range<u32>> {
        if let Some(index) = self
            .free_ranges
            .iter()
            .position(|free| free.end - free.start >= count)
        {
            let free = &mut self.free_ranges[index];
            let range = free.start..free.start + count;
            free.start = range.end;
            if free.start == free.end {
                self.free_ranges.remove(index);
            }
            self.refused_chunks.remove(&chunk);
            self.by_chunk.insert(chunk, ChunkSlots::new(range.clone()));
            return Some(range);
        }
        let end = self
            .end
            .checked_add(count)
            .filter(|&end| end <= self.capacity);
        let Some(end) = end else {
            if self.refused_chunks.insert(chunk) {
                tracing::warn!(
                    %chunk,
                    placements = count,
                    capacity = self.capacity,
                    "Chunk refused: the Instance buffer has no room for its Placements"
                );
            }
            return None;
        };
        let range = self.end..end;
        self.end = end;
        self.refused_chunks.remove(&chunk);
        self.by_chunk.insert(chunk, ChunkSlots::new(range.clone()));
        Some(range)
    }

    /// Gives back the ranges of the Chunks `loaded` no longer holds, into
    /// `freed_ranges`.
    fn free_unloaded(&mut self, loaded: &[LoadedChunk]) {
        let loaded: HashSet<AssetId> = loaded.iter().map(|chunk| chunk.id).collect();
        let freed_ranges = &mut self.freed_ranges;
        self.by_chunk.retain(|chunk, slots| {
            let kept = loaded.contains(chunk);
            if !kept {
                freed_ranges.push(slots.range.clone());
            }
            kept
        });
        self.refused_chunks.retain(|chunk| loaded.contains(chunk));
    }

    /// Moves the ranges freed in the frame before into `free_ranges`, each
    /// merged with the free ranges it touches.
    fn join_freed_ranges(&mut self) {
        for freed in self.freed_ranges.drain(..) {
            let index = self
                .free_ranges
                .partition_point(|free| free.start < freed.start);
            self.free_ranges.insert(index, freed);
            if index + 1 < self.free_ranges.len()
                && self.free_ranges[index].end == self.free_ranges[index + 1].start
            {
                let next = self.free_ranges.remove(index + 1);
                self.free_ranges[index].end = next.end;
            }
            if index > 0 && self.free_ranges[index - 1].end == self.free_ranges[index].start {
                let merged = self.free_ranges.remove(index);
                self.free_ranges[index - 1].end = merged.end;
            }
        }
    }

    fn free(&mut self, entity: Entity) {
        self.refused.remove(&entity);
        if let Some(slot) = self.by_entity.remove(&entity) {
            self.freed.push(slot);
        }
    }
}

The slot table, src/render/prepare.rs.

Slots persist

Prepare's Renderables are the entities with a WorldTransform and a MeshRef, the Mesh Handle; a MaterialRef and a PreviousWorldTransform are optional. A slot stays its Renderable's until the entity stops matching that query: it is despawned, or loses its Mesh Handle or its World transform. Transform brings a WorldTransform with it through #[require(WorldTransform)], and removing the Transform leaves the World transform in place, so an entity that loses only its Transform keeps its slot, by construction.

Prepare frees a slot when the World reports that an entity lost its World transform or its Mesh Handle since the last prepare and the entity is no longer a Renderable; one that lost a component and regained it in the same window keeps its slot.

let renderables = renderable_query.query(world);
// Slots of entities that stopped being Renderables are freed before new
// Renderables take slots.
for entity in world
    .removed::<WorldTransform>()
    .chain(world.removed::<MeshRef>())
{
    if !renderables.contains(entity) {
        instance_slots.free(entity);
    }
}

Chunk ranges

A Placement is a Chunk's static content, and it never becomes an entity: the Chunk's load resolves each Placement's Mesh and Material to Handles and composes its World transform, and the World holds the loaded Chunks as one resource, LoadedChunks, which the Chunk streamer keeps. In the first frame prepare sees a Chunk, before any new Renderable takes a slot, take_range gives it a range, one slot per Placement, all or none: the start of the first free range long enough, else fresh slots past the highest taken. write_chunk writes its Placements' Instances there in the order the Chunk holds them, so the Chunk goes to the GPU as one run; freed Renderable slots, scattered, are never part of one.

A held Chunk, loaded but outside the Load radius, writes Instances with no Mesh over its range instead, so it is neither drawn nor in the static TLAS, and its point lights are left out of the frame's; when it is drawn again, its Placements are written back. ChunkSlots remembers which of the two its range last took. A Chunk gone from LoadedChunks gives its range back through free_unloaded: its slots are written Instances with no Mesh, and the range joins the free ranges at the start of the next prepare, merged with any it touches, so no Chunk takes it in the frame it frees.

instance_slots.join_freed_ranges();
if chunks_changed {
    instance_slots.free_unloaded(chunks);
}
let rewritten_free_ranges = if *rewrite_every_instance {
    instance_slots.free_ranges.as_slice()
} else {
    &[]
};
for slot in instance_slots
    .freed_ranges
    .iter()
    .chain(rewritten_free_ranges)
    .flat_map(Range::clone)
{
    frame.write_instance(slot, no_mesh_instance(), false);
}
if chunks_changed
    || *rewrite_every_instance
    || pools_freed
    || !instance_slots.refused_chunks.is_empty()
{
    for chunk in chunks {
        let slots = match instance_slots.by_chunk.get_mut(&chunk.id) {
            Some(slots)
                if !*rewrite_every_instance
                    && slots.held == chunk.held
                    && !(pools_freed
                        && draws_a_freed_entry(chunk, meshes, material_generations)) =>
            {
                continue;
            }
            Some(slots) => {
                slots.held = chunk.held;
                slots.range.clone()
            }
            None => {
                let count = chunk.placements.len() as u32;
                let Some(slots) = instance_slots.take_range(chunk.id, count) else {
                    *renderables_refused += count;
                    continue;
                };
                if let Some(taken) = instance_slots.by_chunk.get_mut(&chunk.id) {
                    taken.held = chunk.held;
                }
                slots
            }
        };
        if chunk.held {
            for slot in slots {
                frame.write_instance(slot, no_mesh_instance(), false);
            }
        } else {
            write_chunk(frame, chunk, slots, meshes, material_generations);
        }
    }
}

FramePreparer::prepare. The Chunks are visited only in a frame that changed LoadedChunks, writes every Instance, follows a pool's free, or has a Chunk waiting for a range; a Chunk with a range is written again only when it was held or drawn and is now the other, when every Instance is, or after a free when it is drawn and draws_a_freed_entry finds a Placement whose Mesh or Material Handle no longer finds its entry.

A Placement is checked as a Renderable is, but once: one whose Mesh Handle finds no Mesh, whose Material Handle finds no Material, or that has no Material Handle where a Primitive of its Mesh names no Material writes an Instance with no Mesh, and the Chunk's count of them is warned about. It is not retried, since its Handles came from loads that succeeded and the Chunk counts as a user of each entry it names, so a pool frees none of them while it is loaded. A free still checks every drawn Chunk's Handles: one whose entry is gone, even with another entry at its index, has its Placements written again, the freed one's with no Mesh. Held Chunks, free ranges and free slots already hold Instances with no Mesh and are left as they are. A Placement's Instance is built as a static Renderable's is, from its Transform's affine, with no blend.

The free list

get_or_take pops free, so a new Renderable takes the most recently freed slot, and takes a fresh one, one past the highest ever taken, only when the list is empty. A slot freed in this frame goes to freed instead, so no Renderable can take it in the frame it frees. At the end of the visits it is written an Instance with no Mesh, so the GPU stops drawing whatever it held, and only then joins free:

// A slot freed this frame, or every free slot when every Instance is
// written again, takes an Instance with no Mesh, so the GPU no longer
// draws it; Renderables may take it from the next frame.
let rewritten_free_slots = if *rewrite_every_instance {
    instance_slots.free.as_slice()
} else {
    &[]
};
for &slot in instance_slots.freed.iter().chain(rewritten_free_slots) {
    frame.write_instance(slot, no_mesh_instance(), false);
}
instance_slots.free.append(&mut instance_slots.freed);
frame.instance_slot_count = instance_slots.end;

FramePreparer::prepare. With every Instance written again (section 6), every free slot is written an Instance with no Mesh too.

Slot numbers stay dense, and a Renderable's slot never moves while it lives. instance_slot_count is end, one past the highest slot ever taken: the culling pass visits every slot below it, and passes over those that name NO_MESH.

5 · ChangedRenderableQuery

Change detection: which slots are written

A slot is written only when what it holds changes: a Renderable that is new, whose World transform, Mesh or Material changed, that is blended every frame, or that lost its Material Handle or its previous World transform. Prepare finds them with query filters on bevy_ecs's change ticks, and ends the window they cover with World::clear_trackers.

/// The Renderables whose World transform, Mesh or Material changed since the
/// last `prepare`, new ones included, and the blended ones, which move every
/// frame. Of those prepare has written, only these and those that lost their
/// Material Handle or previous World transform are written again.

Every component carries the tick it last changed at. Changed<T> admits an entity whose T was added or mutably dereferenced since the World's last change tick, which prepare's clear_trackers moves at the end of every frame, whether or not the changed query ran, so a new Renderable is admitted by the components it was spawned with, and a moved parent's child is admitted because propagation rewrote its World transform. FramePreparer::prepare. visit takes the Renderable's slot and its place among the frame's Instances; retried are the Renderables the last prepare skipped or refused; rewrite_renderables is set after rewrite_all_instances and in the first prepare after either pool frees an entry.

Inside visit, a Renderable is skipped when its Mesh Handle finds no Mesh in LoadedMeshes, when its Material Handle finds no Material, or when it has no Material Handle and a Primitive of its Mesh names no Material. A Handle finds nothing once its entry is freed, even after a later Mesh or Material takes its index, since that index's generation moved on. A skipped Renderable still takes its slot, which is written an Instance with no Mesh once, in the first frame it is skipped; it is visited again in every frame, changed or not, and draws there as soon as its Mesh loads. Once either pool frees an entry, an unchanged Instance may name an index a later entry took, so the next prepare visits every Renderable, as it does after rewrite_all_instances, and writes again only the Chunks that name a freed entry (section 4). A drawn Renderable takes its place among the frame's Instances, an Instance with no Mesh for now, and joins the drawn list as a DrawnRenderable: that place and its entity.

Once every Renderable is visited, fill_instances writes each listed Instance: the Renderable's World transform blended by the frame's blend weight, in f64, and split into an Anchor and an offset, its rotation and scale and their inverse transpose padded per column for WGSL. Each Instance depends on its Renderable alone, so the list splits into a task per 1,024 Instances on the compute pool, whose workers and the main thread, which joins the scope, run them. A task does not own a fixed part: each takes the next 128 Instances left until none are, since the pool wakes its sleeping workers one at a time, each woken worker waking the next once it finds a task, and the last of them wakes about 100 µs into the fill on town; a thread that woke late takes fewer. The pool is the preparer's own, created with it: a worker per core but the main thread's. The tasks follow the frame's count, not the machine's threads, since each spawn is an allocation the frame's counter sees. The list is in place order, so each batch lands in one run of the Instances, which split_at_mut hands it alone, and the result is the same however the tasks are scheduled.

6 · get_or_take · rewrite_all_instances

Refusal, and writing every Instance again

The Instance buffer never grows. When all 517,376 slots are taken, a new Renderable is refused visibly, by four rules, and it keeps being retried, so it takes the next slot that frees.

  1. No slot. No Instance is written for it and nothing draws it; every other Renderable renders as before.
  2. Warned about once, in the first frame it is refused: Renderable refused: the Instance buffer is full, with the entity and the capacity. The refused set remembers it until it takes a slot or stops being a Renderable.
  3. Counted in every frame, as renderables_refused, which prepare resets at the start of each frame and the State copies into Frame stats.
  4. Retried in every frame: a refused Renderable joins unwritten, which the next prepare visits whether it changed or not. It takes the first slot that frees, from the frame after the slot frees.

When a frame's staging slot fails to map, the GPU never receives that frame's writes. Upload then reports the lost writes, if the frame had any Instances, and the State calls rewrite_all_instances before the next prepare, which visits every Renderable and writes each into the slot it already keeps, with every free slot written an Instance with no Mesh. The slot table stays as it is, so no slot moves, a refused Renderable stays refused and is not warned about again, and every Renderable that held a slot still holds it.

A Chunk is refused whole, never split: when the slots past the highest taken cannot hold all its Placements, it takes none, is warned about once with Chunk refused: the Instance buffer has no room for its Placements, its Asset ID, its Placements and the capacity, and adds its Placements to renderables_refused in every frame. It is asked for again in every frame, and takes a range once a free range or the slots past the highest taken can hold it. A later Chunk that fits still takes its range. A rewrite of every Instance writes each Chunk's Placements into the range it already took.

7 · FrameData::write_instance · Renderer::upload

Runs of consecutive slots, one copy each

Prepare queues each Instance it writes onto the last write when its slot follows that write's last slot and both are of the same kind, Moving or static, so a run of consecutive slots goes to the GPU as one copy.

impl FrameData {
    /// Queues `instance` for `slot`, a Moving Instance or not, in the last
    /// write when `slot` follows it and it is of the same kind, and lists it
    /// among the Moving Instances if it is one.
    fn write_instance(&mut self, slot: u32, instance: InstanceData, moving: bool) {
        let index = self.instances.len();
        self.instances.push(instance);
        if moving {
            self.moving_instances.push(MovingInstance {
                slot,
                instance: index,
            });
        }
        match self.instance_writes.last_mut() {
            Some(write)
                if write.moving == moving
                    && write.first_slot + write.instances.len() as u32 == slot =>
            {
                write.instances.end += 1;
            }
            _ => self.instance_writes.push(InstanceWrite {
                first_slot: slot,
                instances: index..index + 1,
                moving,
            }),
        }
    }
}

8 · moving_instances

The Moving Instances and their cap

An Instance is a Moving Instance while its entity carries PreviousWorldTransform. It is written in every frame, flagged moving, and listed for the dynamic TLAS; past the dynamic TLAS's 10,000 entries, the lowest slots keep their place.

The fixed schedule keeps an entity's previous World transform exactly when it moves that entity, children included, so frames can draw it between Ticks (ADR 0022). Prepare reads the component's presence as the classification; no other component marks a Moving Instance. Its value is None from a spawn or a teleport until the next Tick, and the Instance counts as moving all the same.

Gaining the component. From that frame on the Renderable is admitted by the changed query in every frame, and write_instance lists its slot and the index of its Instance among the Moving Instances. The static TLAS clears the slot's entry when a moving write reaches it.

Losing it. The removal makes prepare write the Instance once more in that frame, unflagged, so the static TLAS takes it. Without that write the slot's last write would stay the moving one: the static TLAS would keep its entry clear and the dynamic TLAS, which lists only this frame's Moving Instances, would drop it, and it would cast no shadow until something rewrote it.

// Past the dynamic TLAS's capacity, the lowest slots keep their place.
let capacity = DYNAMIC_TLAS_CAPACITY as usize;
*moving_instances_left_out = frame.moving_instances.len().saturating_sub(capacity) as u32;
if *moving_instances_left_out > 0 {
    frame
        .moving_instances
        .select_nth_unstable_by_key(capacity, |moving| moving.slot);
    frame.moving_instances.truncate(capacity);
    if !*warned_of_moving_instances_left_out {
        tracing::warn!(
            left_out = *moving_instances_left_out,
            capacity,
            "Moving Instances left out of the dynamic TLAS, past its capacity: those in the highest slots cast no shadow"
        );
    }
}
*warned_of_moving_instances_left_out = *moving_instances_left_out > 0;

The cap, FramePreparer::prepare. select_nth_unstable_by_key moves the lowest 10,000 slots ahead of the index, in no order and in linear time, with no full sort; truncate drops the rest.

The rule keeps the lowest slots rather than the first Moving Instances prepare meets, because the World's order moves and slots do not. bevy_ecs stores each archetype's entities in a table, appends an entity that spawns or changes archetype at its new table's end, and fills a removed entity's row with the table's last entity, so iteration order shifts whenever entities spawn, despawn or change components, even for one Tick, as a teleport's Teleported marker does. A slot changes only when its Renderable stops being one. So a Moving Instance does not lose its shadow because some other entity changed.

Those left out are still drawn, since their Instances are written, and their writes are still flagged moving, so the static TLAS leaves them out too: they cast no shadow. moving_instances_left_out counts them in every frame; the warning fires in the first frame that leaves any out, and again only after a frame that left none out. The dynamic TLAS describes what the TLAS does with the list.

9 · prepare_bends

The bends

Every Renderable with a Bend becomes one BendData in every frame, its curvature blended between the two newest Ticks, in the order of the bent Meshes' ranges of the vertex Arena; bends that could not be applied, would race or do not fit are left out.

A Bend names its rest Mesh, an azimuth and a curvature with the previous Tick's beside it. Prepare draws drawn_curvature, the blend by the frame's blend weight; the azimuth is drawn as set. Each bend becomes the start of the rest Mesh's vertices, the start of the bent Mesh's, their count, the azimuth and the curvature. Three rules keep the list safe to hand to one dispatch:

  1. Both Meshes loaded, with as many vertices. Otherwise the bend is warned about and the Mesh is not bent.
  2. No races. The pass writes each bent Mesh while it reads each rest Mesh, so of two bends of one Mesh one is kept, and a bend whose rest Mesh is a Mesh that some bend writes, its own included, is dropped; one warning counts the dropped.
  3. A fixed order and a fixed capacity. The list is sorted by where each bent Mesh's vertices start, so it does not depend on how the World stores the entities, and past BEND_CAPACITY the bends of the Meshes highest in the Arena are left out, counted in every frame as bends_left_out and warned about once while it lasts.
bends.sort_unstable_by_key(|bend| bend.first_vertex);
let listed = bends.len();
bends.dedup_by_key(|bend| bend.first_vertex);
let mut index = 0;
while index < bends.len() {
    let rest = bends[index].rest_first_vertex;
    if bends
        .binary_search_by_key(&rest, |bend| bend.first_vertex)
        .is_ok()
    {
        bends.remove(index);
    } else {
        index += 1;
    }
}
if bends.len() < listed {
    tracing::warn!(
        dropped = listed - bends.len(),
        "Bends that would race are dropped: a Mesh two Renderables bend is bent once, and one bent from a Mesh a bend writes is not bent"
    );
}
let capacity = BEND_CAPACITY as usize;
*left_out = bends.len().saturating_sub(capacity) as u32;
bends.truncate(capacity);

prepare_bends, src/render/prepare.rs. The search for a rest Mesh among the bent ones is a binary search, since the list is sorted by the bent Meshes' starts.

A bend is game state, so the fixed schedule sets the curvature once per Tick and record_previous_curvatures keeps the one before; prepare only blends. The bend pass reads the list, and The Reference scenes describes the scene that fills it.

12 · ADRs 0003, 0004, 0014, 0016, 0022

Why this way

Pull, into owned data. ADR 0004 keeps the Renderer from reading the World mid-frame: prepare builds Frame data and the Renderer consumes only that. Since the Instance buffer persists, every Frame data must reach the Renderer, in order. ADR 0016 makes Frame data an owned, Send value with no borrow into the World, which a compile-time assertion holds, so moving rendering to its own thread becomes a channel send, and the Renderer is tested headless with no World at all.

Slots that persist, written when they change. ADR 0003 keeps every Instance in one buffer, a slot per Renderable and a range per loaded Chunk, updated incrementally, the shape GPU-driven culling and the TLAS builds consume. With ADR 0014's Anchor and offset per Instance, a camera that moves changes no Instance, so a frame where nothing in the scene changes writes none.

Change ticks the World already keeps. Prepare keeps no copy of last frame's Instances to compare against: the tick bevy_ecs stamps on each component says what changed, and the removal lists say what left. The price is that the change window is prepare's to close, which pins prepare as the frame's last World read.

A fixed capacity that refuses. A buffer that grows has to be copied mid-frame into a larger one, and every bind group that names it rebuilt. ADR 0003 fixes the Instance buffer at the slots its Budget pays for, 517,376 at the checked-in Budgets, sized once at device creation: its memory is known at startup and its bind groups are built once. What does not fit is refused visibly, warned about, counted and retried, never dropped in silence.

A freed slot is emptied and waits a frame. ADR 0003's amendment writes a freed slot an Instance with no Mesh, which the GPU passes over, rather than leaving its last Instance there to draw, and hands the slot out again only from the next frame.

Moving by component, capped by slot. ADR 0022's blend moves a Moving Instance in every frame, between Ticks too, so it is rewritten in every frame, and the component the blend reads already marks it. The dynamic TLAS that holds them has a fixed capacity, and the lowest slots keep their place because an entity's slot changes only when it stops or starts being a Renderable, while the World's order changes whenever entities change components.

The blend in prepare, in f64. ADR 0022 runs everything that changes game state in the fixed schedule and draws a blend of the two newest Ticks, so the simulation does not depend on the frame rate. The blend runs once a frame, where prepare composes what it draws, and in f64, before ADR 0014's split into an Anchor and an f32 offset.

The visit in order, the Instances in parallel. Slots, skips, refusals and runs depend on the order Renderables are visited in, which captures and the GPU's slot order rely on, so the visit stays on the main thread. Composing each Instance, the blend's slerp above all, depends on nothing but its Renderable, so it waits for the visit and then splits among ADR 0016's compute pool, which the main thread joins rather than waiting on. The tasks allocate nothing; the scope and each spawn allocate on the main thread, which is why a frame with few Instances spawns none. The scope allocates twice more when the main thread has to wait for a task, to run the pool's queue itself meanwhile, so a frame whose tasks the workers finish first counts two fewer.

A pool per preparer. A scope's tasks go through the pool's one queue, which allocates its next block on the thread that pushes a block's last task, once every 31 tasks. That thread is the main thread, so which frames count that allocation follows how many tasks the pool has taken since it was created. On the process-global pool that count carried over from every State the process ran before: after town's run, world's counter frames read 10,474 heap allocations where they read 10,473 alone. ADR 0016's amendment gives each preparer its own pool, whose queue starts with it, so which frames count that allocation follows its State's frames alone. The cost is the pool's threads, created with each State and joined when it drops.

13

Limits

Every Renderable visited. Changed<T> is not an archetype filter, so the changed query reads every Renderable's change ticks even in a frame where none changed; only the writes are saved, not the walk.

The slot count never shrinks. end is the highest slot ever taken, plus one. Despawning the Renderables in the highest slots leaves the culling pass visiting their empty slots until new Renderables take them.

Free ranges are never compacted. A Chunk takes the first free range long enough and leaves the rest free, so Chunks of very unequal sizes can strand free slots between ranges, and a Chunk can be refused while that many slots lie free in pieces.

Runs follow the World's order. Writes merge only when consecutive slots are visited one after another, so changes scattered across the World become many small copies.

Lights and bends are rebuilt whole. Every frame lists and uploads every light and every bend, changed or not. Past the light buffer's capacity, which point lights are left out follows their distances from the camera, so it changes as the camera moves, unlike the Moving Instances' rule by slot.

Repeated warnings. A skipped Renderable is visited, and warned about, in every frame until it draws; a dropped or unloaded bend, or one whose two Meshes differ in vertex count, is warned about in every frame it lasts. Only refusal and the three capacities warn once.

Two bends of one Mesh. One is kept, but the list's sort is unstable, so which one is not specified.

The visit on one thread. Only filling the Instances splits among the compute pool's threads; the visit, the Chunks' writes, the lights and the bends run on the main thread, and every drawn Renderable is looked up in the query a second time, by entity, when its Instance is filled.

History

Prepare began as the frame's one pull from the World, with the slot table and change detection that made camera motion free. The Instance buffer then stopped growing and gained refusal; freed slots took an Instance with no Mesh and waited a frame, and the draws left Frame data once the GPU built its own. The lights moved into a light buffer with anchored point lights, the Environment replaced constants in the shaders, the blend between Ticks arrived with the fixed schedule, then the Moving Instance list and its cap with the dynamic TLAS, and the bends with the crowd; change detection moved from per-item tests into query filters. Once Handles carried generations and the pools could free entries, prepare came to read the Meshes and the Materials' generations as plain data rather than the pools. Then the Chunks' static content stopped being entities: each loaded Chunk took a range of slots and its point lights joined the frame's; once Chunks streamed, a held Chunk wrote Instances with no Mesh and an unloaded one gave its range back. Filling the Instances then left the visit, so the compute pool could split it. A pool's free then stopped writing every Instance again: it writes every Renderable and only the Chunks that name a freed entry. Last, the compute pool became the preparer's own. The Instance buffer describes the slots prepare writes; The culling pass and The dynamic TLAS describe what reads the slots and the list. This page describes the mechanism as it is.
