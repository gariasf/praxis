Praxis · the frame · src/render/bend_pass.rs

The bend pass

A compute pass that rewrites, in every frame, each bent Mesh's vertices from its rest Mesh's, the middle curved into a circular arc and each vertex's tangent frame turned with it: the engine's bend, which stands in for skinning and which the crowd scene's figures take.

Describes main at fbae12f4 (2026-11-04). A change to the pass rewrites this page and moves the commit; nothing is appended. Read first: The Reference scenes for the scene whose figures the pass bends, BLAS Refit for what follows the pass in the crowd's refit form.

Interface

Runs
In every frame whose Frame data lists a bend, which among the Reference scenes is crowd's alone: the first pass recorded into the frame's encoder, after the frame's uploads and before culling phase one, so every pass that pulls vertices reads the bent shapes. A frame with no bends records no pass.
Reads
The frame's bends, a BendData each, in a buffer the CPU writes through frame staging; each rest Mesh's range of the vertex Arena.
Writes
Each bent Mesh's range of the vertex Arena, whole vertices: the position bent, the UV copied, the QTangent turned.
Dispatches
One, bend_vertices: a row of workgroups per bend, each of 64 invocations (BEND_WORKGROUP_SIZE), as many as the longest bend's vertices need.
Bind groups
Group 3, BENDS: the bends, read-only storage, and the vertex Arena, read-write storage.
Shader
src/render/shaders/bend.wgsl, assembled after the common part as the module BEND.
Counted
bend_pass in GPU time; bends_left_out in counters; the bends' buffer in GPU memory; each frame's bends in uploaded_bytes.

1 · src/render/renderer.rs

Where it sits in the frame

The pass is the first recorded into the frame's encoder, ahead of every pass that pulls vertices from the Arena, so the depth passes and the lit pass draw the bent shapes; and where the crowd's figures trace their own BLASes, the frame is cut into submissions right after it.

The frame's passes in the default form, in the order the GPU receives them

  1. dynamic TLAS build
  2. bend pass
  3. culling, phase one
  4. Froxel pass
  5. depth pre-pass
  6. depth pyramid pass
  7. culling, phase two
  8. phase two's depth pass
  9. shadow mask pass
  10. lit pass
  11. tonemapping pass

Renderer::render records the pass into the frame's encoder, which already holds what upload recorded, the bends' copy among it, and the start of the frame's GPU stats; every other pass of the frame follows it in that encoder. The dynamic TLAS's build is not in it: it goes in a command buffer of its own, recorded after the pass on the CPU and submitted before the frame's.

let mut timestamps = self.gpu_stats.begin_frame(&mut encoder, recorder);
// Bent Meshes take their shapes before any pass reads their vertices.
let bend_timestamps = timestamps
    .as_mut()
    .map(|timestamps| timestamps.pass(BEND_PASS));
let bent = self
    .bend_pass
    .record(&mut encoder, &frame.bends, bend_timestamps);
let encoding = started.elapsed();
// Their BLASes take them too, in a submission of their own, which
// the dynamic TLAS's build, recorded after it, follows.
if let Some(blas_refit) = self.blas_refit.as_mut().filter(|_| bent) {
    let started = Instant::now();
    let head = std::mem::replace(&mut encoder, create_frame_encoder(&self.device));
    let refit_end = timestamps
        .as_mut()
        .map(|timestamps| timestamps.pass(BLAS_REFIT_PASS));
    blas_refit.submit(&self.device, &self.queue, head, &self.mesh_pool, refit_end);
    if let Some(timestamps) = &mut timestamps {
        timestamps.split_submission();
    }
    recorder.stage(BLAS_REFIT, started);
}

Renderer::render, src/render/renderer.rs.

With the crowd_form Render switch at its default, CrowdForm::Proxies, the Renderer has no BlasRefit, nothing is cut, and the bent Meshes have no BLAS: shadow proxies cast their shadows. In the refit and rebuild forms each figure traces its own BLAS, which must take the bent shape before the dynamic TLAS is built over it. So in a frame that bent anything the encoder is swapped for a fresh one right after the pass, and the head, the uploads and the bend pass, goes to the GPU in a submission of its own with the BLAS updates, ahead of the build (BLAS Refit). record's answer, whether it recorded anything, decides that cut; the pass is timed only when it records, since only then does it turn its queries into timestamp writes, which marks it run for the frame's GPU stats (Frame stats).

2 · Bend · record_previous_curvatures

A curvature per Tick, drawn between two

How far a figure bends is game state: the fixed schedule sets a Bend's curvature once per Tick, after keeping the last one, and each frame draws the blend of the two, as it draws World transforms.


/// Bends its Renderable's Mesh on the GPU each frame from `rest`, a Mesh of
/// the same vertices whose +Y axis runs up its middle from y = 0: a stand-in
/// for skinning. The middle bends into a circular arc towards the
/// azimuth, and every vertex turns with the middle at its height. The bent
/// Mesh is the Renderable's own, since the GPU writes its vertices, and its
/// bounds must hold every shape it bends to, since the culling pass tests
/// them. Game state: the fixed schedule sets the curvature each Tick, after
/// `record_previous_curvatures` keeps the last, and frames draw the blend of
/// the two (ADR 0022); the azimuth is drawn as set. A bend spawns with its
/// previous curvature equal to its curvature.
#[derive(Component, Clone, Copy)]
pub struct Bend {
    pub rest: MeshHandle,
    /// The direction the middle bends towards, about +Y from +X towards +Z,
    /// in radians.
    pub azimuth: f32,
    /// Radians the middle turns through per metre of its height, after the
    /// newest Tick and after the one before.
    pub curvature: f32,
    pub previous_curvature: f32,
}

impl Bend {
    /// The curvature a frame draws, `blend_weight` of the way from the
    /// previous Tick's to the newest Tick's.
    pub fn drawn_curvature(&self, blend_weight: f32) -> f32 {
        self.previous_curvature + (self.curvature - self.previous_curvature) * blend_weight
    }
}

Bend, src/components.rs. It is pure data; the GPU buffer it feeds belongs to the Renderer.

The rest Mesh stands with its +Y axis up its middle from y = 0 and is never written; the bent Mesh is the Renderable's own MeshRef, of as many vertices, since the GPU overwrites it. A writer sets only curvature: at the start of every Tick, right after record_previous_world_transforms, record_previous_curvatures copies it into previous_curvature, so no writer has to remember to. The azimuth is drawn as set, never blended.

/// Starts a Tick, as `record_previous_world_transforms` does for World
/// transforms: each bend's curvature becomes its previous one, before the
/// Tick sets it.
pub fn record_previous_curvatures(mut bends: Query<&mut Bend>) {
    for mut bend in &mut bends {
        bend.previous_curvature = bend.curvature;
    }
}

3 · prepare_bends, src/render/prepare.rs

Prepare's list

Prepare turns each Renderable with a Bend into one BendData, blended by the frame's blend weight, and keeps the list safe to hand to one dispatch: both Meshes loaded with as many vertices, no two bends racing on one Mesh, a fixed order and a fixed capacity.

fn prepare_bends(
    world: &World,
    bend_query: &mut BendQuery,
    mesh_pool: &MeshPool,
    blend_weight: f32,
    bends: &mut Vec<BendData>,
    left_out: &mut u32,
) {
    bends.clear();
    for (mesh_ref, bend) in bend_query.iter(world) {
        let (Some(bent), Some(rest)) = (mesh_pool.get(mesh_ref.0), mesh_pool.get(bend.rest)) else {
            tracing::warn!(
                mesh = mesh_ref.0.0,
                rest = bend.rest.0,
                "A bent Mesh or its rest Mesh is not in the pool, so it is not bent"
            );
            continue;
        };
        if bent.vertices.len() != rest.vertices.len() {
            tracing::warn!(
                mesh = mesh_ref.0.0,
                rest = bend.rest.0,
                "A bent Mesh and its rest Mesh hold different vertex counts, so it is not bent"
            );
            continue;
        }
        let curvature = bend.drawn_curvature(blend_weight);
        bends.push(BendData {
            rest_first_vertex: rest.vertices.start,
            first_vertex: bent.vertices.start,
            vertex_count: bent.vertices.len() as u32,
            azimuth: bend.azimuth,
            curvature,
        });
    }
    bends.sort_unstable_by_key(|bend| bend.first_vertex);
    let listed = bends.len();
    bends.dedup_by_key(|bend| bend.first_vertex);
    let mut index = 0;
    while index < bends.len() {
        let rest = bends[index].rest_first_vertex;
        if bends
            .binary_search_by_key(&rest, |bend| bend.first_vertex)
            .is_ok()
        {
            bends.remove(index);
        } else {
            index += 1;
        }
    }
    if bends.len() < listed {
        tracing::warn!(
            dropped = listed - bends.len(),
            "Bends that would race are dropped: a Mesh two Renderables bend is bent once, and one bent from a Mesh a bend writes is not bent"
        );
    }
    let capacity = BEND_CAPACITY as usize;
    *left_out = bends.len().saturating_sub(capacity) as u32;
    bends.truncate(capacity);
}

prepare_bends, src/render/prepare.rs, called at the end of FramePreparer::prepare with the frame's blend_weight from FixedTime.

The rules, in the code's order:

Both Meshes loaded, with as many vertices. A bend whose Mesh or rest Mesh the Mesh pool lacks, or whose two Meshes differ in vertex count, is warned about and skipped.

No races. One dispatch runs every bend at once, writing each bent Mesh while it reads each rest Mesh. So the list is sorted by where each bent Mesh's vertices start in the Arena; of two bends of one Mesh, the dedup keeps one; and a bend whose rest Mesh some bend writes, its own included, is dropped, found by binary search over the sorted starts. One warning counts what was dropped. These checks run in every build.

A fixed order and a fixed capacity. The sort makes the list independent of how the ECS World stores its entities. Past BEND_CAPACITY, 4,096, the bends of the Meshes highest in the Arena are left out, and those Meshes keep the shape they last took. bends_left_out counts them in every frame's Frame stats, and prepare warns once while any are left out.

4 · BendData · BendPass::record

The dispatch

A bend reaches the GPU as 20 bytes: two vertex starts, a count, an azimuth and a curvature. The pass gives each bend a row of 64-vertex workgroups, as many as the longest bend needs; an invocation past its own bend's count returns.

/// One bend as the pass reads it: where its rest Mesh's vertices and its
/// bent Mesh's start in the vertex Arena, how many each holds, and the bend
/// (`Bend`), its curvature blended between the two newest Ticks.
#[repr(C)]
#[derive(Clone, Copy, Debug, Default, PartialEq, bytemuck::Pod, bytemuck::Zeroable)]
pub struct BendData {
    pub rest_first_vertex: u32,
    pub first_vertex: u32,
    pub vertex_count: u32,
    /// The direction the middle bends towards, about +Y from +X towards +Z,
    /// in radians.
    pub azimuth: f32,
    /// Radians the middle turns through per metre of its height.
    pub curvature: f32,
}

BendData, src/render/bend_pass.rs; its WGSL twin in bend.wgsl holds the same five fields.

The bends' buffer is made once, at BEND_CAPACITY bends, and never grows. Renderer::upload writes the frame's bends to its start through frame staging with the frame's other uploads, whenever the list is not empty, and frame staging's bound counts the buffer whole.

pub fn record(
    &self,
    encoder: &mut wgpu::CommandEncoder,
    bends: &[BendData],
    timed: Option<TimedPass<'_, '_>>,
) -> bool {
    let Some(longest) = bends.iter().map(|bend| bend.vertex_count).max() else {
        return false;
    };
    let mut pass = encoder.begin_compute_pass(&wgpu::ComputePassDescriptor {
        label: Some(BEND_PASS),
        timestamp_writes: timed.map(TimedPass::compute),
    });
    pass.set_pipeline(&self.pipeline);
    pass.set_bind_group(BENDS.index, &self.bind_group, &[]);
    pass.dispatch_workgroups(longest.div_ceil(BEND_WORKGROUP_SIZE), bends.len() as u32, 1);
    true
}

BendPass::record, src/render/bend_pass.rs.

The dispatch is ⌈longest / 64⌉ × bends × 1 workgroups. An invocation's y is its bend and its x the vertex within it, so the bends of one frame need not hold as many vertices as one another.

5 · bend_vertices · sinc, src/render/shaders/bend.wgsl

Where a vertex goes

A middle that turns at a constant rate per metre is a circular arc, and an arc's chord leans at half the angle the arc turns through. So a vertex at rest height h lands at the end of a chord h · sin(θ/2) / (θ/2) long, leaning θ/2 from upright toward the azimuth, plus its horizontal offset from the middle, turned by θ = curvature × h.

θ = κ h  toward = (cos ψ, 0, sin ψ) middle(h) = h · sinc(θ/2) · (sin(θ/2) · toward + cos(θ/2) · Y) q = ((Y × toward) · sin(θ/2), cos(θ/2)) the turn by θ about Y × toward bent vertex = middle(h) + rotate(q, (x, 0, z))

κ is the curvature and ψ the azimuth; (x, y, z) is the rest vertex, h its y.

@compute @workgroup_size(BEND_WORKGROUP_SIZE)
fn bend_vertices(@builtin(global_invocation_id) invocation: vec3<u32>) {
    let bend = bends[invocation.y];
    if invocation.x >= bend.vertex_count {
        return;
    }
    var vertex = vertices[bend.rest_first_vertex + invocation.x];
    let height = vertex.position[1];
    // At this height the middle has turned through twice the half angle,
    // from +Y towards the azimuth, about +Y × toward. The arc's chord from
    // the foot runs at the half angle, its length the height times
    // sin(half) / half.
    let half_angle = 0.5 * bend.curvature * height;
    let toward = vec3<f32>(cos(bend.azimuth), 0.0, sin(bend.azimuth));
    let rotation = vec4<f32>(
        vec3<f32>(toward.z, 0.0, -toward.x) * sin(half_angle),
        cos(half_angle)
    );
    let chord = height * sinc(half_angle);
    let middle = chord * (vec3<f32>(0.0, cos(half_angle), 0.0) + toward * sin(half_angle));
    let offset = vec3<f32>(vertex.position[0], 0.0, vertex.position[2]);
    let position = middle + rotate(rotation, offset);
    vertex.position = array<f32, 3>(position.x, position.y, position.z);

bend_vertices, its first half, bend.wgsl. (toward.z, 0, −toward.x) is +Y × toward, the axis the middle turns about; rotate, in the common part, turns a vector by a unit quaternion.

Where a figure stands nearly straight, the half angle is tiny, and sin(x) / x divides one small number by another. Metal compiles shaders with fast math by default, under which sin is accurate only to an absolute error, at most 2−13 over [−π, π], so dividing it by a small angle would magnify that error. Below 0.5 radians sinc takes the first four terms of the Taylor series instead, 1 − x²/6 + x⁴/120 − x⁶/5040 in nested form; the first term left out, x⁸/9!, is under 1.1 × 10−8 there.

// sin(angle) / angle, sinc, by its Taylor series below 0.5 radians, whose
// first term left out, angle⁸ / 9!, is under 1.1e-8 there: Metal compiles
// with fast math [ref:msl-4.1-fast-math], which leaves sin an absolute
// error [ref:msl-4.1-sin-fast-accuracy] that dividing by a small angle
// would magnify.
fn sinc(angle: f32) -> f32 {
    let squared = angle * angle;
    let series = 1.0 - squared / 6.0 * (1.0 - squared / 20.0 * (1.0 - squared / 42.0));
    return select(sin(angle) / angle, series, abs(angle) < 0.5);
}

6 · bend_vertices, its second half

The tangent frame turns too

A cooked vertex's normal, tangent and bitangent sign travel as one QTangent, a unit quaternion in four Snorm16 values whose sign is the bitangent sign (ADR 0018). The pass turns it by the vertex's rotation and stores it back as the cooker stores one.

    // The QTangent turns with it, stored as the cooker stores one: its w
    // made positive and kept off zero, then given the bitangent sign
    // (ADR 0018).
    let stored = unpack_qtangent(vertex);
    let bitangent_sign = select(1.0, -1.0, stored.w < 0.0);
    var turned = quaternion_product(rotation, normalize(stored) * bitangent_sign);
    turned *= select(1.0, -1.0, turned.w < 0.0);
    if turned.w < QTANGENT_SMALLEST_W {
        let axis_length = sqrt(1.0 - QTANGENT_SMALLEST_W * QTANGENT_SMALLEST_W);
        turned = vec4<f32>(normalize(turned.xyz) * axis_length, QTANGENT_SMALLEST_W);
    }
    turned *= bitangent_sign;
    vertex.qtangent = array<u32, 2>(pack2x16snorm(turned.xy), pack2x16snorm(turned.zw));
    vertices[bend.first_vertex + invocation.x] = vertex;
}

bend_vertices, its end, bend.wgsl. unpack_qtangent is the common part's; QTANGENT_SMALLEST_W and BEND_WORKGROUP_SIZE are declared into the WGSL from Rust when the module is assembled.

The stored quaternion is normalised and given back its positive w before the turn, since its sign carries the bitangent sign and not the rotation. After the product, w is made positive again and kept at least QTANGENT_SMALLEST_W, one Snorm16 step, so it never rounds to zero and loses the sign; then the sign is put back. The cooker's qtangent in src/cook/mesh.rs takes the same three steps with the same constant. The vertex's UV is copied unchanged, and the whole vertex lands in the bent Mesh's range at the same index.

9 · ADRs 0003, 0013, 0017, 0018, 0019, 0020, 0022

Why this way

A stand-in for skinning. ADR 0020 gives every shadow to a ray against the TLAS, so whatever deforms must reach the TLAS in the shape it is drawn in. Until skinning arrives, the crowd needs Meshes whose every vertex the GPU rewrites each frame, as skinning would, so that the forms a deforming mesh can take in the TLAS can be measured against the crowd's Budget. One arc per figure is the least that does it: one curvature and one azimuth a bend, no bones or weights.

In place in the vertex Arena. The main pass pulls every vertex from the Arena (ADR 0019), so a bent Mesh needs nothing new downstream: the depth passes and the lit pass draw it as any Mesh. Writing over the bent Mesh's own range keeps the fixed Arenas of ADR 0017 as they are, and is why the bent Mesh is the Renderable's own rather than a shared one.

Blended between Ticks. ADR 0022 puts game state in the fixed schedule at 64 Hz and draws frames between the two newest Ticks. A curvature is game state, so it takes the treatment World transforms take: the previous value kept at the start of each Tick, the blend drawn. The azimuth does not change in the scene, and is drawn as set.

One dispatch, races ruled out on the CPU. All bends run in one dispatch with no barrier between them, so prepare drops what would race, a second bend of one Mesh and a bend from a Mesh a bend writes, rather than the GPU ordering them.

A fixed buffer. No GPU buffer grows at runtime (ADRs 0003, 0017): the bends' buffer is made at its capacity, a request past it is refused and counted, and the capacity stays provisional until ADR 0013's split of the GPU memory Budget sizes it.

The QTangent as the cooker stores it. ADR 0018's 28-byte vertex carries one quaternion for the tangent frame, so turning the frame is one quaternion product, and storing it back by the cooker's rule keeps every bent vertex one the main pass decodes like any other.

10

Limits

One arc, about one axis. A bend curves the middle of a rest Mesh that stands up +Y from y = 0, toward one azimuth, at one curvature over its whole height. It is not skinning: no bones, no weights, no twist.

A rigid turn of the tangent frame. Each vertex's offset and tangent frame turn rigidly with the middle at its height. The bend also stretches the surface along the middle on the side away from the azimuth and compresses it on the side toward it, which a rigid turn does not follow, so a normal that is neither horizontal nor along the middle leans a little off the bent surface's.

Bounds and BLASes stay as loaded. The pass rewrites vertices only. The culling pass tests the bent Mesh's cooked bounds, which must hold every shape it bends to, as Bend requires. A bent Mesh loaded as MeshUse::Drawn has no BLAS; its shadow comes from shadow proxies or, in the refit and rebuild forms, from a BLAS the next step updates.

A frame's bends, at most 4,096. Past BEND_CAPACITY the highest Meshes in the Arena keep their last shape, counted and warned about. A bend prepare drops as a race keeps no shape of its own that frame.

No bends, no time. A frame that bends nothing records no pass; its timestamp slots keep an earlier frame's values, and the readback reads the pass as taking no time.

History

The pass arrived in the third milestone with the crowd scene, in four steps: the pass, the Bend component and its blend between Ticks, the scene's swaying figures, and the shadow proxies that give them shadows; the refit form then cut the frame after the pass so each figure's own BLAS could follow its bend. This page describes the pass as it is.
