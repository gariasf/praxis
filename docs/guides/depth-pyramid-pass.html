The depth pyramid pass

A compute pass that reduces the depth pre-pass's 4x MSAA depth, level by level, into the depth pyramid, whose every texel holds the minimum depth over its share of the screen: under reverse Z, the farthest surface drawn anywhere beneath it. Phase two of the culling pass reads four of its texels per Instance to cull those hidden behind what phase one drew.

Describes main at b3d764b4 (2026-11-04). A change to the pass rewrites this page and moves the commit; nothing is appended. Read first: The culling pass for the test that reads the pyramid and the two phases around it.

Interface

Runs
Every frame, after the depth pre-pass has drawn phase one's Instances and before phase two of the culling pass, whatever the Render switches.
Reads
The depth target, 4x MSAA, every sample of every pixel; each later level, the level below it.
Writes
The depth pyramid, an R32Float texture of every level from level 0, half the targets' size rounded down and at least 1, to 1×1.
Dispatches
One per level, in order, in one compute pass: reduce_depth for level 0 in workgroups of 16×16 pixels, each writing 8×8 texels; reduce_level for every later level in workgroups of 8×8 texels. Eleven at 2560×1440.
Bind groups
Group 3, DEPTH_PYRAMID_LEVEL, one per level: level 0's holds the level and the depth target, every later level's the level and the level below. Phase two reads the whole pyramid through the culling pass's own group 3.
Shader
src/render/shaders/depth_pyramid.wgsl, with DEPTH_PYRAMID_TILE_SIZE declared from Rust.
Counted
depth_pyramid_pass in GPU time; every level of the pyramid in GPU memory, through the render targets.

1 · src/render/renderer.rs

Where it sits in the frame

The pyramid is built from the depth of the Instances phase one drew, the ones visible the frame before, so that phase two can test every other Instance in view against it within the same frame.

The frame's passes with shadow rays on, in the order the GPU receives them

  1. dynamic TLAS build
  2. bend pass
  3. culling, phase one
  4. Froxel pass
  5. depth pre-pass
  6. depth pyramid pass
  7. culling, phase two
  8. phase two's depth pass
  9. shadow mask pass
  10. lit pass
  11. tonemapping pass

The depth pre-pass clears the depth target to 0, the far plane, draws phase one's Instances into it with depth compared Greater, and stores it. The pyramid pass then reduces it, and phase two reads the result. Nothing after phase two reads the pyramid, so it is built fresh each frame and holds nothing of phase two's own Instances.

The pass records one compute pass of one dispatch per level, each level's bind group holding the level it writes and what it reduces:

// Level 0 reduces the depth target, each later level the one below,
// a workgroup per tile of texels: level 0's with an invocation per
// pixel of the tile, the others' per texel.
for (index, (bind_group, size)) in self.levels.iter().enumerate() {
    pass.set_pipeline(if index == 0 {
        &self.reduce_depth
    } else {
        &self.reduce_level
    });
    pass.set_bind_group(DEPTH_PYRAMID_LEVEL.index, bind_group, &[]);
    pass.dispatch_workgroups(
        size.width.div_ceil(DEPTH_PYRAMID_TILE_SIZE),
        size.height.div_ceil(DEPTH_PYRAMID_TILE_SIZE),
        1,
    );
}

DepthPyramidPass::record, src/render/depth_pyramid_pass.rs.

wgpu tracks each dispatch's use of every texture in a usage scope of its own, so it orders a level's writes before the next dispatch reads that level; the pass records no barrier itself. Both dispatch forms take the level's size over DEPTH_PYRAMID_TILE_SIZE, 8, as their workgroup counts: level 0's workgroups cover 16×16 pixels, which reduce to 8×8 texels.

2 · RenderTargets::new · overlapped_texels

Sizes and shares

Each level is the one below halved and rounded down, at least 1, as a mip chain is, and each level's rows and columns divide the screen evenly. A texel holds the minimum of every texel below whose share of the screen overlaps its own: two along a side that halves exactly, three along one whose level below is odd.

The render targets create the pyramid with the other targets whose size is the frame's. Level 0 is half the targets' width and height, rounded down and at least 1, and the texture holds every level to 1×1. At 2560×1440 that is eleven levels, 1280×720, 640×360, 320×180, 160×90, 80×45, 40×22, 20×11, 10×5, 5×2, 2×1 and 1×1: 1,228,763 texels, 4,915,052 bytes. Besides a view of every level, which phase two reads, the targets keep a view of each level alone, which the pass writes and then reads to reduce the next.

Texel x of a level n texels wide stands for x/n to (x+1)/n of the screen's width, its share. Where the level below is m texels wide, the texels below whose shares overlap it run from ⌊x·m/n⌋ to ⌈(x+1)·m/n⌉ − 1. Where m = 2n that is columns 2x and 2x+1; where m = 2n+1, a texel's share spans 2 + 1/n columns below, so it overlaps three.

// The texels of a level `below_size` texels in size that `texel` of a level
// `size` overlaps, the rows and columns of each level sharing the screen
// evenly: from ⌊texel × below / size⌋ to ⌈(texel + 1) × below / size⌉ − 1.
// Two along an axis that halves exactly, three where the level below is odd.
fn overlapped_texels(texel: vec2<u32>, size: vec2<u32>, below_size: vec2<u32>) -> OverlappedTexels {
    return OverlappedTexels(
        texel * below_size / size,
        ((texel + 1u) * below_size + size - 1u) / size - 1u,
    );
}

depth_pyramid.wgsl.

The shares matter because phase two finds texels by the same rule: a screen position u, from 0 to 1, falls in texel ⌊u·n⌋. A plain 2×2 reduction, reading columns 2x and 2x+1 everywhere, would leave the last column of an odd level unread and some texels short of their share; a pixel there that showed the far plane through a gap would be missed, and a visible Instance behind it culled.

3 · reduce_depth

Level 0: every sample of every pixel

Under 4x MSAA a pixel along a silhouette holds the near surface at some samples and what lies behind at others. Level 0 takes the minimum of all four samples of every pixel its share covers, so one sample that sees past an edge pulls the texel to the farther depth.

The depth target is bound as a texture_depth_multisampled_2d, which textureLoad reads one sample at a time. Each invocation of reduce_depth owns one pixel of a 16×16 tile, loads its four samples with four explicit loads, since Metal's compiler does not unroll a loop over them, and shares their minimum in workgroup memory. Rust asserts the sample count is 4, so the build fails if it changes.

fn pixel_minimum(pixel: vec2<u32>) -> f32 {
    return min(
        min(textureLoad(depth, pixel, 0), textureLoad(depth, pixel, 1)),
        min(textureLoad(depth, pixel, 2), textureLoad(depth, pixel, 3))
    );
}

depth_pyramid.wgsl.

Level 0 is half the depth target rounded down, so along an even side each texel overlaps the two pixels from twice its index, and along an odd side those two and the next texel's first. The workgroup's shared array therefore holds a 17th row and column: where a side is odd, the invocations along the tile's first row or column also load the pixel just past the tile. A pixel past the depth target's edge reads as 1, the nearest depth, which leaves any minimum as it is. After a barrier, the tile's first 8×8 invocations each take one texel's minimum from the shared minima and store it.

let first = 2u * local.xy;
let last = first + 2u;
var minimum = shared_block_minimum(first);
if odd_sides.x {
    minimum = min(minimum, min(pixel_minima[first.y][last.x], pixel_minima[first.y + 1u][last.x]));
}
if odd_sides.y {
    minimum = min(minimum, min(pixel_minima[last.y][first.x], pixel_minima[last.y][first.x + 1u]));
}
if all(odd_sides) {
    minimum = min(minimum, pixel_minima[last.y][last.x]);
}
textureStore(level, texel, vec4<f32>(minimum));

reduce_depth, depth_pyramid.wgsl, after the barrier.

At 2560×1440 level 0 is exactly half the target, so each texel reduces 2×2 pixels, 16 samples; where both of a target's sides are odd, a texel reduces 3×3 pixels, 36 samples.

4 · reduce_level

The later levels

Every later level runs one invocation per texel, in workgroups of 8×8, and takes the minimum of the texels below it overlaps, with explicit loads in blocks of four.

let overlapped = overlapped_texels(texel.xy, size, textureDimensions(level_below));
let first = overlapped.first;
let second = min(first + 1u, overlapped.last);
let last = overlapped.last;
var minimum = level_block_minimum(vec2<u32>(first.x, second.x), vec2<u32>(first.y, second.y));
if last.x > second.x {
    minimum = min(minimum, level_block_minimum(vec2<u32>(last.x), vec2<u32>(first.y, second.y)));
}
if last.y > second.y {
    minimum = min(minimum, level_block_minimum(vec2<u32>(first.x, second.x), vec2<u32>(last.y)));
}
if all(last > second) {
    minimum = min(minimum, level_block_minimum(vec2<u32>(last.x), vec2<u32>(last.y)));
}
textureStore(level, texel.xy, vec4<f32>(minimum));

reduce_level, depth_pyramid.wgsl.

The first block is the texel's first two columns and rows below, the second taken again where the texel overlaps one alone, as a 1-texel level below a 1-texel level does. A third column, a third row, or both, follow where the level below is odd. The two entry points stay apart, with a pipeline each: WGSL has no generics, and a function shared between them would make each use both the depth target's binding and the level below's, so each pipeline's layout holds only the two bindings its entry point reads.

5 · DepthPyramidPass::bind_render_targets

Recreated on resize

The pyramid's size follows the targets', so it lives with them and is created again on every resize; the passes whose bind groups hold it rebuild those groups, since a bind group keeps the textures it was built with.

Renderer::resize creates every render target again, then calls bind_render_targets on each pass whose groups read one: the pyramid pass, which rebuilds a group per level with that level's size, and the culling pass, whose group 3 holds the whole pyramid for phase two, among others. Left bound to the old targets, the pyramid pass would go on reducing the old depth into the old pyramid, and phase two would read texels the frame never wrote.

6 · occluded, src/render/shaders/culling.wgsl

What phase two reads

Phase two reads four texels per Instance, at the level where the Instance's screen rectangle spans at most two per axis, and culls the Instance where even its nearest point is farther than their minimum.

The test, with its rounding margins, the level it picks and why it computes each level's size rather than query it, is described in full on the culling pass's page. What it needs of the pyramid is two properties. Every texel's value is never nearer than the farthest sample beneath its share, so a rectangle's covering texels bound the farthest depth under it; and the levels' sizes are those of a mip chain, so phase two can derive any level's size from level 0's by shifting. Where phase one drew nothing, the depth stays 0, and no box in front of the camera lies behind 0: open sky hides nothing, and the first frame, before any Instance was visible, culls nothing.

9 · ADRs 0015, 0019

Why this way

A pyramid, not the depth itself. Bounding the farthest depth under a rectangle from the 4x depth means reading every sample under it, 160,000 for a square 200 pixels on a side; a pyramid answers with four reads whatever the rectangle's size. Greene, Kass and Miller's Z pyramid combines four depths into the farthest at each coarser level; ADR 0019 takes it, with two phases, for its GPU-driven culling.

The minimum, not the maximum. Under ADR 0015's reverse Z a nearer depth is greater, so the farthest is the smallest, and the ADR says a Hi-Z pyramid keeps the minimum. A pyramid that kept the maximum would let a box showing through a gap be culled: built so on purpose, the culled and unculled captures differed by 2,742 to 29,519 pixels on four Reference scenes on Metal.

Even shares, not a plain 2×2. A plain reduction is exact only where every level halves, which 1440p's chain stops doing at 80×45. Taking every texel below whose share overlaps costs a third load along an odd side and keeps the pyramid conservative at any target size.

Every sample, not one. Reading one sample a pixel, or a 1x depth, would let a pixel whose other samples see past an edge hide what lies behind; phase two also grows each rectangle by a pixel so that every sample a covered pixel holds is in the texels it reads. Published reductions start from less: one from a GPU's depth tile metadata, another from a 16-bit depth already decompressed. Reading one sample instead of four cut level 0 by a third on town and by half on uv-grid on the M4 Pro, which is the price of keeping the test conservative under MSAA.

An invocation per pixel at level 0. With an invocation per texel each issued sixteen loads; with one per pixel each issues four and the texels' minima come from workgroup memory, which saved about 40 µs on town and matched a CPU reduction texel for texel. Fusing levels 1 to 3 into level 0's dispatch was measured and was slower: their later steps run on 16, 4 and 1 of the 256 invocations behind barriers.

A dispatch per level. The ten later levels cost about 40 µs together, mostly per-dispatch cost. A single-pass downsampler would save some of it, but its last step needs storage writes visible across workgroups, which not every WebGPU platform promises; it waits until a profile names the pyramid's tail.

Explicit loads. In its first form, written as a loop over pixels and samples, level 0 took 656 µs on the M4 Pro, a loop over samples alone 175, and the written-out loads 150: Metal's compiler serialised the loads in a loop.

10

Limits

Phase one's depth only. The pyramid holds what phase one drew, the Instances visible the frame before. After a camera cut it holds little, and phase two culls little in that frame; the image stays right.

Four samples, fixed. Level 0 loads exactly four samples a pixel; another sample count fails the build until the loads are rewritten.

Bandwidth-bound. Level 0 reads every byte of the multisampled depth, so its cost scales with the target's area and does not fall with what a scene draws. A minimum-depth resolve in the depth pre-pass would let level 0 read one sample a pixel; Metal has one, but wgpu 30 exposes none.

History

The pass was built in the third milestone with the two-phase culling that reads it: the pyramid first, with its even shares and every sample at level 0 written out as explicit loads, then phase two's test of it. A later comparison of its cost with the published figures found level 0 at the M4 Pro's bandwidth floor and the sources reading less input, and moved level 0 to an invocation per pixel. The development narrative, with each step's measurements, was the notebook's volume Depth Pyramid Explained, which this page replaces; docs/performance.md keeps the measurements.
