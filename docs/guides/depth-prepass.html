The depth pre-pass

The render pass that draws phase one of the culling pass's frame's draw into the 4x MSAA depth target, cleared to 0 and kept by Greater under reverse Z, before anything is shaded, so the depth pyramid can reduce it and the lit pass can shade only what it kept; with shadow rays on it writes each sample's surface normals beside its depth, and phase two's depth pass draws phase two's Instances the same way once the pyramid has tested them.

Describes main at b3d764b4 (2026-11-04). A change to the pass rewrites this page and moves the commit; nothing is appended. Read first: MSAA for samples and fragments, The culling pass for the frame's draw the GPU builds and its two phases.

Interface

Runs
Every frame: after phase one of the culling pass and the Froxel pass, before the depth pyramid pass. Phase two's depth pass runs with the shadow_rays Render switch on, as Praxis ships: after phase two of the culling pass, before the shadow mask pass. With it off, the lit pass draws phase two's depth.
Reads
The frame's draw: its packed indices as the index buffer and the indirect arguments of the phase's draw; the Meshlet records, the Instances, the Meshlets and the vertex Arena, from which the vertex shader pulls each vertex; the camera.
Writes
The depth target, Depth32Float at 4x MSAA: the pre-pass clears it to 0 and stores it, phase two's depth pass loads and stores it. With shadow rays on, the surface normals, Rgba8Unorm at 4x MSAA, cleared and loaded alike.
Draws
One draw_indexed_indirect per pass, at the phase's offset in the frame's draw.
Bind groups
The groups its vertex stage sees: group 0, the frame, for the camera; group 2, the scene geometry; group 3, the main pass inputs, for the Meshlet records. Its fragment stage reads no bind group.
Shader
src/render/shaders/main.wgsl: vs_depth_prepass with no fragment stage, or with shadow rays on vs_depth_normals and fs_surface_normals.
Counted
depth_prepass and phase_two_depth_pass in GPU time; the pre-pass inside ADR 0019's gate, which is measured with shadow rays off, when phase two's depth is the lit pass's; their draws in draw_calls; the depth target and the surface normals in GPU memory.

1 · MainPass::record_depth_pass

Where it sits in the frame

Depth comes before shading. The pre-pass gives the depth pyramid the surfaces phase two's occlusion test needs, gives the lit pass the one depth per sample it shades at, and, with shadow rays on, gives the shadow mask pass the surfaces it traces from.

The frame's passes with shadow rays on, in the order the GPU receives them

  1. dynamic TLAS build
  2. bend pass
  3. culling, phase one
  4. Froxel pass
  5. depth pre-pass
  6. depth pyramid pass
  7. culling, phase two
  8. phase two's depth pass
  9. shadow mask pass
  10. lit pass
  11. tonemapping pass

Phase one of the culling pass draws the Instances in view that were visible the frame before. The pre-pass draws them into depth; the depth pyramid pass reduces that depth to the farthest over each share of the screen; phase two tests every other Instance in view against the pyramid and draws what it does not hide. One function records both depth passes, differing in the attachment's load, the draw's offset and whether the surface normals are cleared.

let (label, depth_attachment, clears_surface_normals, draw_offset) = match phase {
    CullingPhase::One => (DEPTH_PREPASS, render_targets.depth_attachment(), true, 0),
    CullingPhase::Two => (
        PHASE_TWO_DEPTH_PASS,
        render_targets.loaded_depth_attachment(),
        false,
        PHASE_TWO_DRAW_OFFSET,
    ),
};
let surface_normals = [Some(
    render_targets.surface_normals_attachment(clears_surface_normals),
)];
let mut depth_pass = encoder.begin_render_pass(&wgpu::RenderPassDescriptor {
    label: Some(label),
    color_attachments: if self.shadow_rays {
        &surface_normals
    } else {
        &[]
    },
    depth_stencil_attachment: Some(depth_attachment),
    occlusion_query_set: None,
    timestamp_writes,
    multiview_mask: None,
});
depth_pass.set_pipeline(&self.depth_prepass_pipeline);
self.bind(
    &mut depth_pass,
    bind_groups
        .iter()
        .copied()
        .filter(|&(definition, _)| definition.visible_to(wgpu::ShaderStages::VERTEX)),
);
depth_pass.draw_indexed_indirect(&self.frame_draw_buffer, draw_offset);

MainPass::record_depth_pass, src/render/main_pass.rs.

The depth pipeline's layout keeps only the bind groups its vertex stage sees, since its fragment stage reads none: the Materials' group, which the fragment stage alone reads, is left out of the layout and not set. With shadow rays off the pipeline has no fragment stage at all.

2 · vertex_output · src/render/shaders/main.wgsl

One draw, its vertices pulled

The draw has no vertex buffers. Each index the culling pass wrote packs a Meshlet record above its low bits and a vertex of that Meshlet below them; the vertex shader reads the record for the Instance, the Meshlet and the Material, and pulls the vertex from the vertex Arena.

fn vertex_output(packed_index: u32) -> VertexOutput {
    var out: VertexOutput;
    // The frame's draw has no base vertex, so the vertex index is the packed
    // index: a Meshlet record, which names the Instance, the Meshlet and the
    // Material, and a vertex of that Meshlet (ADR 0019).
    let index = unpack_index(packed_index);
    let record = meshlet_records[index.record];
    let instance = instances[record.instance_slot];
    let first_vertex = meshlets[record.meshlet].first_vertex;
    let vertex = decode_vertex(vertices[meshlet_vertices[first_vertex + index.vertex]]);
    let position = camera_relative_position(
        instance.anchor,
        instance.offset,
        camera.anchor,
        camera.offset,
        instance.rotation_scale * vertex.position
    );
    out.clip_position = camera.view_proj * vec4<f32>(position, 1.0);

vertex_output, main.wgsl, to the clip position; the rest of it fills what the lit pass reads.

unpack_index splits the index at MESHLET_VERTEX_BITS, which Rust declares from the cooker's limit of 64 vertices a Meshlet. Since the record is in every index, triangles of different Meshlets or Instances never share an index, even where their positions coincide. The position is composed relative to the camera from the Instance's Anchor and offset and the camera's (ADR 0014), so no World position reaches the GPU in f32, and the view-projection matrix holds no translation.

All three entry points of the main pass that place vertices call this one function, and declare the clip position @invariant, so the depth passes and the lit pass compute each vertex's depth by the same expressions and the lit pass's Equal test meets exactly the depth kept here. vs_depth_prepass returns only that position; vs_depth_normals also passes on the position, normal and Material ID the fragment stage below reads.

3 · src/render/targets.rs · ADR 0015

Reverse Z: cleared to 0, nearer is greater

Depth is reversed with an infinite far plane: the far plane is 0, the near plane 1, and a sample keeps the greatest depth. A float's precision is densest near 0, which reverse Z puts at the distance, where a perspective projection needs it.

pub fn depth_stencil_state() -> wgpu::DepthStencilState {
    wgpu::DepthStencilState {
        format: DEPTH_FORMAT,
        depth_write_enabled: Some(true),
        depth_compare: Some(wgpu::CompareFunction::Greater),
        stencil: wgpu::StencilState::default(),
        bias: wgpu::DepthBiasState::default(),
    }
}
pub fn depth_attachment(&self) -> wgpu::RenderPassDepthStencilAttachment<'_> {
    wgpu::RenderPassDepthStencilAttachment {
        view: &self.depth,
        depth_ops: Some(wgpu::Operations {
            load: wgpu::LoadOp::Clear(0.0),
            store: wgpu::StoreOp::Store,
        }),
        stencil_ops: None,
    }
}

depth_stencil_state and RenderTargets::depth_attachment, src/render/targets.rs.

The projection puts the near distance in clip z and the view depth in clip w, so a stored depth is the near distance over the view depth: 1 at the near plane, falling toward 0 with distance, never reaching it. With a 0.1 m near plane in Depth32Float, standard depth resolves 2.4 m at 2 km and reversed depth with no far plane 0.15 mm (ADR 0015). A sample nothing covers keeps the clear value, 0, which every later pass reads as background. The same direction runs through the frame: the depth pyramid keeps the minimum, the farthest; the shadow mask pass takes a pixel's nearest sample as its greatest depth.

4 · fs_surface_normals

The surface normals

The depth passes already rasterise every triangle the shadow mask pass will trace from. With shadow rays on they also write, for each sample, the triangle's own normal and the normal interpolated over it, so the mask knows what the triangle was rather than guessing it from neighbouring depths.

@fragment
fn fs_surface_normals(in: DepthNormalsOutput) -> @location(0) vec4<f32> {
    let crossed = cross(dpdx(in.camera_relative_position), dpdy(in.camera_relative_position));
    let crossed_length_squared = dot(crossed, crossed);
    let toward_camera = -normalize(in.camera_relative_position);
    let unit_crossed = crossed * inverseSqrt(crossed_length_squared);
    let triangle_normal = select(
        toward_camera,
        select(unit_crossed, -unit_crossed, dot(unit_crossed, toward_camera) < 0.0),
        crossed_length_squared > 0.0
    );
    let normal_length_squared = dot(in.normal, in.normal);
    let interpolated_normal = select(
        triangle_normal,
        in.normal * inverseSqrt(normal_length_squared),
        normal_length_squared > 0.0
    );
    let encoded_normals = vec4<f32>(octahedral_encode(triangle_normal), octahedral_encode(interpolated_normal))
        * 0.5 + 0.5;
    // Reads the flat input, so the stage has one the compiler cannot drop,
    // to no effect: Material IDs index the Material table, far below
    // NO_MATERIAL - 1.
    return select(encoded_normals, vec4<f32>(0.0), in.material_id == NO_MATERIAL - 1u);
}

fs_surface_normals, main.wgsl.

The triangle's normal. Across a triangle the camera-relative position changes linearly in the triangle's plane, so its screen-space derivatives are two vectors in that plane and their cross product is its normal. Where a 2×2 quad overhangs the triangle's edge, the pixels outside run as helper invocations of the same triangle, so even at an edge the derivatives belong to it. The cross product's sign depends on how the triangle lies on screen, so it is flipped to face the camera, the side the sample shows; a triangle seen exactly edge-on spans no plane on screen and takes the direction toward the camera. Neither case gives a NaN.

The interpolated normal. The vertex normals, turned by the Instance's normal matrix and interpolated over the triangle, then normalised: the lit pass's normal before its normal map. One that interpolates to zero length takes the triangle's. The shadow mask reads no Textures, so normal maps play no part in it.

Octahedral, 8 bits a coordinate. A unit vector has two degrees of freedom. Projected onto the octahedron |x| + |y| + |z| = 1, with the lower half folded over the upper, every direction lands in the square [−1, 1]² with nearly even precision:

fn octahedral_encode(direction: vec3<f32>) -> vec2<f32> {
    let projected = direction.xy / (abs(direction.x) + abs(direction.y) + abs(direction.z));
    let sign = select(vec2<f32>(-1.0), vec2<f32>(1.0), projected >= vec2<f32>(0.0));
    return select((1.0 - abs(projected.yx)) * sign, projected, direction.z >= 0.0);
}

octahedral_encode, common.wgsl; the shadow mask pass decodes with octahedral_decode beside it.

Each coordinate is mapped from [−1, 1] to [0, 1] for the Rgba8Unorm target: the triangle normal in red and green, the interpolated one in blue and alpha, 4 bytes a sample. Decoded, each lies within 0.95° of the normal it encodes where the store rounds to the nearest step, as Metal's does; Vulkan only recommends that rounding and may round to either neighbour, which about doubles the error, and the shadow mask pass's margins are sized for both.

Under 4x MSAA the fragment shader runs once per pixel per triangle and its output lands in every sample that triangle covers, so both normals are values at the pixel's centre, credited to each sample of the triangle. The pre-pass clears the target, phase two's depth pass loads it, and both store it for the shadow mask pass. With shadow rays off the depth pipeline writes depth alone and the target is not written, though the targets module creates it either way.

5 · DepthNormalsOutput · ADR 0019

The flat input: each sample credited to its own triangle

On the Apple M4 Pro, a fragment stage that reads no flat input can have the fragments of neighbouring triangles that share indices merged in a pixel, one triangle's inputs written into both's samples. The depth passes and the lit pass must agree on which triangle each sample shows, so both read a flat input.

struct DepthNormalsOutput {
    @builtin(position) @invariant clip_position: vec4<f32>,
    @location(0) camera_relative_position: vec3<f32>,
    @location(1) normal: vec3<f32>,
    @location(2) @interpolate(flat) material_id: u32,
}

main.wgsl.

The lit pass reads its flat Material ID to find its Material, so its fragments are never merged. Before the depth passes read one, their fragments could be: at a sample beside a shared edge, the normals could come from one triangle while the lit pass shaded the other there, at the same depth, so it passed the Equal test. Across a crease the first may turn from a light the second faces, and the mask hid a light the shading called lit. Which fragments merge depends on what the draw holds, so culling on and off gave town images that differed at a few pixels, which is how it was found.

An input a shader never reads can be dropped by the compiler, and the stage then reads no flat input after all. So fs_surface_normals compares the Material ID with NO_MATERIAL − 1, the largest u32 but one: Material IDs index the Material table, far smaller, so the comparison never holds and the normals pass through unchanged, but the compiler cannot bound a value read from a vertex output and keeps the read. What merging is, and how it was measured, is on Metal quirks.

6 · PHASE_TWO_DEPTH_PASS · fs_depth

Phase two's depth

Phase two's Instances are missing from the depth the pre-pass kept, and the lit pass shades only at depth equal. With shadow rays on they are drawn into depth in a pass of their own, so the shadow mask pass sees every surface; with them off, the lit pass draws them into depth just before it shades.

With shadow rays on, phase two's depth pass is the same pipeline as the pre-pass, recorded at PHASE_TWO_DRAW_OFFSET in the frame's draw, loading the depth target and the surface normals and storing both for the shadow mask pass. It costs one more load and store of the 4x depth each frame, even when phase two draws nothing, as in a scene where nothing moves into view.

With shadow rays off, no compute pass reads depth before the lit pass, so the lit pass draws phase two's depth inside its own render pass first, with the pre-pass's vertex stage and a fragment stage that writes nothing:

// With shadow rays off, the lit pass draws phase two's Instances into depth
// before it shades, with this and `vs_depth_prepass`: it writes no colour.
@fragment
fn fs_depth() {}

main.wgsl. Every pipeline the lit pass sets names its colour target, so this one names the HDR format and a write mask of nothing.

Without that draw, an Instance phase two adds fails depth equal and shows the background. The lit pass's depth is then discarded at its end, so the extra load and store never happen.

9 · ADRs 0014, 0015, 0019, 0021

Why this way

A depth pre-pass at all. ADR 0019's option A: the pre-pass seeds the Hi-Z pyramid phase two culls against and the lit pass's depth-equal test, so the lit pass shades each covered sample's visible triangle once and nothing behind it. The culling pass writes the frame's draw in slot order, not front to back, so without depth first the lit pass would shade surfaces later hidden; the pre-pass restores front-to-back cost at the price of rasterising the frame's triangles twice.

The GPU builds the draw. Recording a draw per Primitive of each Instance on the CPU grows with the Instances, and town holds about a quarter of a million. The culling pass writes one index buffer with each phase's indirect arguments beside it, drawn with one draw_indexed_indirect per pass, one native call on every backend, since wgpu's Metal backend has no count draws and runs multi-draw as a CPU loop (ADR 0019).

Reverse Z with no far plane. The view reaches 2 km; reversed Depth32Float resolves sub-millimetre depth there where standard depth resolves metres, and needs no far plane at all (ADR 0015).

4x MSAA depth. Thin geometry, such as town's wires, needs coverage tested at more than one place per pixel in every frame, since ADR 0008 lets nothing average frames, and a post-process filter cannot rebuild what no sample saw; 4x is the Apple9 GPU family's maximum (ADR 0019, MSAA).

Normals written here, not rebuilt from depth. The shadow mask pass runs before the lit pass, so the lit pass cannot write them, and depth alone gives at best each sample's plane, guessed from neighbours that at an edge belong to other triangles. Of the options measured on town, writing the triangle's normal and the interpolated one per sample, and starting a ray inside the surface where the triangle turns from a light the interpolated normal faces, was chosen over moving the ray's origin by the shading normals, which needs the triangle's vertices, and over an offset estimated from the depth's curvature, which is approximate. Two normals at 8 bits a coordinate fill the 4 bytes a sample one normal at 16 bits would have; ADR 0019's amendment records the target and its cost.

A flat read, not another draw. Of the ways to make the depth passes credit each sample to the lit pass's triangle, reading a flat input costs nothing measurable and matches the measurement that a fragment stage reading one is never merged. Drawing the normals in one draw of both phases at depth equal would cost about another geometry pass, and no specification promises identical fragments from different fragment shaders anyway; writing them in the lit pass's own draw is impossible, as the mask is traced before it; a triangle ID per sample, as a visibility buffer stores, is exact by construction and stays the fallback should another GPU merge regardless. WGSL's @invariant and Metal's preserved invariance cover the position alone, which already made depth equal.

Phase two's depth in its own pass, with rays. The mask must see every surface the lit pass will shade before the lit pass runs, so phase two's depth cannot wait for it; with rays off nothing needs it sooner, and drawing it inside the lit pass saves a load and store of the 4x depth.

10

Limits

Twice through the triangles. Every triangle of phase one is rasterised here and again in the lit pass, which on town is what breaches ADR 0019's gate; the lever every option shares is fewer triangles, which LOD will bring.

Merging measured on one GPU. Only the M4 Pro was measured. Another Apple GPU, or a later macOS, may merge under other conditions or regardless of a flat input; the culled-against-unculled check on Metal would show it, and a triangle ID per sample is the way out.

Normals at the pixel's centre. The normals written into a sample are the triangle's values at the pixel's centre, not at the sample, and quantised to within about a degree; the shadow mask pass's margins absorb both.

Edge-on triangles. A triangle seen exactly edge-on records the direction toward the camera as its normal, not its own.

The target with rays off. The surface normals are created and counted in GPU memory even when shadow rays are off and nothing writes them.

History

The pre-pass took its present form in the third milestone. It began as a depth-only pass over a draw the CPU recorded per Primitive; it came to draw the culling pass's frame's draw, then only phase one's, phase two's depth following first inside the lit pass and, once the shadow mask pass needed it, in a pass of its own; with shadow rays it gained the surface normals, and then the flat read that keeps them credited to the lit pass's triangle. The merging, its measurement and the alternatives are on Metal quirks; this page describes the pass as it is.
