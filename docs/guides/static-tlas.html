The static TLAS

A TLAS over every static Instance, each in an entry of its own and tagged with its slot, placed in a frame whose origin is the corner of the camera's Anchor in the first Frame data; held in two TLASes, one bound for rays while a worker thread brings the other up to date and records its build, which the main thread submits and binds the frame after, it is the first structure every shadow ray queries.

Describes main at 73aec1f3 (2026-11-07). A change to the static TLAS rewrites this page and moves the commit; nothing is appended. Read first: A BLAS per Mesh for the structures its entries place, Instance Buffer Explained for the slots and writes it follows. The dynamic TLAS holds the Instances it leaves out; the shadow mask pass traces against both.

Interface

Runs
In every frame's Renderer::upload, after the loads' BLASes are compacted and before the dynamic TLAS's fill: StaticTlas::update takes the frame's entry changes, binds the spare whose build the frame before submitted, submits a build the worker has finished, and hands the idle spare to a new worker when either TLAS lacks a change. The build runs on the worker thread, never in the frame's encoder.
Reads
The Frame data's instance_writes and the instances they cover; each static Instance's BLAS, from MeshPool::blas; the camera's Anchor, in the first Frame data only; the wait_for_static_tlas Render switch, which a capture sets.
Writes
The entry each static Instance's slot holds and each frame's entry changes, which both TLASes take; the Anchor of its frame, which the camera uniform carries to the GPU as tlas_anchor and the dynamic TLAS shares; the static Instances it leaves out, by slot.
Builds
Both TLASes, empty, at creation; then one build_acceleration_structures of the spare alone, recorded and finished on the worker into a command buffer of its own, which the main thread submits before the frame's, when the bound TLAS lacks a change.
Bind groups
Group 2 of the shadow mask pass, SHADOW_RAY_SCENE, as static_tlas: one group per TLAS, built once since each is rebuilt in place, and set by StaticTlas::bound_index.
Shader
Queried in first_intersection, src/render/shaders/shadow_mask.wgsl.
Counted
static_instances_left_out in counters; static_tlas_build_time, the worker's time on the build a frame submits, and frames_until_traced, in a frame that binds a new build; both TLASes at full capacity in the acceleration structures' ledger, and so in gpu_memory_bytes; the main thread's share, the entry changes and the submit, in the static_tlas_update stage. No GPU pass time is taken of its build.

1 · Renderer::upload

Where it sits in the frame

The static TLAS is updated in the upload, after the frame's loads have been built and compacted and before the dynamic TLAS's fill. It records nothing into the frame's encoder: a build lands on the GPU in a command buffer of its own, and rays trace it from the frame after its submit.

// Loads staged since the last frame land before its copies and
// draws, and their BLASes are compacted before the static TLAS
// takes them.
recorder.counters.uploaded_bytes += self.load_staging.submit(&self.queue);
self.mesh_pool.compact_blases(&self.queue);
// Before the frame's encoder, as `prepare_encoder` says; it counts
// as the dynamic TLAS's recording.
let preparing = Instant::now();
self.dynamic_tlas.prepare_encoder(&self.device);
let prepare_time = recorder.stage(DYNAMIC_TLAS_RECORDING, preparing);
let mut encoder = create_frame_encoder(&self.device);
let updating = Instant::now();
let static_tlas_update = self.static_tlas.update(
    frame,
    &self.mesh_pool,
    &self.device,
    &self.queue,
    self.wait_for_static_tlas,
);
let update_time = recorder.stage(STATIC_TLAS_UPDATE, updating);
recorder.counters.static_tlas_build_time =
    static_tlas_update.build_time.unwrap_or_default();
recorder.counters.frames_until_traced = static_tlas_update.frames_until_traced;
recorder.counters.static_instances_left_out = self.static_tlas.instances_left_out();
// Shadow rays start in the static TLAS's frame, whose Anchor the
// first Frame data's camera set, and the dynamic TLAS shares it. Its
// fill counts as its recording, not as the upload.
let tlas_anchor = self.static_tlas.anchor();
TLAS's encoder and fill are the dynamic TLAS's.

Renderer::new creates it with capacities.static_tlas_instances entries in each of its two TLASes, the capacity it derives from the Budgets (section 5), and builds both empty at once, so rays can query either from the first frame. Each frame's upload first submits the loads staged since the last frame and, when they loaded Meshes, waits for their BLASes to be built and compacted (A BLAS per Mesh, Compaction); only then does StaticTlas::update take the frame's Instance writes. Its time on the main thread is the static_tlas_update stage, taken out of upload; the worker's time on the build the update submits goes into Frame stats as static_tlas_build_time, apart from the frame, and the frames a change waited to be traced as frames_until_traced. The update also hands Frame stats the count of Instances it left out, and its Anchor goes into the camera uniform, which shadow rays start from.

2 · StaticTlas::entry_changes · tlas_instance

An entry per static Instance

A static Instance whose Mesh has a BLAS takes an entry of its own, a freed one before a fresh one, tagged with its slot; a Moving Instance, a freed slot and a Mesh no ray traces empty its entry and free it. Each is an entry change, which both TLASes take in turn. Its slot is only the key that finds the entry, so a slot past the capacity traces like any other.

/// The static TLAS (ADR 0020): each static Instance in an entry of its own,
/// tagged with its slot, in a frame whose origin is the corner of the
/// camera's Anchor in the first Frame data it takes, never re-anchored.
/// Two TLASes hold it: rays trace the bound one while a worker thread brings
/// the spare up to date and records its build, which the main thread submits
/// (ADR 0016), and the spare is bound from the frame after that submit. A
/// frame that changes a static Instance or frees one's slot starts a build
/// once the spare is idle; both are built empty at creation, so rays can
/// always query them.
pub struct StaticTlas {
    bound: Counted<wgpu::Tlas>,
    /// Which of the two `bound` is: 0 for the one bound at creation.
    bound_index: usize,
    spare: Option<Spare>,
    /// The entry changes each TLAS's entries lack, by TLAS, oldest first;
    /// the bound one's are those its last build lacked.
    behind: [Vec<ChangeBatch>; 2],
    /// Frames it has taken.
    frame: u64,
    capacity: u32,
    anchor: Option<[i32; 3]>,
    /// The entry each slot's static Instance holds, by slot, up to the
    /// highest slot that held one.
    entry_by_slot: Vec<Option<u32>>,
    /// Entries emptied since they were filled, taken before fresh ones.
    free_entries: Vec<u32>,
    /// One past the highest entry filled.
    end: u32,
    /// Static Instances it had no free entry for, by slot, which take the
    /// entries still free after a later frame's writes, lowest slot first.
    left_out: BTreeMap<u32, wgpu::TlasInstance>,
}
/// An empty static TLAS of `capacity` entries, both TLASes counted in
/// `memory` and built at once through `queue`.
pub fn new(
    device: &wgpu::Device,
    memory: &GpuMemory,
    queue: &wgpu::Queue,
    capacity: u32,
) -> Self {
    let create = |label| {
        memory.create_tlas(
            device,
            &wgpu::CreateTlasDescriptor {
                label: Some(label),
                max_instances: capacity,
                // Rebuilt only when its Instances change, traced every frame.
                flags: wgpu::AccelerationStructureFlags::PREFER_FAST_TRACE,
                update_mode: wgpu::AccelerationStructureUpdateMode::Build,
            },
        )
    };
    let bound = create("Static TLAS 0");
    let spare = create("Static TLAS 1");
    let mut encoder = device.create_command_encoder(&wgpu::CommandEncoderDescriptor {
        label: Some("Static TLAS Encoder"),
    });
    encoder.build_acceleration_structures(std::iter::empty(), [&*bound, &*spare]);
    queue.submit(std::iter::once(encoder.finish()));
    Self {
        bound,
        bound_index: 0,
        spare: Some(Spare::Idle(spare)),
        behind: [Vec::new(), Vec::new()],
        frame: 0,
        capacity,
        anchor: None,
        entry_by_slot: Vec::new(),
        free_entries: Vec::new(),
        end: 0,
        left_out: BTreeMap::new(),
    }
}

/// The entry changes of `frame`'s Instance writes, its entries taken and
/// freed as its static Instances need.
fn entry_changes(&mut self, frame: &FrameData, mesh_pool: &MeshPool) -> Vec<EntryChange> {
    let mut changes = Vec::new();
    let anchor = *self.anchor.get_or_insert(frame.camera.anchor);
    let was_leaving_out = !self.left_out.is_empty();
    for write in &frame.instance_writes {
        let instances = &frame.instances[write.instances.clone()];
        for (slot, instance) in (write.first_slot..).zip(instances) {
            // A freed slot's Instance has no Mesh, so no BLAS.
            let blas = (!write.moving)
                .then(|| {
                    mesh_pool
                        .handle_at(instance.mesh)
                        .and_then(|handle| mesh_pool.blas(handle))
                })
                .flatten();
            let Some(blas) = blas else {
                if let Some(entry) = self.release(slot) {
                    changes.push(EntryChange {
                        entry,
                        instance: None,
                    });
                }
                continue;
            };
            let instance = tlas_instance(blas, anchored_transform(instance, anchor), slot);
            match self.entry_of(slot) {
                Some(entry) => changes.push(EntryChange {
                    entry,
                    instance: Some(instance),
                }),
                None => {
                    self.left_out.insert(slot, instance);
                }
            }
        }
    }
    while !self.left_out.is_empty()
        && let Some(entry) = self.take_entry()
    {
        let (slot, instance) = self.left_out.pop_first().expect("not empty");
        self.hold(slot, entry);
        changes.push(EntryChange {
            entry,
            instance: Some(instance),
        });
    }
    if !was_leaving_out && !self.left_out.is_empty() {
        tracing::warn!(
            left_out = self.left_out.len(),
            capacity = self.capacity,
            "Static Instances left out of the static TLAS: it is full, so they cast no shadow"
        );
    }
    changes
}

/// The entry of `slot`'s static Instance, taking one if it has none;
/// None when it is full.
fn entry_of(&mut self, slot: u32) -> Option<u32> {
    self.left_out.remove(&slot);
    if let Some(entry) = self.entry_by_slot.get(slot as usize).copied().flatten() {
        return Some(entry);
    }
    let entry = self.take_entry()?;
    self.hold(slot, entry);
    Some(entry)
}

/// Frees `slot`'s entry, if it has one, and returns it; drops its
/// Instance if left out.
fn release(&mut self, slot: u32) -> Option<u32> {
    self.left_out.remove(&slot);
    let entry = self
        .entry_by_slot
        .get_mut(slot as usize)
        .and_then(Option::take)?;
    self.free_entries.push(entry);
    Some(entry)
}

fn hold(&mut self, slot: u32, entry: u32) {
    let slot = slot as usize;
    if slot >= self.entry_by_slot.len() {
        self.entry_by_slot.resize(slot + 1, None);
    }
    self.entry_by_slot[slot] = Some(entry);
}

/// A freed entry, else a fresh one, else None when it is full.
fn take_entry(&mut self) -> Option<u32> {
    self.free_entries.pop().or_else(|| {
        let fresh = (self.end < self.capacity).then_some(self.end)?;
        self.end += 1;
        Some(fresh)
    })
}

StaticTlas::entry_of, StaticTlas::release, StaticTlas::hold and StaticTlas::take_entry, src/render/acceleration_structures.rs.

Prepare writes Instances in runs of consecutive slots, each run an InstanceWrite flagged moving where its Instances are Moving Instances, and splits a run where the flag changes. The update walks every written slot. A static Instance gets its Mesh's BLAS, found through the Handle of the Mesh at the index the Instance names (MeshPool::handle_at); a Moving Instance gets none, so a static Instance that starts to move empties its entry the frame it does. A freed slot is written an Instance whose Mesh is NO_MESH, which no Mesh is loaded at, and a Mesh loaded MeshUse::Drawn has no BLAS, so both empty the entry.

A written static Instance asks entry_of for its slot's entry: the one the slot already holds, else the last entry freed, else the next fresh one below the capacity, and when neither is left its Instance waits in left_out, keyed by slot. The entry's new Instance becomes an EntryChange, pushed into the frame's list; a frame that changes nothing static allocates no list. A write with no BLAS calls release, which frees the slot's entry into free_entries, drops it from entry_by_slot, a table indexed by slot, and returns the entry to empty. After the writes, the waiting Instances take whatever entries are still free, lowest slot first, each a change. So prepare's slots never limit what it holds: a Chunk's range, which comes past the highest slot taken, traces whether it lies under the capacity or not. Entries are taken in write order, and wgpu-core builds from the filled entries in entry order, skipping empty ones, so a scene whose first frame writes its static Instances in slot order builds from the list it built from when entries were slots.

/// An Instance's entry in a TLAS: `blas`, placed by `transform`
/// (`anchored_transform`) and tagged with its `slot`.
fn tlas_instance(blas: &wgpu::Blas, transform: [f32; 12], slot: u32) -> wgpu::TlasInstance {
    // Every ray's cull mask.
    wgpu::TlasInstance::new(blas, transform, slot, 0xff)
}

tlas_instance, src/render/acceleration_structures.rs, which the dynamic TLAS's entries share.

Each entry is a wgpu::TlasInstance of the BLAS, a transform, custom data and a mask. The custom data is the slot, which a hit returns to the shader as instance_custom_data, so a hit can name the Instance it struck; the shadow mask pass's rays need only whether they hit, and read it nowhere. wgpu-core rejects custom data of 224 or more at build time, and every slot under the capacity fits, as a test holds the checked-in Budgets' Instance slots and static TLAS entries to it. The mask is 0xff: a ray's 8-bit cull mask counts an entry only where the two share a bit, and the shadow rays pass 0xffu, so every ray sees every entry.

3 · anchored_transform

A frame anchored at load

An entry's transform is twelve f32, so the TLAS owns a frame of its own, as ADR 0014 requires of any subsystem that computes in f32: its origin is the corner of the camera's Anchor in the first Frame data it takes, and each entry's translation is composed from that corner in f64 and rounded to f32 once.

/// `instance`'s transform as rows of the 3×4 matrix a TLAS Instance holds,
/// its translation from `anchor`'s corner composed in f64, so only the f32
/// result rounds (ADR 0014).
fn anchored_transform(instance: &InstanceData, anchor: [i32; 3]) -> [f32; 12] {
    let [x_axis, y_axis, z_axis] = instance.rotation_scale;
    let row = |axis: usize| {
        let cells = i64::from(instance.anchor[axis]) - i64::from(anchor[axis]);
        let translation = cells as f64 * ANCHOR_CELL_SIZE + f64::from(instance.offset[axis]);
        [x_axis[axis], y_axis[axis], z_axis[axis], translation as f32]
    };
    bytemuck::cast([0, 1, 2].map(row))
}

anchored_transform, src/render/acceleration_structures.rs.

translation = (Instance Anchor − TLAS Anchor) × 64 m + Instance offset

The difference of the two Anchors is exact in integers, and the Instance's offset from its own cell's corner is under 64 m, so the only rounding that grows with distance is the final one, to f32, of the distance from the TLAS's origin. The rows come out as the 3×4 matrix [R | t], row-major, as wgpu takes them: each row is one axis's components of the rotation and scale columns, then that axis's translation.

The anchor is set by the first update and never moved, and StaticTlas::anchor returns it, zero before that update. The camera uniform carries it to the GPU as tlas_anchor; the shadow mask pass composes each ray's origin into this frame, and the dynamic TLAS places its entries in the same frame, so one ray is traced against both (the shadow mask pass, One ray).

ADR 0014's precision bar for a drawn point near the camera is 0.043 mm; its 100 km check renders every Reference scene that has a Golden shifted 100 km from the World origin, shadows included, and requires the Golden.

4 · StaticTlas::update · Spare

Two TLASes and a worker

wgpu 30 cannot update a TLAS in place, so every change is a full rebuild, whose CPU cost a worker thread takes: rays trace the bound TLAS while the worker applies the changes the other lacks and records its build, the main thread submits it, and the frame after binds it. Each frame's changes are one shared batch that both TLASes take, so neither ever copies the other.

/// What a static TLAS's update did on the main thread's behalf.
#[derive(Clone, Copy, Debug, Default, PartialEq)]
pub struct StaticTlasUpdate {
    /// The worker's time on the build the update submitted: taking the
    /// entry changes, recording and finishing.
    pub build_time: Option<Duration>,
    /// When the update bound a newly built TLAS, the frames since the
    /// earliest change it brings: how long a newly loaded Chunk's Instances
    /// waited to be traced.
    pub frames_until_traced: Option<u32>,
}
/// The TLAS that is not bound.
enum Spare {
    /// On the main thread.
    Idle(Counted<wgpu::Tlas>),
    /// On the worker, which takes the entry changes it lacks and records its
    /// build when `built_from` is set: the frame of the earliest change the
    /// bound TLAS lacks.
    Working {
        worker: std::thread::JoinHandle<Work>,
        built_from: Option<u64>,
    },
    /// Its build submitted, bound from the next frame.
    Submitted {
        tlas: Counted<wgpu::Tlas>,
        built_from: u64,
    },
}

/// What the worker hands back.
struct Work {
    tlas: Counted<wgpu::Tlas>,
    build: Option<wgpu::CommandBuffer>,
    time: Duration,
}

/// The entry changes of one frame.
struct ChangeBatch {
    frame: u64,
    changes: Arc<Vec<EntryChange>>,
}

struct EntryChange {
    entry: u32,
    instance: Option<wgpu::TlasInstance>,
}

/// Takes `frame`'s Instance writes, each static one's BLAS from
/// `mesh_pool`; binds the spare if its build was submitted in the
/// frame before; collects the worker's result, submitting its build
/// through `queue`; and hands the idle spare to a new worker on
/// `device` when either TLAS lacks a change. With `wait`, it waits for
/// that worker, so no frame depends on the worker's timing.
pub fn update(
    &mut self,
    frame: &FrameData,
    mesh_pool: &MeshPool,
    device: &wgpu::Device,
    queue: &wgpu::Queue,
    wait: bool,
) -> StaticTlasUpdate {
    self.frame += 1;
    let changes = self.entry_changes(frame, mesh_pool);
    if !changes.is_empty() {
        let changes = Arc::new(changes);
        for behind in &mut self.behind {
            behind.push(ChangeBatch {
                frame: self.frame,
                changes: changes.clone(),
            });
        }
    }
    let mut update = StaticTlasUpdate::default();
    if let Some(Spare::Submitted { .. }) = self.spare {
        let Some(Spare::Submitted { tlas, built_from }) = self.spare.take() else {
            unreachable!("matched")
        };
        let unbound = std::mem::replace(&mut self.bound, tlas);
        self.bound_index = 1 - self.bound_index;
        self.spare = Some(Spare::Idle(unbound));
        update.frames_until_traced = Some((self.frame - built_from) as u32);
    }
    loop {
        self.collect(queue, wait, &mut update);
        if !self.start(device) || !wait {
            break;
        }
    }
    update
}

StaticTlas::update, src/render/acceleration_structures.rs.

A frame's entry changes go, as one Arc, into behind for both TLASes, tagged with the frame. The bound TLAS's list is what its last build lacked; the spare's, what its entries lack. A spare whose build the frame before submitted is bound first, by swapping it with the bound one, and the update reports the frames since the earliest change the build brought. Then it collects the worker's result and starts the next job; with wait it goes round again, so a job it starts is collected in the same frame.

/// Hands the idle spare to a worker on `device` when its entries lack a
/// change or the bound TLAS's build does, the worker recording a build
/// in the latter case. Returns whether it did.
fn start(&mut self, device: &wgpu::Device) -> bool {
    let spare_index = 1 - self.bound_index;
    let built_from = self.behind[self.bound_index]
        .first()
        .map(|batch| batch.frame);
    if !matches!(self.spare, Some(Spare::Idle(_)))
        || (self.behind[spare_index].is_empty() && built_from.is_none())
    {
        return false;
    }
    let Some(Spare::Idle(mut tlas)) = self.spare.take() else {
        unreachable!("matched")
    };
    let batches = std::mem::take(&mut self.behind[spare_index]);
    let device = built_from.map(|_| device.clone());
    let worker = std::thread::Builder::new()
        .name("Static TLAS Worker".to_string())
        .spawn(move || {
            let started = Instant::now();
            for change in batches.iter().flat_map(|batch| batch.changes.iter()) {
                *tlas
                    .get_mut_single(change.entry as usize)
                    .expect("entries are taken under its capacity") = change.instance.clone();
            }
            drop(batches);
            let build = device.map(|device| {
                let mut encoder =
                    device.create_command_encoder(&wgpu::CommandEncoderDescriptor {
                        label: Some("Static TLAS Encoder"),
                    });
                encoder
                    .build_acceleration_structures(std::iter::empty(), std::iter::once(&*tlas));
                encoder.finish()
            });
            Work {
                tlas,
                build,
                time: started.elapsed(),
            }
        })
        .expect("the OS starts a thread");
    self.spare = Some(Spare::Working { worker, built_from });
    true
}
/// Takes the worker's result, with `wait` waiting for it, else once it
/// is done, and submits its build through `queue`.
fn collect(&mut self, queue: &wgpu::Queue, wait: bool, update: &mut StaticTlasUpdate) {
    let Some(Spare::Working { worker, .. }) = &self.spare else {
        return;
    };
    if !wait && !worker.is_finished() {
        return;
    }
    let Some(Spare::Working { worker, built_from }) = self.spare.take() else {
        unreachable!("matched")
    };
    let work = worker
        .join()
        .unwrap_or_else(|panic| std::panic::resume_unwind(panic));
    self.spare = Some(match (work.build, built_from) {
        (Some(build), Some(built_from)) => {
            queue.submit(std::iter::once(build));
            update.build_time = Some(work.time);
            Spare::Submitted {
                tlas: work.tlas,
                built_from,
            }
        }
        _ => Spare::Idle(work.tlas),
    });
}

StaticTlas::start and StaticTlas::collect, src/render/acceleration_structures.rs.

A job starts only on an idle spare, when its entries lack a change or the bound TLAS lacks one. The worker, a thread spawned for the job, applies every batch the spare lacks, oldest first, so an entry changed twice ends as its last change says, and drops its share of the batches. It records a build only when the bound TLAS lacks a change: built_from, the frame of the earliest change the bound TLAS lacks, is then set, and the job's Work carries a finished command buffer. CommandEncoder and Tlas are Send, so the worker records and finishes, and only the main thread submits, as ADR 0016 rules. Once the worker is done, or at once with wait, collect joins it, submits a build through the queue and reports the worker's time; a job without one, a catch-up, returns the spare to idle. A panic on the worker resumes on the main thread.

Any write of a static Instance is a change, whether or not its data changed. The catch-up keeps both TLASes' entries level without a second build: the unbound one builds only when a later change finds the bound one lacking, from entries that by then hold everything. Captures set the wait_for_static_tlas Render switch, so which frame binds a build never depends on the worker's timing; off, as it ships and as the bench runs, the frame never waits.

5 · RenderCapacities

Capacity and what it leaves out

The capacity is fixed at device creation, derived from the acceleration structures' GPU memory Budget, and every rebuild walks all of it, filled or not, so it is no larger than that Budget gives at a KiB per entry. It caps how many static Instances it holds, whatever their slots: one written while every entry is filled casts no shadow until another frees one, and is counted and warned about.

/// Bytes of the acceleration structures' Budget per static TLAS entry.
const ACCELERATION_STRUCTURE_BYTES_PER_STATIC_TLAS_INSTANCE: u64 = 1 << 10;

/// What the Instance buffer, the light buffer and the static TLAS hold,
/// derived from the GPU memory Budgets at device creation, which assembles
/// the shader modules with them: each the largest power of two of entries
/// its kind's Budget gives at a fixed number of bytes per entry, the Instance
/// slots in whole scan blocks. The bytes per entry keep the capacities the
/// checked-in Budgets gave before; the Budget split sets them (ADR 0013).
#[derive(Clone, Copy, Debug, PartialEq)]
pub struct RenderCapacities {
    /// Slots the Instance buffer holds.
    pub instances: u32,
    /// Lights the light buffer holds, directional and point lights together.
    pub lights: u32,
    /// Static Instances the static TLAS holds, whatever their slots: one
    /// past them is left out, so it casts no shadow, and is counted and
    /// warned about. In wgpu a TLAS rebuild's CPU time grows with its
    /// capacity, filled or not.
    pub static_tlas_instances: u32,
}

The checked-in Budget for acceleration structures, acceleration_structures in bench/budgets.json, is 268,435,456 bytes: an entry per KiB of it is 218 = 262,144 entries, already a power of two. In wgpu 30 a TLAS holds one optional entry per place of its capacity from its creation, and recording a build maps every one of them, filled or not, into what wgpu-core builds from; wgpu-core sizes the structure and its buffer of entries by capacity too. As tlas_bytes gives it on the M4 Pro, each of its two TLASes takes 75,597,888 of those bytes, 151,195,776 together, the rest left to the BLASes and the dynamic TLAS. town's 254,319 Instances, as tests/frame_stats.rs counts them, are 244,319 static ones and 10,000 Moving ones, so its static Instances fill all but 17,825 entries.

A static Instance written while every entry is filled joins the left-out set, keyed by its slot; a later write to that slot replaces or, with no BLAS, removes it, and an entry freed in a later frame admits the lowest slot's. Frame stats read the set's size as static_instances_left_out, shown on the counts line, so it counts only Instances refused for want of an entry. The frame whose update takes the set from empty to holding one warns once, "Static Instances left out of the static TLAS: it is full, so they cast no shadow", with the count and the capacity; the next warning waits until the set has emptied and filled again.

9 · ADRs 0013, 0014, 0016, 0020

Why this way

Two TLAS, split by motion. ADR 0020 splits the near field into a static TLAS, rebuilt only when its static Instances change, and a dynamic TLAS of Moving Instances, rebuilt each frame and capped at 10,000 Instances. One TLAS over everything would rebuild over every static Instance whenever anything moved, since wgpu-core 30.0.1 has no TLAS update, only rebuilds.

A worker records, the main thread submits. Rebuilding town's 254,256 Instances took 17.5 to 18.1 ms of CPU on the M4 Pro under wgpu 30.0.1, and an empty TLAS of 262,144 entries 4.3 to 6.9 ms (docs/research/acceleration-structures-for-streamed-worlds.md). A worker can fill, record and finish, 13 to 14 ms of it, and hand the command buffer over, as ADR 0016 lets workers do; the main thread keeps the submit, 4.3 to 4.5 ms at that size alone and 5.6 to 7.1 ms beside a frame's, since wgpu-core walks one dependency per entry. Recording the build in a command buffer of its own on the main thread (the research's option A) overlaps it on the GPU but leaves the whole CPU cost in the frame; several smaller static TLASes, by Chunk group or ring (option C), make each rebuild cheap, but every ray then queries each of them, at a cost not yet measured, and on Metal each is a binding of its own.

A spare, swapped in. A bind group holds its TLAS from creation, so two TLASes take two groups, and the worker builds the one no frame binds; rebuilding the bound TLAS in place (S2) would put the build in the frame that traces it and leave ordering its build after the passes that read it to Metal's hazard tracking. The spare costs a second TLAS's memory, 75.6 MB at 262,144 entries on the M4 Pro. Ize, Wald and Parker switch a BVH rebuilt over several frames in "with two pointer swaps"; the research found no shipped engine that double-buffers its TLAS. Sharing each frame's changes between the two keeps the main thread's work in proportion to the changes, not to the capacity, and the catch-up keeps the second build a change would otherwise cost.

Captures wait, frames do not. Which frame finds the worker done depends on the machine, so a capture, whose image must not, waits for the worker in the frame that starts it and binds the build in the next. Frames in a window and the bench never wait.

Tagged with the slot, indexed by none. Indexing entries by slot would need no map, as an Instance keeps its slot while it is one, but it would cap slot numbers rather than static Instances: Chunks take their ranges past the highest slot taken, and the Instance buffer holds twice the static TLAS's capacity, so a Chunk's static Instances could fall past the capacity with entries to spare. A table of entries by slot keeps the old cost, one array read per Instance written, Moving ones included, for 8 bytes of CPU memory per slot up to the highest that held a static Instance; a hash map would cost a hash per Moving Instance each frame, 10,000 of them in town. The tag stays the slot: the frame's shaders do not read it, and a test's query reads it back to name the Instance a ray hit.

Anchored at load, never re-anchored. ADR 0014 forbids f32 World positions on the GPU and names ray-tracing acceleration structures among the subsystems that convert into a local frame they own; ADR 0020 anchors this one at scene load and never re-anchors it until re-anchoring is decided with Chunk streaming. Measured from that corner, a scene's entries round to f32 as near ones do, so the 100 km check holds for shadows.

A capacity sized from its Budget. Every rebuild walks the full capacity, filled or not, so a larger one costs every static spawn in every scene. ADR 0013 splits the 8 GB GPU memory Budget into a Budget per kind, and the capacity takes an entry per KiB of the acceleration structures', which gives 218, enough for town; the KiB per entry is provisional until the split sets it.

A CPU wait before the build, at load. Nothing on the GPU orders the build after the compaction copies of the BLASes it reads, so compact_blases waits for them on the main thread, which alone submits and polls under ADR 0016. A wait once, at load, costs one frame; the per-frame refit, which could not pay that every frame, orders its writes on the GPU instead (the BLAS refit).

10

Limits

A CPU wait in each frame that loads Meshes. Before its update, the upload waits on the main thread for the GPU to build and then to compact the frame's new BLASes, since wgpu-core 30.0.1 records no barrier after a compaction copy on any backend and wgpu-hal 30.0.1 records none on Metal. A Mesh whose BLAS lost that race would cast no shadow until the next rebuild, which, where nothing static changes, never comes. Today every Mesh loads before the first frame, so the first frame alone waits; Meshes streamed during play would make every load frame wait, until a wgpu release orders the copy on every backend, a version change that is the owner's call.

A build lands a frame or more after its change. A change is traced from the frame after the build that brings it is submitted, and a change made while a build or a catch-up is on the worker waits for it to come back first. frames_until_traced counts the wait.

A rebuild walks every entry. Spawning or despawning one static Instance costs a full rebuild at 218 entries, on the worker, and a submit of all of them on the main thread.

The unbound TLAS is rebuilt after frames that read it. Frames still on the GPU may trace the TLAS just unbound when its next build is submitted; queue order and Metal's hazard tracking order the two, as they ordered an in-place rebuild before.

Changes held for the catch-up. The TLAS just unbound keeps its share of the change batches until its catch-up has taken them, so a load's changes stay in CPU memory for a frame or more after its build.

A lock shared with the main thread. finish holds the device's snatch lock for reading, which a buffer or texture destroy, a poll that frees what one left, and a surface's present or discard take for writing, so such a call on the main thread can wait for the worker's whole finish.

Left out by write order. Past the capacity, which static Instances cast shadows is settled by when they were written, the left-out ones admitted lowest slot first, not by their distance from the camera.

Memory at full capacity, twice. The estimate, and wgpu-core's allocation, are for every entry of both TLASes, so the smallest scene pays what town does.

One frame, fixed at load. The origin never moves, so an entry far from where the camera stood at load rounds to f32 more coarsely: from 2,048 m out its step is 0.244 mm.

A pinned wgpu. No update in place and no barrier after compaction are wgpu 30.0.1's; each holds while the pin does.

History

The static TLAS arrived on 2026-10-20, together with the BLAS per Mesh, anchored at load and rebuilt only when a static Instance changes; its first build in every scene, empty or not, came when the orrery, whose bodies all move, showed it could stay unbuilt. Shadow rays then came to read it, and the dynamic TLAS took the Moving Instances beside it. On 2026-10-23 a test that sometimes missed a triangle showed the build could read a BLAS whose compaction had not finished, and the upload has waited for the copies since. On 2026-11-07 its entries stopped being the slots below its capacity, once Chunks took ranges of slots past the highest taken. On 2026-11-08 its build moved off the frame's critical path: a second TLAS, built on a worker thread and bound the frame after the main thread submits it, while rays trace the first; captures wait for the worker so their images do not depend on its timing. The race and its routes are on Waiting on the GPU; The Reference scenes describes the scene whose Instances the capacity was sized for. This page describes the mechanism as it is.
