The Bench history

Every bench run kept as a Bench record on the orphan bench-history branch, a JSON file at a path that is its key, the source hash of the paths that can change a measurement, the adapter, the backend and the scene; the clean, release-profile, quiet runs of main's source form each machine's Series, which every publish rebuilds and marks its Suspects on, a page draws, and a nightly sweep re-benches, bisects and files as Regressions.

Describes main at 075919da (2026-11-05). A change to what a Bench record holds, to where one lands, to how a Series is judged or to what the sweep does rewrites this page and moves the commit; nothing is appended. Read first: The bench for what a run measures and how the Baselines gate, Frame stats for the metrics a record holds.

Interface

Runs
After a bench, never during a frame. praxis bench publishes its results as it ends unless given --no-publish; praxis publish <directory> publishes results later; with --experiment <name> either publishes them as that Experiment's. CI's publish-bench job publishes lavapipe's records and the release build's on every push to main; a pull request's run publishes nothing. The sweep, scripts/sweep.sh, runs at 04:00 on the Apple M4 Pro and the RTX 2070 SUPER: praxis history import, history unrecorded, fetch and cook, preflight, history bisect before each re-bench, history publish-night after the last, history regressions, then the benches unrecorded named.
Key
Source hash × adapter × backend × scene, as the path records/<adapter>-<backend>/<scene>/<source hash>.json. The source hash is the git tree of src, assets, Cargo.toml, Cargo.lock and .cargo alone, so a commit that changes none of them has its parent's. The Harness version is defined under src/, so a source hash names one; the record holds it.
Reads
The bench's results, one Measurements JSON per scene with its Provenance; the remote's main, fetched, for its source hash and each commit's time; the remote's bench-history tip, fetched into a worktree of its own. The sweep reads the Series rows and the Verdicts; the import reads every Baseline each first-parent commit of main changed.
Writes
On the branch, in one commit per publish: records/ (on a Series), tagged/ (every other record, with its tags), experiments/<name>/, records/<adapter>-<backend>/release-build/ (CI's release build), series/ (one file per Series, every one rebuilt by every publish), verdicts/ (the sweep's) and README.md. Never anything on main: the Baselines in bench/baselines/ stay chosen by hand.
Drawn
gariasf.github.io/praxis/bench/, the page docs/bench/index.html, which lists the branch through GitHub's API and reads its Series, records and Budgets raw in the browser.
Counted
Nothing in Frame stats: the history keeps what the bench measured. A publish prints what it did, a Publication: records on a Series, tagged, in an Experiment, dropped, re-stamped, and the commit pushed.
Where in the code

The record and its key

A record is the bench's own result file, stamped with when its commit was made and with the reasons it is kept off a Series, at a path that is its key: the source it measured, not the commit. Two commits that differ only outside the measured paths share one record, and a path that exists is a duplicate.

src/bench/provenance.rs

/// The source hash of `revision` in `repository`: the git tree holding
/// only its measured paths, so a commit that changes none of them has its
/// parent's.
pub fn source_hash(repository: &Path, revision: &str) -> anyhow::Result<String> {
    let listing = git(
        repository,
        &[
            &["ls-tree", "--full-tree", revision, "--"][..],
            &MEASURED_PATHS[..],
        ]
        .concat(),
        None,
    )?;
    // An empty tree is no input at all: mktree refuses a blank line.
    let entries = if listing.is_empty() {
        listing
    } else {
        listing + "\n"
    };
    git(repository, &["mktree"], Some(&entries))
}

The source hash is a git tree written from the five measured paths' entries at a revision, so it is a 40-digit hash git itself can list. A checkout whose measured paths differ from its commit, untracked files included, hashes its working tree instead, through a temporary index (Checkout::read, working_tree), and is marked dirty. A test in the same file classifies every tracked top-level path as measured or as one of the twelve UNMEASURED_PATHS, so a new top-level directory fails the build until someone says which it is.

Publishing

A publish turns each result into a record, tags it with every reason it is off a Series, writes the records into a worktree of the branch, rebuilds every Series file and pushes one commit. A publish that fails warns and fails no bench; verify never publishes.

src/bench/history.rs
pub fn publish(
    repository: &Path,
    results: &[Measurements],
    release_build: Option<ReleaseBuild>,
) -> anyhow::Result<Publication> {
    let root = git(repository, &["rev-parse", "--show-toplevel"], None)?;
    let repository = Path::new(&root);
    let main = fetch_main(repository)?;
    let main_source_hash = source_hash(repository, &main)?;
    let release_build = release_build
        .map(|build| release_build_record(repository, results, build, &main, &main_source_hash))
        .transpose()?;
    let records: Vec<BenchRecord> =
        bench_records(repository, results, &main, &main_source_hash, None)
            .chain(release_build)
            .collect();
    push_records(repository, &records)
}

fetch_main fetches the remote's main into its remote-tracking ref, so the publish judges against the main everyone shares, not the checkout's. bench_records turns each result into a record through record, skipping with a warning one that has no provenance, which a run outside a git checkout lacks. Each record's tags come from the checkout and the run:

src/bench/history.rs
/// Every reason a record is kept off a Series: a dirty tree, a source other
/// than `main`'s, and for a `run` a profile other than release, a machine
/// that was not quiet, and a size and frame count other than its Series'
/// configuration. lavapipe's Series read counters only, which load cannot
/// change, at the configuration CI benches.
fn tags(dirty: bool, mains_source: bool, run: Option<Run>) -> Vec<String> {
    let mut tags = vec![
        (dirty, "dirty tree".to_owned()),
        (!mains_source, "source not main's".to_owned()),
    ];
    if let Some(Run {
        adapter,
        profile,
        quiet,
        width,
        height,
        measured_frames,
    }) = run
    {
        let lavapipe = is_lavapipe(adapter);
        let (configuration, configuration_name) = if lavapipe {
            (Configuration::CI_COUNTERS, "CI's configuration")
        } else {
            (Configuration::REFERENCE, "the reference configuration")
        };
        tags.extend([
            (profile != "release", format!("{profile} profile")),
            (!lavapipe && !quiet, "machine not quiet".to_owned()),
            (
                (width, height, measured_frames)
                    != (
                        configuration.width,
                        configuration.height,
                        configuration.measured_frames,
                    ),
                format!("{width}x{height} over {measured_frames} frames, not {configuration_name}"),
            ),
        ]);
    }
    tags.into_iter()
        .filter_map(|(applies, tag)| applies.then_some(tag))
        .collect()
}

A checkout holds main's source when its source hash is main's or its commit is an ancestor of main (mains_source), so a session that benches a commit of main behind the tip still lands on the Series. Whether the machine was quiet is decided by the bench, before the publish, in Provenance:

fn is_quiet(
    gpu_load_percent: Option<u32>,
    one_minute_load_average: Option<f64>,
    other_processes: Option<&[String]>,
    machine_warnings: &[String],
    gpu_frame_p95_over_median: Option<f64>,

        && one_minute_load_average.is_none_or(|load| load <= BUSY_LOAD_AVERAGE)
        && other_processes.is_none_or(<[String]>::is_empty)
        && machine_warnings.is_empty()
        && gpu_frame_p95_over_median.is_some_and(|ratio| ratio < QUIET_P95_OVER_MEDIAN)
}

The load figures are read once, before the first scene, since a reading right after a scene would include that scene's own work; BUSY_GPU_PERCENT is 10 and BUSY_LOAD_AVERAGE 2.0, preflight's thresholds (src/preflight/mod.rs). A load that could not be read is a preflight note, not a warning, so it passes; a GPU frame spread that could not be computed, from a zero median, does not. lavapipe is the exception: its times measure a shared runner's CPU, its Series read counters, binary size and build time, which load cannot change or moves whatever the test says, so its records join the Series from CI's configuration quiet or not, and the first under a key stays.

A publish to an Experiment takes the same records and moves each into a directory of the Experiment's name, with its merge base with main and that commit's source hash, which is the Series record the page compares it with. An Experiment's records join no Series, main's own clean, quiet source included.

/// Fails unless `name` can name an Experiment: one directory on the branch,
/// of ASCII letters, digits, `-` and `_`.
pub fn check_experiment_name(name: &str) -> anyhow::Result<()> {
    anyhow::ensure!(
        !name.is_empty()
            && name
                .chars()
                .all(|character| character.is_ascii_alphanumeric() || "-_".contains(character)),
        "an Experiment's name is ASCII letters, digits, `-` and `_`, not {name:?}"
    );
    Ok(())
}

The binary checks the name before it benches, so a bad name fails before any GPU work (src/bin/praxis.rs); --experiment takes no --no-publish, as it exists to publish, and no --release-build-seconds, as a release build publishes beside main's results only. The records are written through a detached worktree of the branch in a temporary directory, removed on drop, so the checkout's own index and branches stay as they are; with no branch on the remote yet, the worktree starts from an empty tree and the first commit is an orphan.

src/bench/history.rs
/// How many times a publish pushes: each attempt after the first rebuilds
/// its commit on the branch's new tip, as another publish pushed first.
const PUSH_ATTEMPTS: u32 = 5;
…
fn push(
    repository: &Path,
    message: &str,
    write: impl Fn(&Worktree) -> anyhow::Result<Publication>,
) -> anyhow::Result<Publication> {
    let mut attempt = 1;
    let mut tip = remote_tip(repository)?;
    loop {
        let worktree = Worktree::add(repository, tip.as_deref())?;
        let mut publication = write(&worktree)?;
        publication.commit = worktree.commit(tip.as_deref(), message)?;
        let Some(commit) = &publication.commit else {
            return Ok(publication);
        };
        let pushed = git(
            repository,
            &[
                "push",
                "--quiet",
                REMOTE,
                &format!("{commit}:refs/heads/{BRANCH}"),
            ],
            None,
        );
        let Err(error) = pushed else {
            return Ok(publication);
        };
        // Only a tip that moved since the fetch is a race worth another try.
        let current = remote_tip(repository)?;
        if current == tip || attempt == PUSH_ATTEMPTS {
            return Err(error);
        }
        tracing::info!(
            attempt,
            "bench-history moved; publishing again on its new tip"
        );
        tip = current;
        attempt += 1;
    }
}

Two machines publishing at once race to push; the loser fetches the new tip and writes its records again on it, up to PUSH_ATTEMPTS times, so both land in their own commits. A commit whose tree equals the tip's is not made, and the publish reports nothing changed. The commit message names the adapters: Publish 11 Bench records from apple-m4-pro-metal. CI's release build

CI benches lavapipe in its configuration on every run that changes the engine and, on a push to main only, publishes those results together with the release build whose binary measured them. The Series

A Series file is derived data: one row per record in its records/ directory, in the order their commits were made, holding each record's metrics without the rest of its provenance, with the Suspect marks computed over the whole Series. Every publish rebuilds every Series, so rows always take the form the publishing binary writes, whichever bench wrote the records.

src/bench/history.rs
/// One Series file's row: a record's source and its metrics, without the

Suspects

A record is a Suspect on a timing when its median sits outside the median of up to 8 records before it on its line, ± the larger of 4 median absolute deviations of those medians and 3% of their median. A step is flagged where it starts and not again while the window lags it; a lone outlier is flagged once and outvoted after.

src/bench/history/suspects.rs
/// How many records before a record judge it.
const WINDOW_RECORDS: usize = 8;

/// The fewest records before a record that judge it; with fewer, as at the
/// start of a line, it is not judged.
const FEWEST_JUDGING_RECORDS: usize = 3;

/// How many median absolute deviations of its window a median may sit from
/// the window's median before it is a suspect.
const MEDIAN_ABSOLUTE_DEVIATIONS: f64 = 4.0;

/// The smallest shift that makes a suspect, as a share of the window's
/// median, so that a window of near-equal medians does not flag noise.
const SMALLEST_SHIFT_FRACTION: f64 = 0.03;

pub(super) fn suspects(points: &[Point]) -> Vec<Option<f64>> {
    let mut line = Vec::new();
    let mut step: Option<Step> = None;
    points
        .iter()
        .map(|point| {
            if point.starts_line {
                line.clear();
                step = None;
            }
            let median = point.median?;
            let position = line.len();
            let window = &line[position.saturating_sub(WINDOW_RECORDS)..];
            let band = band(window);
            line.push(median);
            let (center, tolerance) = band?;
            if (median - center).abs() <= tolerance {
                return None;
            }
            let slower = median > center;
            let continues = step.as_ref().is_some_and(|step| {
                position - step.position <= WINDOW_RECORDS
                    && step.slower == slower
                    && (median - step.median).abs() <= step.tolerance
            });
            if continues {
                return None;
            }
            step = Some(Step {
                position,
                slower,
                median,
                tolerance,
            });
            Some((median - center) / center)
        })
        .collect()
}

/// `window`'s median and how far from it a median may lie, when it holds
/// enough records to judge.
fn band(window: &[f64]) -> Option<(f64, f64)> {
    if window.len() < FEWEST_JUDGING_RECORDS {
        return None;
    }
    let center = percentile(window.to_vec(), 0.5);
    let deviation = percentile(
        window.iter().map(|value| (value - center).abs()).collect(),
        0.5,
    );
    Some((
        center,
        (MEDIAN_ABSOLUTE_DEVIATIONS * deviation).max(SMALLEST_SHIFT_FRACTION * center),
    ))
}

The window holds the medians of up to WINDOW_RECORDS records before the point on its line, a record that did not measure the timing contributing nothing, and judges only once it holds FEWEST_JUDGING_RECORDS; the first three records of every line are not judged. The centre and the deviation are the bench's own percentile, a nearest-rank median, so for a window of even length the centre is the lower of the two middle values. The band is the median and the median absolute deviation rather than the mean and the standard deviation because one far record moves neither: half the window must change before the median does. The floor of SMALLEST_SHIFT_FRACTION keeps a window of near-equal medians, whose deviation is nearly zero, from flagging a wobble as a step.

After a real step the window's median lags until five of its eight records are at the new level, so the next records would also lie outside; a point that continues a flagged step among the 8 before it, on the same side and within that Suspect's tolerance of its median, is not flagged again, even after a noisy record between them fell back inside the band. A second step on the same side, past the first's tolerance, is flagged again. The shift kept is the point's distance from the centre as a share of it, negative for a faster record; a row's suspects map holds one per judged timing. Faster records are marked too; only slower ones go to the sweep.

pub(super) fn filing(verdict: &Verdict, verdicts: &[Verdict]) -> Filing {
    let Some(pinned) = &verdict.pinned else {
        return Filing::Done;
    };
    if pinned.covered_by_baseline || verdict.issue.is_some() {
        return Filing::Done;
    }
    verdicts
        .iter()
        .filter(|other| other.scene == verdict.scene)
        .filter(|other| {
            other.pinned.as_ref().map(|pinned| &pinned.commit.commit) == Some(&pinned.commit.commit)
        })
        .find_map(|other| other.issue)
        .map_or(Filing::Open, Filing::Shared)
}

The page

The page is one HTML file on GitHub Pages that reads the branch in the browser: the tree listing through GitHub's API, each Series file raw, tagged and Experiment records raw and only on request, the Budgets from main, and the subjects of main's latest commits. It computes nothing a publish already did: it draws the rows, reads their Suspect marks, and judges the Budgets as praxis compare would.

The page's script lives under docs/, outside the tree the guides' checks index, so its names are written plain here; the file names each in the order below.

Its start fetches the branch's recursive tree listing, the Budgets file bench/budgets.json from main and the closed milestones, reads the machines, scenes and Experiment names from the paths it finds, then loads every machine's Series of every scene and of the release build at once, each machine's display name from one of its records (the adapter's name becomes M4 Pro · Metal, lavapipe's lavapipe) and the subjects and PR numbers of main's latest 100 commits, so a point names its change without a request of its own. A fetch that fails names its status, or, when GitHub's unauthenticated rate limit is used up, the time it resets. The M4 Pro opens the page when it has a Series, town the scene; the URL's machine, scene and experiment parameters pick others, and the page writes them back as the picks change.

A Series' rows become points in source order, by commit time then commit, each knowing the point before it, its segment, and what broke the line at it. The page's test of whether two rows measure the same thing is the twin of SeriesRow::same_definition (section 3): one Harness version, and one scene content hash where both know it; the break is labelled with the later Harness version or scene content. A chart draws a line per segment and labels the break; a change across one is shown uncoloured, as it compares two definitions. Tagged records are fetched raw, one request each, only with the Tagged records box ticked, and turned into rows the way a publish would, the GPU frame read under its first name too; where the machine has a Series, a tagged point's change is from the Series record before it.

An Experiment is picked by name, its records fetched raw, and each compared with the Series record whose source hash is its merge base's, on the same machine: a branch's change is measured against the main it started from. With no such record, the table says so and names the merge base, since the sweep benches main's sources and that commit can be benched by hand. The Experiment table lists each record's machine, commit, base, GPU and CPU frame with their change from the base, how many counters changed and its tags, less source not main's, which every Experiment record carries; a change across a break says which definition differs instead.

A Suspect's mark is read from its row, never recomputed, and only a Series point has one; a chart rings it, and the record view states the timing and the shift as a percentage of the median before it. Budgets are judged for the M4 Pro alone, at the newest Harness version its Series hold, against the six Budgets praxis compare checks: the CPU frame, the GPU frame, the gate, the dynamic TLAS's CPU time and its build pass, and the GPU memory of the measured frames. A timing's change is coloured by praxis compare's rule, with the page's own copies of WARN_RATIO, 1.05, and FAIL_RATIO, 1.10, and noise floors of 10 µs for a CPU timing and 20 µs for a GPU one: a fail past the fail ratio and the floor, a warning past the warn ratio, better when it shrank by more than a warning's share, else flat and grey. Each scene's standing is its latest record's change from the record before it and from the median of up to 8 records before it, both within the latest's segment; this median averages the two middle values of an even count, a summary for the eye, where the Suspect rule's nearest-rank median does not.

10 · ADRs 0024, 0013

Why this way

Records in git, not a hosted service. ADR 0024 considered Bencher.dev, whose change detection and charts come ready-made, and rejected it: the history would move outside the repository, behind an account and a token every machine and CI would hold, and the key, the quiet rule and the Harness version breaks would still have to be layered on top. On an orphan branch, an agent queries the history with git and jq, and a bad publish is undone with git revert.

Not github-action-benchmark. It charts results on a gh-pages branch from Actions, so only CI could publish, and CI has no GPU: lavapipe's timings mean nothing. The key, the quiet rule and the breaks would again be the engine's to add.

Not a time-series database. Grafana over a database is a server to run and back up for a few kilobytes a record, and agents could no longer read the history with git and jq.

The source hash, not the commit or the tree. PR branches need not be up to date with main, and merges are squashed, so a PR head's commit never lands on main; a docs-only commit gets a new tree, and the sweep would bench it for nothing. A hash over the five paths that can change a measurement lets a docs commit inherit the record before it, and lets a PR's clean, up-to-date run share a key with its squashed merge. The Harness version was first part of the key and then left to the record, since it is defined under src/ and a source hash already names one.

No self-hosted runners. Runners on the two machines would let CI bench real GPUs, but GitHub's own guidance is that self-hosted runners should almost never be used for public repositories, because any user can open a pull request against the repository and compromise the environment. A local scheduled task runs no code from a pull request; it runs main, and only after the machine's own preflight passes.

The history observes and never gates. ADR 0013's Baselines in bench/baselines/ on main, chosen by hand, are what verify and compare judge against, and what CI fails on; the history keeps every run beside them so a drift or a step between two Baselines can be seen. A failed publish warns and the bench still succeeds; verify never publishes; a Suspect is a candidate until a night re-benches it, so no mark blocks anything, and a Regression becomes a needs-triage issue for a person to judge, not a failed check.

Quiet, and only quiet, on a Series. A GPU median moves with whatever else the machine runs, so a record from a loaded machine would read as a step. Preflight's checks at the run's start and the run's own GPU frame spread tag such a record, which is kept and drawn on request, and when two runs share a key the quieter stays, so a noisy evening cannot displace a quiet night. lavapipe's Series read what load cannot change, so its first record stays.

Breaks, so a new ruler never reads as a Regression. A change to how a metric is measured raises the Harness version, and a scene given new content hashes differently; a chart's line breaks at either and the Suspect rule starts a new line, so nothing is judged across them. An imported or re-recorded Baseline and a pinned commit start a line too: each is a level someone accepted or the sweep explained.

11

Limits

Steps, not slopes. A timing that grows a little every record never leaves a band that follows it; the rule finds steps.

A step right after an outlier on the same side. If the outlier sits within the step's tolerance of it, the step reads as continuing the outlier, which takes the mark; the night re-benches the outlier's commit, and a cleared Verdict does not re-judge the step.

The first three records of a line. They are not judged, so a step at the second record after a Harness version, a new scene content, a Baseline or a pinned commit goes unmarked.

One Suspect a night, one machine's Verdicts. Each machine judges its own Series, from release binaries it builds itself; the RTX 2070 SUPER's task runs only while the owner is logged on, and the M4 Pro's gh must be logged in for an issue to open. The oldest unjudged Suspect goes first, so a backlog of Suspects takes as many nights.

What the quiet test cannot see. It reads the load once before the first scene, so load that arrives mid-run is caught only by the GPU frame spread; a CPU frame spread is not judged. An imported Baseline is quiet unless its own GPU frame spread says otherwise.

Lines pinned by a Verdict are not visible on the page. The page breaks a line at a Harness version or scene content only; a line start at a pinned commit, a Baseline or a re-recorded Baseline shows only through the Suspect marks the publish wrote.

The page depends on GitHub's API. Its tree listing is capped, and the page says so when it was cut short; its unauthenticated rate limit stops the page for an address that has used it up until the reset; the PR lookup of an Experiment's unpushed commit fails.

Old records hold less. A metric added after a record was made is null in its row and absent from its tooltip; a release build's record has no Harness version and is never a Suspect.

Interleaved ends on one night. A shift that holds on one night from two runs of each end is held for good; a night that then fails to show it during a bisect judges nothing, and a slow machine state on the night a commit is pinned goes into the Verdict's measured.

History

The history began as a decision to keep every bench run rather than only the Baselines a PR chose to commit: a record keyed by the source it measured, the Harness version numbered backwards over the Baselines' eras by an import, the quiet rule, the Series the page draws, and a Suspect rule over a window of medians, which the volume that first narrated it covered. The sweep's re-bench and bisect followed, with the Verdict kept on the branch and a pinned commit starting its Series' line, then the filing of a pinned Regression as one issue per scene, the nightly import of Baselines re-recorded since the history started, and the one-minute load average in the quiet test. Experiments, published from a branch under a name against the Series record of their merge base, and the release build's record CI publishes beside lavapipe's, had no volume; the key dropped the Harness version into the record, and the quieter-record rule learnt to hold a Series record against a tagged one. The Night's directory, first laid out by the sweep's script and read by the bisect, moved whole into the binary, the script keeping the builds, waits and time cap. This page describes the mechanism as it is, from the code.
