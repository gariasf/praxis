The Instance buffer

The GPU storage buffer that holds every Instance, 128 bytes in a slot per Renderable, created once at a fixed 524,288 slots and never grown, which the culling pass and the main pass's vertex stage read through one bind group built once.

Describes main at b3d764b4 (2026-11-04). A change to the Instance buffer, its slot's layout or its capacity rewrites this page and moves the commit; nothing is appended. Read first: Prepare for how a Renderable keeps its slot and which slots a frame writes, The culling pass for the pass that reads every slot.

Interface

Created
Once, in Renderer::new, at INSTANCE_CAPACITY slots of InstanceData: 67,108,864 bytes, with the STORAGE and COPY_DST usages. It never grows and is never replaced.
Written
Each frame, only the slots that Frame data's Instance writes name, a run of consecutive slots per copy, at the slot's index times 128 bytes; every other slot keeps what an earlier frame wrote (ADR 0003). The copies go through the frame's staging (Staging).
Read by
The culling pass's compute stage, in offset_slots, append_records and append_triangles; the main pass's vertex stage, in vertex_output, which the depth pre-pass, phase two's depth pass and the lit pass all run. No fragment stage reads it. The static and dynamic TLAS take the same InstanceData values from Frame data on the CPU, not from the buffer.
Bind group
Group 2, the scene geometry (SCENE_GEOMETRY): binding instances, read-only storage, array<InstanceData>, visible to the vertex and compute stages; built once in Renderer::new.
Counted
Whole, in Frame stats' gpu_memory_bytes; its writes in uploaded_bytes and instances_written; Renderables the full buffer turned away in renderables_refused.
Where in the code
src/render/instance.rs (the slot, the capacity, the anchor split); src/render/renderer.rs (creation, upload, memory); src/render/bind_groups.rs (group 2); src/render/shaders/common.wgsl (the WGSL twin); src/render/shaders/culling.wgsl and main.wgsl (the readers).

1 · InstanceData, src/render/instance.rs

One slot: what an Instance holds

A slot is one InstanceData, 128 bytes: where the Renderable is, as an integer Anchor and an f32 offset, never as one f32 position; how it is turned and scaled, with the matrix its normals need; which Mesh it draws; and which Material overrides its Mesh's, if any.

/// The Mesh reference of a freed slot's Instance, which draws nothing.
pub const NO_MESH: u32 = u32::MAX;

/// The Material ID of an Instance that overrides none of its Mesh's
/// Materials, and of a Primitive that names none.
pub const NO_MATERIAL: u32 = u32::MAX;

/// One Instance where its Transform puts it: the anchor and offset of its
/// pivot, which do not change as the camera moves, and its rotation-scale;
/// its Mesh's Handle, or `NO_MESH`; and the Material ID that overrides its
/// Mesh's Materials, or `NO_MATERIAL`.
#[repr(C)]
#[derive(Copy, Clone, bytemuck::Pod, bytemuck::Zeroable)]
pub struct InstanceData {
    pub rotation_scale: [[f32; 4]; 3],
    pub normal_matrix: [[f32; 4]; 3],
    pub anchor: [i32; 3],
    pub material_id: u32,
    pub offset: [f32; 3],
    pub mesh: u32,
}

src/render/instance.rs.

Prepare fills a slot from the Renderable's World transform, blended between its two newest Ticks where the fixed schedule moves it: the rotation-scale is its 3×3 linear part in f32, the normal matrix that part's inverse transpose, and the anchor and offset come from splitting its f64 translation (section 4). mesh is the index of the Renderable's Mesh Handle, by which the culling pass finds the Mesh in the Mesh pool's table. material_id is the Material ID of the Renderable's Material Handle, or NO_MATERIAL where it has none and each Primitive draws with its own.

WGSL gives each vec3 column of a mat3x3 16 bytes, so each matrix is 48 bytes, not 36, and Rust holds it as three 4-float columns; padded_columns writes a glam matrix that way, with each column's fourth float 0. A vec3 is 16-byte aligned but 12 bytes long, so a 4-byte scalar fits after each: material_id after the anchor, mesh after the offset. The slot has no padding of its own; every one of its 128 bytes is data but the matrices' six column pads, 24 bytes.

The WGSL twin and the test that holds them together

The shaders read the slot through a WGSL struct of the same name and fields, declared once in the common part. Nothing in the compiler links the two, so a test parses every shader module and compares the struct, field by field, with its Rust twin.

// An Instance's pivot as anchor plus offset, so camera motion changes no
// Instance, and its rotation-scale; its Mesh, or NO_MESH in a freed slot;
// and the Material ID that overrides its Mesh's, or NO_MATERIAL. Both are
// declared from Rust's (src/render/shaders/mod.rs).
struct InstanceData {
    rotation_scale: mat3x3<f32>,
    normal_matrix: mat3x3<f32>,
    anchor: vec3<i32>,
    material_id: u32,
    offset: vec3<f32>,
    mesh: u32,
}

src/render/shaders/common.wgsl.

structs_shared_with_the_cpu_match_their_rust_twins validates every module with naga, finds each struct that a uniform, storage or immediate binding holds where the CPU writes it, and matches it by name to a twin the twin! macro builds. For each field it compares the offset, the size, the scalar type and the strides, per column of a matrix, and it compares the two structs' sizes; a field Rust adds that the macro's list leaves out fails to compile, since the list builds a literal of the type. Rust fields whose names start with an underscore are padding, absent from WGSL; InstanceData has none, as its matrices carry their padding inside each column.

twin!(InstanceData {
    rotation_scale,
    normal_matrix,
    anchor,
    material_id,
    offset,
    mesh,
}),

3 · Renderer::new, src/render/renderer.rs

One buffer at a fixed size, one bind group built once

The Renderer creates the buffer once, at its whole capacity, before any Scene loads, and builds the bind group that holds it in the same function. Since the buffer is never replaced, the bind group never goes stale and nothing rebuilds it.

// Created at its fixed capacity; it never grows.
let instance_buffer = device.create_buffer(&wgpu::BufferDescriptor {
    label: Some("Instance Buffer"),
    size: u64::from(INSTANCE_CAPACITY) * std::mem::size_of::<InstanceData>() as u64,
    usage: wgpu::BufferUsages::STORAGE | wgpu::BufferUsages::COPY_DST,
    mapped_at_creation: false,
});

Renderer::new, src/render/renderer.rs.

The size is the product of two constants, so it is the same 67,108,864 bytes on every adapter and backend, at every render size and in every scene: nothing in its creation asks the adapter anything. It needs only STORAGE, since shaders read it, and COPY_DST, since the frame's uploads copy into it; nothing copies out of it.

A bind group is a snapshot of the resources it was built with. The scene geometry group holds the Instance buffer beside the vertex Arena and the Mesh pool's tables of Meshes and Meshlets, each created at a fixed capacity, so the group is built once, right after them, and the culling and main passes bind that one group at index 2 every frame.

/// Group 2, the scene geometry, built once since its buffers never grow: the
/// Instances, the vertex Arena the vertex shader pulls from (ADR 0019), and
/// the Mesh pool's tables of Meshes and Meshlets.
pub const SCENE_GEOMETRY: BindGroupDefinition = BindGroupDefinition {
    index: 2,
    label: "Scene Geometry Bind Group",
    bindings: &[
        read_only_storage(
            "instances",
            "array<InstanceData>",
            wgpu::ShaderStages::VERTEX.union(wgpu::ShaderStages::COMPUTE),
        ),
        // … the vertex Arena, the Mesh table and the Meshlet Arenas …
    ],
};

src/render/bind_groups.rs, the other bindings elided.

The definition is the binding's one statement: it declares instances in WGSL in every module assembled with group 2, the culling module and the main module, gives its layout entry, and gives the index both pipeline layouts and both passes' set_bind_group calls use.

Where a frame's writes land

Frame data lists the Instances a frame writes and groups them into runs of consecutive slots. Each run becomes one copy, at its first slot's index times the slot's size; every slot outside the runs keeps its bytes from the frame that wrote it last. Which Renderables a frame writes, and how runs form, is prepare's (Prepare); the staging slot the bytes pass through is Staging's.

let instance_size = std::mem::size_of::<InstanceData>() as wgpu::BufferAddress;
let instance_uploads = frame.instance_writes.iter().map(|write| {
    (
        &self.instance_buffer,
        u64::from(write.first_slot) * instance_size,
        bytemuck::cast_slice(&frame.instances[write.instances.clone()]),
    )
});

Renderer::upload, src/render/renderer.rs.

Since unwritten slots keep their bytes, a lost write would leave a slot wrong until its Renderable next changed. Where a frame's staging slot fails to map and its writes never land, the Renderer records it, take_lost_instance_writes reports it to the State, and the next prepare writes every Instance again (rewrite_all_instances).

4 · anchor_and_offset · camera_relative_position

Anchor plus offset: no World position in f32

A slot holds its pivot as the integer cell of a 64 m grid plus an f32 offset from that cell's corner, split from the f64 World position on the CPU. The shader subtracts the camera's anchor in integers before it adds any float, so f32 only ever holds magnitudes near the camera, and a moving camera changes no slot (ADR 0014).

/// Splits a World position into the integer anchor of its grid cell and its
/// f32 offset from that anchor's corner, so no World position reaches the GPU
/// in f32 (ADR 0014).
pub fn anchor_and_offset(position: glam::DVec3) -> ([i32; 3], [f32; 3]) {
    let anchor = (position / ANCHOR_CELL_SIZE).floor();
    let offset = position - anchor * ANCHOR_CELL_SIZE;
    (anchor.as_ivec3().to_array(), offset.as_vec3().to_array())
}

src/render/instance.rs.

The offset is taken from the cell's corner, so it never reaches past one cell, 64 m, along an axis however far the Instance is from the World's origin. The camera is split by the same function and reaches the GPU in the camera uniform, not in any slot, which is why a frame where only the camera moves writes no Instance but the Moving Instances, which prepare writes every frame.

// A point's position relative to the camera, from its Instance's anchor and
// offset, the camera's, and its position relative to the Instance's pivot
// (ADR 0014). The anchor difference is exact in integers, so f32 only ever
// holds magnitudes near the camera.
fn camera_relative_position(
    anchor: vec3<i32>,
    offset: vec3<f32>,
    camera_anchor: vec3<i32>,
    camera_offset: vec3<f32>,
    local_position: vec3<f32>
) -> vec3<f32> {
    let anchor_position = vec3<f32>(anchor - camera_anchor) * ANCHOR_CELL_SIZE;
    return anchor_position + (offset - camera_offset) + local_position;
}

src/render/shaders/common.wgsl.

Both readers call it: the culling pass for the centre of an Instance's Mesh bounds, the vertex stage for each vertex. The view-projection matrix in the camera uniform holds no translation, since every position it multiplies is already relative to the camera.

5 · culling.wgsl · main.wgsl · acceleration_structures.rs

Who reads it

Two passes read the buffer on the GPU, each by slot: the culling pass walks every slot in use to build the frame's draw, and the vertex stage finds its slot in the Meshlet record a packed index names. The TLAS never read the buffer; they place their entries from the same values, in Frame data, on the CPU.

The culling pass

offset_slots runs an invocation per slot, in workgroups of SCAN_BLOCK_SIZE, dispatched over the slots in use, instance_slot_count, one past the highest slot any Renderable has taken, not over the capacity. A slot whose Mesh is NO_MESH is read no further: it is neither visible nor drawn.

if slot < instance_slot_count && instances[slot].mesh != NO_MESH {
    let instance = instances[slot];
    let mesh = meshes[instance.mesh];
    let bounds = clip_space_bounds(instance, mesh);
    visible = !CULLING || in_view_frustum(bounds);

offset_slots, src/render/shaders/culling.wgsl.

append_records reads a drawn slot again for its Mesh and its material_id, which replaces each Meshlet's own Material ID in the records it writes unless it is NO_MATERIAL; append_triangles reads the slot's Mesh to place a record's indices. Each Meshlet record carries its Instance's slot, so the draw names Instances by slot, in slot order.

The vertex stage

The frame's draw has no base vertex and no instance index: its vertex index is a packed index, a Meshlet record in the high bits and a vertex of that record's Meshlet in the low ones. vertex_output reads the record, the record names the slot, and the slot gives the transform. The three vertex entry points, vs_depth_prepass, vs_depth_normals and vs_main, all go through it.

let index = unpack_index(packed_index);
let record = meshlet_records[index.record];
let instance = instances[record.instance_slot];
let first_vertex = meshlets[record.meshlet].first_vertex;
let vertex = decode_vertex(vertices[meshlet_vertices[first_vertex + index.vertex]]);
let position = camera_relative_position(
    instance.anchor,
    instance.offset,
    camera.anchor,
    camera.offset,
    instance.rotation_scale * vertex.position
);
out.clip_position = camera.view_proj * vec4<f32>(position, 1.0);
out.uv = vertex.uv;
let tangent_frame = vertex.tangent_frame;
out.normal = instance.normal_matrix * tangent_frame.normal;
// Tangents are directions along the surface, so they follow the
// rotation-scale; only normals need the inverse-transpose.
out.tangent_world = vec4<f32>(
    instance.rotation_scale * tangent_frame.tangent,
    tangent_frame.bitangent_sign
);

vertex_output, src/render/shaders/main.wgsl.

The TLAS

The static TLAS takes each static Instance from the frame's Instance writes, into the entry at the Instance's slot, and the dynamic TLAS takes each Moving Instance Frame data lists. Both read the InstanceData that prepare queued for the buffer, on the CPU, and compose its anchor and offset into a TLAS entry's f32 rows from one fixed anchor, the camera's in the first Frame data. Each entry is tagged with its slot. A slot whose Mesh is NO_MESH has no BLAS, so its static entry is emptied.

/// `instance`'s transform as rows of the 3×4 matrix a TLAS Instance holds,
/// its translation from `anchor`'s corner composed in f64, so only the f32
/// result rounds (ADR 0014).
fn anchored_transform(instance: &InstanceData, anchor: [i32; 3]) -> [f32; 12] {
    let [x_axis, y_axis, z_axis] = instance.rotation_scale;
    let row = |axis: usize| {
        let cells = i64::from(instance.anchor[axis]) - i64::from(anchor[axis]);
        let translation = cells as f64 * ANCHOR_CELL_SIZE + f64::from(instance.offset[axis]);
        [x_axis[axis], y_axis[axis], z_axis[axis], translation as f32]
    };
    bytemuck::cast([0, 1, 2].map(row))
}

6 · NO_MESH · InstanceSlots::get_or_take

Empty slots and a full buffer

A slot that should draw nothing still holds an Instance: one whose Mesh is NO_MESH, which the culling pass skips. A Renderable that finds every slot taken gets none: it is refused, warned about once, counted every frame, and drawn once a slot frees.

Two kinds of slot hold that empty Instance. A freed slot, whose Renderable was despawned or lost its Mesh Handle or World transform, is written the empty Instance in the frame it is freed, so the GPU stops drawing it at once. A skipped Renderable, whose Mesh is not in the Mesh pool yet or which has no Material Handle where a Primitive names no Material, keeps its slot, which holds the empty Instance until the Renderable can draw.

/// The Instance of a slot that draws nothing: a freed slot's, or a skipped
/// Renderable's.
fn no_mesh_instance() -> InstanceData {
    InstanceData {
        mesh: NO_MESH,
        ..bytemuck::Zeroable::zeroed()
    }
}

src/render/prepare.rs.

The rest of the empty Instance is zeroes, which no reader looks at: the culling pass tests the Mesh before anything else, and only drawn slots reach a Meshlet record. A freed slot stays below instance_slot_count, so the culling pass still reads its Mesh each frame until a Renderable takes it again.

Past capacity

The capacity is enforced where slots are handed out, in prepare's slot table, not at the buffer. A Renderable without a slot takes a freed one first, then a fresh one, the next past the highest yet taken, while that is under INSTANCE_CAPACITY; with neither, it is refused.

let fresh = (self.end < INSTANCE_CAPACITY).then_some(self.end);
let Some(slot) = self.free.pop().or(fresh) else {
    if self.refused.insert(entity) {
        tracing::warn!(
            ?entity,
            capacity = INSTANCE_CAPACITY,
            "Renderable refused: the Instance buffer is full"
        );
    }
    return None;
};

InstanceSlots::get_or_take, src/render/prepare.rs.

A refused Renderable is neither written nor drawn; it is warned about the first time it is refused, counted in renderables_refused every frame it stays refused, and asked again every frame, so it takes the first slot another Renderable frees, from the frame after. No frame grows the buffer, and no write can land past its end, since no slot past it is ever handed out. How the table keeps, frees and reuses slots is on the Prepare page.

8 · bench/baselines/apple-m4-pro

What it costs

The buffer costs the same 64 MiB in every scene, whatever it holds: about a tenth of the GPU memory of every Reference scene but town, the dense scene, whose other memory is larger. The time it costs lies inside the culling and main passes and the frame's uploads, which no Baseline splits out.

GPU memory is the engine's own ledger: Renderer::gpu_memory_bytes adds up the size of every buffer and texture the Renderer created, and the measured estimate of its acceleration structures, the same way on every backend, since wgpu has no allocator report on Metal (ADR 0013). The Instance buffer joins it at its full size, whatever its slots hold. gpu_memory_bytes and instances_drawn below are the medians the committed Baselines hold over 1,800 measured frames at 2560×1440 with 4x MSAA, release builds on the Apple M4 Pro; the buffer's bytes come from the code.

uploaded_bytes is left out of the table: it sums the camera and light uniforms, the light buffer, the bends, the Instance writes, the slot count when it changes and the dynamic TLAS's entries, and the Baselines do not record the Instance writes' share of it.

9 · ADRs 0003, 0005, 0013, 0014, 0021

Why this way

One persistent buffer, a slot per Renderable. ADR 0003 keeps every Instance in one GPU buffer, in a slot the Renderable keeps while it is one, written only when what it holds changes, and every frame for a Moving Instance, with no uniform buffer per entity: GPU-driven culling, TLAS builds and instancing all consume that one shape, and a frame in which nothing changed and nothing moves writes no Instance. A published GPU-driven renderer draws a test scene of 250,000 separate moving objects with two indirect draw calls from data of this kind.

A structured buffer, looked up by slot. ADR 0005 puts per-Instance data in a structured buffer that each draw indexes into, with no bind group per Mesh or per Instance. Since one draw spans every Instance (ADR 0019), the key is the slot a Meshlet record names, not the draw's instance index.

A fixed capacity, not growth. A GPU buffer cannot grow in place: growing one means creating a larger buffer, copying the old into it on the GPU and rebuilding every bind group that held the old one, mid-frame, with both alive during the copy. Created once at its capacity, the buffer's memory is known at startup, no frame pays for a resize, the scene geometry bind group is built once, and a full buffer shows itself as a refusal, warned about and counted, rather than as more memory. The price is 64 MiB in every scene, a one-Instance scene included. The capacity is provisional, its doc comment says, until the split of the 8 GB GPU memory Budget by kind of memory sizes it.

Within one storage binding at the floor. The vertex and compute stages read the whole buffer through one binding, so it must fit the Capability floor's max_storage_buffer_binding_size. ADR 0021 keeps that limit at wgpu's default of 128 MiB, Vulkan's minimum, and 64 MiB fits within it, so the capacity raised no limit.

Anchor plus offset in the slot. ADR 0014 forbids any World position in f32 on the GPU: f32 positions fail the precision bar beyond 512 m from their origin, and Metal has no f64 in shaders. An integer anchor and an f32 offset per slot, composed relative to the camera in the shader, keep every slot valid as the camera moves, so camera motion dirties no Instance; a floating origin would instead rewrite every position the engine holds, GPU buffers among them, at each shift.

Counted whole, as the engine counts it. ADR 0013 counts GPU memory as the bytes of the buffers and textures the engine created, summed by the engine on every backend, so the Instance buffer counts at its capacity, not at the slots in use: the figure is what the device holds for it.

10

Limits

524,288 Renderables at once. Past that a Renderable is refused and not drawn until a slot frees; nothing streams or evicts Instances.

Shadows cover fewer slots. The static TLAS covers the lowest STATIC_TLAS_CAPACITY slots, 262,144, half the buffer: a static Instance in a higher slot draws but casts no shadow, and is counted in static_instances_left_out. The dynamic TLAS holds at most DYNAMIC_TLAS_CAPACITY, 10,000, Moving Instances.

One doubling of headroom in its binding. At 128 bytes a slot, twice the capacity would fill the floor's 128 MiB storage binding exactly; any more would need the binding split or the floor raised.

The slots in use never shrink. The culling pass walks every slot below one past the highest ever taken, so a scene that frees its high slots still dispatches over them, each read for its NO_MESH and skipped.

64 MiB whatever the scene. A scene of one Instance holds the same buffer as town; until the Budget split sizes it, the capacity is one number for the app, tests, bench and CI.

History

The buffer began as per-Instance data in a structured buffer that each draw looked up by its instance index, then became persistent, a slot per Renderable written only when it changes, and took an anchor plus an offset in place of a World translation. It grew by doubling, copied into a larger buffer mid-frame with its bind group rebuilt, until it was created once at its fixed capacity, with the refusal past it. The Mesh then moved into the slot's spare bytes, a freed slot came to hold an Instance with no Mesh, and the lookup moved from the instance index to the slot a Meshlet record names, as the GPU began to build the frame's draw; the buffer moved to group 2, whose bind group came to be built once. The narrative, with the measurements of its day, is in The Instance buffer, whose chapters on GPU memory and on measuring stay there for now. This page describes the mechanism as it is.
