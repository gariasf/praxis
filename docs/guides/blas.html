A BLAS per Mesh

Each Mesh that rays trace gets a BLAS when it loads, built on the GPU from where the Mesh already lies in the vertex and index Arenas, then compacted into a tighter copy, which the CPU waits for before any TLAS is built from it; a Mesh loaded to be refitted keeps its BLAS uncompacted, and one only drawn gets none.

Describes main at 3654003f (2026-11-06). A change to the Mesh pool's BLASes rewrites this page and moves the commit; nothing is appended. Read first: Waiting on the GPU for why a GPU read of what other GPU work writes needs something to order the two. The static TLAS and the dynamic TLAS place these BLASes; the BLAS refit updates the refitted ones.

Interface

Runs
The build at load, in MeshPool::load_for, for a Mesh whose MeshUse has rays trace it. The compaction in the next frame's Renderer::upload, through MeshPool::compact_blases, before the static TLAS takes the BLASes. Every Mesh loads in State::new, before the first frame, so only the first frame compacts.
Reads
The Mesh's range of the vertex Arena, of which the build sees each vertex's position alone, and its range of the index Arena, which holds a Mesh's cooked index stream only where rays trace it.
Writes
One wgpu::Blas per traced Mesh, kept at its Handle's index in the Mesh pool and returned by MeshPool::blas; for a refitted Mesh, also a MeshBlas, the BLAS with the build's sizes and ranges, which each refit repeats.
Builds
One build_acceleration_structures call per traced Mesh, recorded into the load encoder after the copies that fill its Arena ranges; one compaction copy per compacted BLAS, which wgpu queues in its pending writes.
Bind groups
None: no pass binds a BLAS. A TLAS entry names one, and a ray reaches it through the TLAS.
Shader
None.
Counted
In the acceleration structures' kind of gpu_memory_bytes: each BLAS at the size its driver gives for it, and once compacted at the adapter's estimated fraction of that size. The compaction's two CPU waits count in the upload stage of the frame that runs them. No GPU pass time is taken of the builds or the copies.

1 · MeshUse

What a Mesh is loaded for

A Mesh is loaded for a use: drawn, traced, both, or drawn and traced through a BLAS the GPU updates each frame. Only a traced Mesh gets a BLAS and the index stream it is built from; only a drawn one gets Meshlets.

/// What a Mesh is loaded for: the main pass draws it from its Meshlets, rays
/// trace it through its BLAS, or both.
#[derive(Clone, Copy, Debug, Eq, Hash, PartialEq)]
pub enum MeshUse {
    DrawnAndTraced,
    /// Drawn alone: a Mesh the GPU bends, whose BLAS, built from its rest
    /// shape, would cast another shape's shadow.
    Drawn,
    /// Traced alone: a shadow proxy, which no pass draws, so it keeps no
    /// Meshlets and needs no Material.
    Traced,
    /// Drawn and traced, a Mesh the GPU bends whose BLAS is updated each
    /// frame from its bent shape: built to allow updates, never compacted.
    Refitted,
}

impl MeshUse {
    /// Whether the main pass draws it, so it needs Meshlets.
    pub(crate) fn drawn(self) -> bool {
        self != MeshUse::Traced
    }

    /// Whether rays trace it, so it needs a BLAS and the index stream the
    /// BLAS is built from.
    fn traced(self) -> bool {
        self != MeshUse::Drawn
    }
}

/// The flags a refitted Mesh's BLAS is built with, which its refits repeat.
pub const REFITTED_BLAS_FLAGS: wgpu::AccelerationStructureFlags =
    wgpu::AccelerationStructureFlags::PREFER_FAST_TRACE
        .union(wgpu::AccelerationStructureFlags::ALLOW_UPDATE);

MeshUse and REFITTED_BLAS_FLAGS, src/assets/pools.rs.

A BLAS is built from the vertices a Mesh holds when it loads. A Mesh the GPU bends changes shape every frame, so a BLAS of its rest shape would cast a shadow of a shape it no longer has. Such a Mesh is either drawn alone, with its shadow cast by shadow proxies, or loaded as refitted, its BLAS brought to the bent shape each frame. The asset loader names each Mesh's use, MeshUse::DrawnAndTraced for a Mesh neither bent nor a shadow proxy.

A Mesh loaded drawn alone still takes its vertices and Meshlets, which the main pass draws, but no range of the index Arena and no BLAS: its slot in the pool's BLAS list holds none, so MeshPool::blas returns None and neither TLAS gives its Instances an entry. A Mesh loaded traced alone takes no Meshlet ranges, so the culling pass finds nothing of it to draw.

2 · MeshPool::load_for · LoadStaging::build_blas

The build, from the Arenas

The BLAS is built from the Mesh where it already lies: its positions in the vertex Arena, its indices in the index Arena, read in place by the GPU after the copies that put them there, with no transform and no second copy of the geometry.

Once the Mesh has its Arena ranges and its writes are staged, load_for describes the BLAS's one geometry and its flags, asks the driver how large such a BLAS is, and keeps that size with the Mesh's ranges at its Handle's index; then it creates the BLAS and records its build. A Mesh no ray traces counts no bytes and returns before the BLAS.

/// The build of `blas` from its ranges of the vertex and index Arenas:
/// the position leads each vertex, and the cooked indices count from the
/// Mesh's first vertex.
fn blas_build_entry<'a>(&'a self, blas: &'a MeshBlas) -> wgpu::BlasBuildEntry<'a> {
    wgpu::BlasBuildEntry {
        blas: &blas.blas,
        geometry: wgpu::BlasGeometries::TriangleGeometries(vec![wgpu::BlasTriangleGeometry {
            size: &blas.geometry,
            vertex_buffer: &self.vertex_arena.buffer,
            first_vertex: blas.first_vertex,
            vertex_stride: size_of::<CookedVertex>() as u64,
            index_buffer: Some(self.index_arena()),
            first_index: Some(blas.first_index),
            transform_buffer: None,
            transform_buffer_offset: None,
        }]),
    }
}

MeshPool::blas_build_entry, src/assets/pools.rs, which rebuild_refitted_blases also builds from.

A cooked vertex is 28 bytes, a position of three f32, a uv of two f32 and a QTangent of four i16, as CookedVertex asserts. The build reads Float32x3 at a 28-byte stride, so it sees each vertex's leading 12 bytes, the position, and nothing else. first_vertex is the Mesh's offset into the vertex Arena in vertices, which wgpu-core multiplies by the stride; first_index skips the indices before the Mesh's range. The cooked indices count from the Mesh's own first vertex, so with that offset they land on the Mesh's positions.

/// Records `entry`'s BLAS build after the copies recorded so far, so it
/// reads what they write.
pub fn build_blas(&mut self, entry: &wgpu::BlasBuildEntry<'_>) {
    let (_, encoder) = self.pending();
    encoder.build_acceleration_structures(std::iter::once(entry), std::iter::empty());
}

LoadStaging::build_blas, src/render/staging.rs.

LoadStaging holds one encoder for everything a load writes: each Arena write goes through its StagingBelt into a copy on that encoder, and each BLAS build is recorded on the same encoder after them. LoadStaging::submit sends the encoder ahead of the next frame's. The builds need two buffer usages: the vertex Arena is created STORAGE | BLAS_INPUT, since the vertex shader pulls from it and builds read it, and the index Arena BLAS_INPUT alone, since no pass draws from it; Arena::new adds COPY_DST to both, for the copies that fill them.

The size is asked with the same geometry and flags the BLAS is created with, so it is the size wgpu-core creates it at; Meshlets play no part in it. The Mesh's bytes count as uncompacted until compaction moves them, and a Mesh freed from the pool takes them back from whichever sum holds them (Counting bytes).

3 · AccelerationStructureFlags · OPAQUE

Flags and opaque triangles

A BLAS built once and traced every frame asks the driver to spend build time on fast tracing, and allows compaction; one refitted every frame allows updates instead. Every triangle is opaque, so a hit counts the moment traversal finds it.

PREFER_FAST_TRACE suits geometry that is built once and traced at every lit pixel of every frame. ALLOW_COMPACTION is what lets the copy in the next section run: wgpu-core refuses to compact a BLAS created without it. A refitted Mesh's BLAS is created with REFITTED_BLAS_FLAGS, PREFER_FAST_TRACE with ALLOW_UPDATE in place of compaction, and each refit repeats those flags; wgpu documents a compacted BLAS as one that "may not be rebuilt or compacted", so a BLAS the frame rewrites cannot be one.

The geometry is flagged AccelerationStructureGeometryFlags::OPAQUE: no triangle has an alpha test. wgpu-types 30.0.1's doc for the flag recommends it, saying that BLASes without it will not have hits, since naga has no candidate intersections. The shadow mask pass's queries also pass RAY_FLAG_FORCE_OPAQUE, so one rayQueryProceed completes a traversal (the shadow mask pass, One ray).

4 · MeshPool::compact_blases

Compaction and its two waits

A BLAS's compacted size is known only once it is built, so compaction waits on the CPU for the builds, records a copy of each into a tighter allocation, and waits again for the copies: nothing on the GPU orders a TLAS build after them.

/// Compacts the BLASes of the Meshes loaded since the last call, once
/// the staging their builds were recorded into is submitted: it waits
/// for the GPU to build them, then to compact them. Nothing else orders
/// a TLAS build after the copies: wgpu-core 30.0.1 records no barrier
/// after `compact_blas`'s copy on any backend, and Metal has no
/// acceleration-structure barrier at all (gfx-rs/wgpu#9215). A Mesh keeps
/// its compacted BLAS, or the one built where compaction failed, as
/// logged.
pub fn compact_blases(&mut self, queue: &wgpu::Queue) {
    if self.awaiting_compaction.is_empty() {
        return;
    }
    for &(handle, _) in &self.awaiting_compaction {
        if let Some(blas) = &self.blases[handle.index as usize] {
            blas.prepare_compaction_async(|_| {});
        }
    }
    if let Err(error) = self.device.poll(wgpu::PollType::wait_indefinitely()) {
        tracing::error!(%error, "waiting for BLAS builds failed");
    }
    for (handle, bytes) in self.awaiting_compaction.drain(..) {
        let Some(blas) = &mut self.blases[handle.index as usize] else {
            continue;
        };
        if !blas.ready_for_compaction() {
            tracing::warn!(
                mesh = handle.index,
                "BLAS not compacted: not ready after its build"
            );
            continue;
        }
        *blas = queue.compact_blas(blas);
        if let Some(allocation) = &mut self.allocations[handle.index as usize] {
            allocation.blas_compacted = true;
        }
        self.uncompacted_blas_bytes -= bytes;
        self.compacted_blas_bytes += bytes;
    }
    self.charge_blases();
    // The copies wait in the queue's pending writes until a submit.
    queue.submit(std::iter::empty());
    if let Err(error) = self.device.poll(wgpu::PollType::wait_indefinitely()) {
        tracing::error!(%error, "waiting for BLAS compaction failed");
    }
}

MeshPool::compact_blases, src/assets/pools.rs.

  1. Ask for each compacted size. prepare_compaction_async on each BLAS loaded since the last call; wgpu answers once the GPU has built it.
  2. Wait for the builds. device.poll(PollType::wait_indefinitely()) blocks the calling thread, the main thread, until the GPU has finished every submission, the load encoder with its builds among them, and so has answered.
  3. Replace each ready BLAS with its copy. queue.compact_blas returns the compacted BLAS at once and records the copy into the queue's pending writes; the Mesh's allocation is marked compacted, and its built bytes move from the uncompacted sum to the compacted one, which the charge then counts at the adapter's fraction. A BLAS that is not ready keeps its built form, counted as built, and a warning names its Mesh.
  4. Send the copies. Pending writes reach the GPU only with a submission, and a poll waits only for what was submitted, so an empty queue.submit sends them as a submission of their own.
  5. Wait for the copies. A second poll blocks until the GPU has written every compacted BLAS.

The second wait is there because nothing else orders the copies before the TLAS builds that read them. wgpu-core 30.0.1 records no barrier after compact_blas's copy on any backend, and wgpu-hal 30.0.1's Metal backend records no barrier at all; and a GPU queue orders when its work starts, not when it finishes. Without the wait a TLAS built in the next submission could read a BLAS whose copy had not finished, and the Mesh would cast no shadow until that TLAS was next rebuilt. Waiting on the GPU follows the race to its cause.

// Loads staged since the last frame land before its copies and
// draws, and their BLASes are compacted before the static TLAS
// takes them.
recorder.counters.uploaded_bytes += self.load_staging.submit(&self.queue);
self.mesh_pool.compact_blases(&self.queue);

The start of Renderer::upload, src/render/renderer.rs.

The waits run where the BLASes are first needed: at the head of the upload of the first frame after the loads, which submits the load encoder and compacts before the static TLAS's update records its build into the frame's encoder. Since every Mesh loads in State::new, that is the first frame, and every later frame finds nothing awaiting compaction and returns at once. Both waits block the main thread, which records and submits the frame, for the whole of the load's GPU work, the Textures' copies included, since a poll waits for every submission. Refitted BLASes take no part: they are never compacted, and how a frame orders their updates before the dynamic TLAS's build is the BLAS refit's. The static TLAS's Limits count the wait among its own.

5 · blas_bytes · compacted_blas_fraction

Counting bytes

wgpu keeps an acceleration structure's size to itself, so the engine asks the driver the same question wgpu-core asks when it creates one, through wgpu-hal, and counts that answer; only a compacted BLAS's size, which neither wgpu-core nor wgpu-hal gives back, stays an estimate: a fraction of its built size measured once on each kind of adapter.

blas_bytes and tlas_bytes both end in hal_built_bytes, tried on each backend the build has: Metal on Apple targets, Vulkan on Windows, Linux, Android and FreeBSD, DX12 on Windows. Each returns None on a device of another backend, so the one the device runs on answers.

let buffer = Some(&*hal_buffer);

            vertex_stride: 0,

            buffer,

// SAFETY: the descriptor names live buffers only, as wgpu-core's does.

The body of hal_built_bytes, src/render/acceleration_structures.rs; the elided lines give the triangles' indices, a transform only under USE_TRANSFORM, as wgpu-core gives one, and an Instance of zeros.

The geometry it describes is wgpu-core's own: zero first vertex and zero stride, a buffer named in place of wgpu-core's zero buffer, and for a TLAS one Instances entry of its capacity. Metal's query panics without a buffer there, so a caller passes input: the Mesh pool its vertex Arena, the GPU memory ledger a 64-byte buffer it creates for the query and drops at once. A TLAS adds wgpu-core's buffer of its Instances, a record per slot and at least one, each as long as wgpu-hal's encoding of an Instance: 72 bytes on Metal, 64 on Vulkan and DX12.

/// The fraction of its built bytes a compacted BLAS keeps on `adapter`, as
/// measured there: an estimate, since wgpu-core keeps the compacted size it
/// reads crate-private [ref:wgpu-30-blas-compacted-size-private], and reading
/// it again takes a query recorded through wgpu-hal outside wgpu's tracking
/// and another wait. NVIDIA's on an NVIDIA GPU, on any backend; lavapipe's on
/// any other Vulkan adapter, software or not; and the M4 Pro's on any other,
/// as the Budgets' reference machine (ADR 0013).
pub fn compacted_blas_fraction(adapter: &wgpu::AdapterInfo) -> f64 {
    if adapter.vendor == NVIDIA_VENDOR {
        // The RTX 2070 SUPER on Vulkan (NVIDIA 621.01), bytes a triangle by
        // wgpu's allocator report (`docs/performance.md`, Measurements
        // behind the code).
        29.2 / 70.7
    } else if adapter.backend == wgpu::Backend::Vulkan {
        // lavapipe (Mesa 25.2.8) leaves a compacted BLAS as it was built
        // (`docs/research/source-audit.md`, lavapipe's figures).
        1.0
    } else {
        // The M4 Pro on Metal, bytes a triangle by `currentAllocatedSize`
        // (`docs/research/global-illumination-and-lighting.md`).
        45.5 / 94.0
    }
}

compacted_blas_fraction, src/render/acceleration_structures.rs.

fn charge_blases(&mut self) {
    let compacted_bytes =
        (self.compacted_blas_bytes as f64 * self.compacted_blas_fraction).round() as u64;
    let bytes = compacted_bytes + self.uncompacted_blas_bytes;
    self.blas_charge
        .set(GpuMemoryKind::AccelerationStructures, bytes);
}

MeshPool::charge_blases, src/assets/pools.rs.

The Mesh pool keeps two sums of built bytes, compacted and not, and its one charge on the ledger counts the compacted sum at the adapter's fraction, rounded to a whole byte, plus the other. The fraction is picked once, from the adapter, when the ledger is created: an NVIDIA GPU, on Vulkan or DX12, gets the RTX 2070 SUPER's; any other Vulkan adapter gets lavapipe's, whose compaction leaves a BLAS as large as it was; every other adapter, as on Metal, gets the Apple M4 Pro's, the reference machine of ADR 0013. The vendor test reads the PCI vendor ID, which Vulkan and DXGI both report. Each TLAS is counted where it is created, through GpuMemory::create_tlas, at tlas_bytes.

Frame stats carry the acceleration structures' kind and add it into gpu_memory_bytes. For scale, pbr-sweep's sphere, one Mesh of 2,208 triangles shared by every sphere, is built at 207,424 bytes on the M4 Pro and counted at 100,402 once compacted.

What it costs

A BLAS costs GPU memory in proportion to its triangles, about 95 bytes each as the M4 Pro's driver sizes a large one, and compaction is counted at under half of that on the M4 Pro and on NVIDIA. Its other cost, the CPU waiting for the builds and copies, falls in a load frame, which no Baseline measures.

8 · ADRs 0013, 0016, 0017, 0020

Why this way

A BLAS per Mesh, at load. ADR 0020 gives each Mesh rays trace a BLAS at load, compacted unless it is loaded to be refitted or rebuilt each frame, and places it through TLAS entries, one per Instance: a Mesh's triangles are built into one structure however many Instances share it, as helmet's and pbr-sweep's do.

Built from the Arenas in place. ADR 0017 keeps geometry in fixed Arenas that a Pool sub-allocates; the build reads the Mesh's ranges there, so the geometry exists once on the GPU and no staging copy is kept for it. Keeping the index stream only for traced Meshes leaves the index Arena to the Meshes that need it.

No BLAS for a bent Mesh drawn alone. Its BLAS, built from its rest shape, would cast another shape's shadow; the default crowd form casts the figures' shadows through rigid proxies instead, and the refitted form updates a BLAS each frame, which a compacted BLAS cannot be.

Compaction. A BLAS built once is traced for the rest of the run, so a one-time copy at load buys back over half its memory on the M4 Pro and on NVIDIA, the adapters Budgets and comparisons are judged on.

A CPU wait, not ordering on the GPU. The compaction runs once, at load, where a stall of the main thread, the one thread that submits and polls under ADR 0016, costs one frame. Ordering the copies before the TLAS builds on the GPU would need wgpu to record a barrier after the copy, which wgpu-core 30.0.1 does not on any backend, or Metal shared events through wgpu-hal, the route the per-frame refit takes because a wait in every frame could not pay; a wgpu version that orders the copy is a dependency change and the owner's call.

The driver's size, not a measured rate. ADR 0013's GPU memory Budget and ADR 0017's split of it by kind need acceleration structures counted, and wgpu 30 keeps the sizes it creates them at to itself. wgpu-hal answers the same question wgpu-core asks, so asking it as wgpu-core does counts each structure at the size it is created at, on any adapter, where bytes per triangle and per slot measured on three adapters counted every other adapter by one of theirs.

A compacted size estimated. wgpu-core reads a compacted BLAS's size back into its own buffer and keeps it crate-private. wgpu-hal's command encoder could read it again, but only through commands recorded outside wgpu's tracking, with their own barriers on each backend and another wait on the GPU; a new dependency was ruled out. So the built size, which is exact, is scaled by the compaction measured on each kind of adapter.

9

Limits

A CPU wait per load. The frame after a load blocks the main thread twice for the load's whole GPU work. Today that is the first frame alone; Meshes streamed during play would stall each frame that loads them, until wgpu orders the copy on every backend.

Compaction estimated, by kind of adapter. A compacted BLAS counts its built size at a fraction measured on the M4 Pro, the RTX 2070 SUPER or lavapipe: an AMD or Intel GPU on Vulkan is counted with lavapipe's, which counts no saving, and any adapter neither NVIDIA nor on Vulkan with the M4 Pro's.

Sizes, not allocations. The count is the size the driver asks for; what its allocator rounds that up to, or the scratch each build takes and returns, is not counted.

Compaction can fail. One that is not ready after its build keeps its built size, counted as built, with a warning.

Opaque only. No triangle has an alpha test, so a cutout Material would cast a solid shadow.

Freed only by tests. MeshPool::free drops a Mesh's BLAS and gives back its bytes, but nothing outside tests calls it yet, and it refuses a refitted Mesh, whose refit scratch holds a region per refitted BLAS in load order.

One build per Mesh. Each Mesh's build is its own build_acceleration_structures call on the load encoder; builds are not batched across Meshes.

History

The Mesh pool gained a compacted BLAS per Mesh on 2026-10-20, with the memory estimate, measured then on the M4 Pro and lavapipe and since 2026-10-26 chosen by adapter, with an RTX 2070 SUPER's figures for NVIDIA. The wait for the compaction's copies followed on 2026-10-23, once a test that traced a triangle sometimes missed it under load and the race proved to be the engine's own. The crowd brought the uses: a Mesh drawn alone with no BLAS, and a shadow proxy traced alone, then on 2026-10-26 the refitted Mesh, built to allow updates and never compacted. Since 2026-11-06 each BLAS and TLAS is counted at the size its driver gives through wgpu-hal, and only compaction is estimated. The race behind the wait is on Waiting on the GPU. This page describes the mechanism as it is.
