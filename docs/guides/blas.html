Praxis · before the frame · src/assets/pools.rs

A BLAS per Mesh

Each Mesh that rays trace gets a BLAS of its LOD 0 when it loads, built on the GPU from where the Mesh already lies in the vertex and index Arenas, then compacted into a tighter copy, which no TLAS takes until the GPU has finished it: the CPU waits for that at a spawn and in a Settled frame, and a streamed load is placed only once it is; a Mesh loaded to be refitted keeps its BLAS uncompacted, and one only drawn gets none.

Describes main at 61426980 (2026-11-25). A change to the Mesh pool's BLASes rewrites this page and moves the commit; nothing is appended. Read first: Waiting on the GPU for why a GPU read of what other GPU work writes needs something to order the two. The static TLAS and the dynamic TLAS place these BLASes; the BLAS refit updates the refitted ones; the Chunk streamer places a streamed load once its BLASes are ready.

Interface

Runs
The build at load, in MeshPool::load_for, for a Mesh whose MeshUse has rays trace it: a spawn's Meshes in State::new, a streamed Chunk's or Far proxy's in the frame that loads it. The compaction in each Renderer::upload while a BLAS awaits it, through MeshPool::compact_blases, before the static TLAS takes the BLASes: waited for when a load's BLASes are not deferred, as a spawn's, in the first frame, and a Settled frame's are; otherwise taken a step each upload, with MeshPool::poll_blases in each frame that streams, until MeshPool::blas_ready lets the streamer place the load.
Reads
The Mesh's range of the vertex Arena, of which the build sees each vertex's position alone, and its range of the index Arena, which holds the Mesh's LOD 0 index stream only where rays trace it.
Writes
One wgpu::Blas per traced Mesh, kept at its Handle's index in the Mesh pool and returned by MeshPool::blas; for a refitted Mesh, also a MeshBlas, the BLAS with the build's sizes and ranges, which each refit repeats. Beside it, the pool keeps what the static TLAS reads with a BLAS: the Mesh's Thin Primitive radius (MeshPool::thin_radius_metres) and whether it is a Far proxy's (MeshPool::is_far_proxy).
Builds
One build_acceleration_structures call per traced Mesh, recorded into the load encoder after the copies that fill its Arena ranges; one compaction copy per compacted BLAS, which wgpu queues in its pending writes and an empty submit sends.
Bind groups
None: no pass binds a BLAS. A TLAS entry names one, and a ray reaches it through the TLAS.
Shader
None.
Counted
In the acceleration structures' kind of gpu_memory_bytes: each BLAS at the size its driver gives for it, and once compacted at the adapter's estimated fraction of that size. The two CPU waits of a frame that waits count as its CPU stage blas_compaction, taken out of its upload stage; a frame whose BLASes are all deferred records no such stage, and its step stays in upload. No GPU pass time is taken of the builds or the copies.

1 · MeshUse

What a Mesh is loaded for

A Mesh is loaded for a use: drawn, traced, both, drawn and traced through a BLAS the GPU updates each frame, or drawn and traced as a Far proxy. Only a traced Mesh gets a BLAS and the index stream it is built from; only a drawn one gets Meshlets.

/// What a Mesh is loaded for: the main pass draws it from its Meshlets, rays
/// trace it through its BLAS, or both.
#[derive(Clone, Copy, Debug, Eq, Hash, PartialEq)]
pub enum MeshUse {
    DrawnAndTraced,
    /// Drawn alone: a Mesh the GPU bends, whose BLAS, built from its rest
    /// shape, would cast another shape's shadow, or one that casts none.
    Drawn,
    /// Traced alone: a shadow proxy, which no pass draws, so it keeps no
    /// Meshlets and needs no Material.
    Traced,
    /// Drawn and traced, a Mesh the GPU bends whose BLAS is updated each
    /// frame from its bent shape: built to allow updates, never compacted.
    Refitted,
    /// Drawn and traced: a Far proxy's load, whose baked Material takes an
    /// entry of the Material table's count for Far proxies.
    FarProxy,
}

impl MeshUse {
    /// Whether the main pass draws it, so it needs Meshlets.
    pub(crate) fn drawn(self) -> bool {
        self != MeshUse::Traced
    }

    /// Whether rays trace it, so it needs a BLAS and the index stream the
    /// BLAS is built from.
    fn traced(self) -> bool {
        self != MeshUse::Drawn
    }

    /// Whether Renderables share one entry per Asset ID: a bent Mesh is its
    /// Renderable's own, as the GPU writes its vertices.
    fn shared(self) -> bool {
        matches!(
            self,
            MeshUse::DrawnAndTraced | MeshUse::Traced | MeshUse::FarProxy
        )
    }
}

/// The flags a refitted Mesh's BLAS is built with, which its refits repeat.
pub const REFITTED_BLAS_FLAGS: wgpu::AccelerationStructureFlags =
    wgpu::AccelerationStructureFlags::PREFER_FAST_TRACE
        .union(wgpu::AccelerationStructureFlags::ALLOW_UPDATE);

A BLAS is built from the vertices a Mesh holds when it loads. A Mesh the GPU bends changes shape every frame, so a BLAS of its rest shape would cast a shadow of a shape it no longer has. Such a Mesh is either drawn alone, with its shadow cast by shadow proxies, or loaded as refitted, its BLAS brought to the bent shape each frame. A Mesh that should cast no shadow at all is drawn alone too. A Far proxy is drawn and traced like any static Mesh, compacted, and loaded under a use of its own so its baked Material is counted apart and a Material pool short of room for one frees unused Far proxies alone. The asset loader names each Mesh's use, MeshUse::DrawnAndTraced for a Mesh none of these.

2 · MeshPool::load_for · LoadStaging::build_blas

The build, from the Arenas

The BLAS is built from the Mesh where it already lies: its positions in the vertex Arena, its LOD 0 indices in the index Arena, read in place by the GPU after the copies that put them there, with no transform and no second copy of the geometry.

Once the Mesh has its Arena ranges and its writes are staged, load_for describes the BLAS's one geometry and its flags, asks the driver how large such a BLAS is, and keeps that size with the Mesh's ranges at its Handle's index; then it creates the BLAS, records its build and adds it to the BLASes awaiting compaction, deferred or not as the pool was told before the load. A Mesh no ray traces counts no bytes and returns before the BLAS.

mesh.indices is the cooked Mesh's LOD 0 index stream; each coarser LOD keeps indices of its own, which reach the GPU only as Meshlets. So the BLAS holds LOD 0's triangles, and the index Arena holds LOD 0's indices of each traced Mesh and nothing else. The allocation also keeps two things the static TLAS reads with the BLAS when it gives an Instance an entry, and that play no part in the build: the widest radius of the Mesh's Thin Primitives, where every Primitive of the LOD 0 the BLAS holds is one, and whether the Mesh was loaded as a Far proxy's (the static TLAS, Entries).

/// The build of `blas` from its ranges of the vertex and index Arenas:
/// the position leads each vertex, and the cooked indices count from the
/// Mesh's first vertex.
fn blas_build_entry<'a>(&'a self, blas: &'a MeshBlas) -> wgpu::BlasBuildEntry<'a> {
    wgpu::BlasBuildEntry {
        blas: &blas.blas,
        geometry: wgpu::BlasGeometries::TriangleGeometries(vec![wgpu::BlasTriangleGeometry {
            size: &blas.geometry,
            vertex_buffer: &self.vertex_arena.buffer,
            first_vertex: blas.first_vertex,
            vertex_stride: size_of::<CookedVertex>() as u64,
            index_buffer: Some(self.index_arena()),
            first_index: Some(blas.first_index),
            transform_buffer: None,
            transform_buffer_offset: None,
        }]),
    }
}

MeshPool::blas_build_entry, src/assets/pools.rs, which rebuild_refitted_blases also builds from.

A cooked vertex is 28 bytes, a position of three f32, a uv of two f32 and a QTangent of four i16, as CookedVertex asserts. The build reads Float32x3 at a 28-byte stride, so it sees each vertex's leading 12 bytes, the position, and nothing else. first_vertex is the Mesh's offset into the vertex Arena in vertices, which wgpu-core multiplies by the stride; first_index skips the indices before the Mesh's range. The cooked indices count from the Mesh's own first vertex, so with that offset they land on the Mesh's positions.

/// Records `entry`'s BLAS build after the copies recorded so far, so it
/// reads what they write.
pub fn build_blas(&mut self, entry: &wgpu::BlasBuildEntry<'_>) {
    let (_, encoder) = self.pending();
    encoder.build_acceleration_structures(std::iter::once(entry), std::iter::empty());
}

LoadStaging::build_blas, src/render/staging.rs.

LoadStaging holds one encoder for everything a load writes: each Arena write goes through its StagingBelt into a copy on that encoder, and each BLAS build is recorded on the same encoder after them. LoadStaging::submit sends the encoder at the head of the next upload. The builds need two buffer usages: the vertex Arena is created STORAGE | BLAS_INPUT, since the vertex shader pulls from it and builds read it, and the index Arena BLAS_INPUT alone, since no pass draws from it; Arena::new adds COPY_DST to both, for the copies that fill them. Each Arena's capacity is its share of the geometry Arenas' Budget (PoolCapacities::from_budgets).

The size is asked with the same geometry and flags the BLAS is created with, so it is the size wgpu-core creates it at; Meshlets play no part in it. The Mesh's bytes count as uncompacted until compaction moves them, and a Mesh freed from the pool takes them back from whichever sum holds them, and leaves the BLASes awaiting compaction (Counting bytes).

3 · AccelerationStructureFlags · OPAQUE

Flags and opaque triangles

A BLAS built once and traced every frame asks the driver to spend build time on fast tracing, and allows compaction; one refitted every frame allows updates instead. Every triangle is opaque, so a hit counts the moment traversal finds it.

PREFER_FAST_TRACE suits geometry that is built once and traced at every lit pixel of every frame. ALLOW_COMPACTION is what lets the copy in the next section run: wgpu-core refuses to compact a BLAS created without it. A refitted Mesh's BLAS is created with REFITTED_BLAS_FLAGS, PREFER_FAST_TRACE with ALLOW_UPDATE in place of compaction, and each refit repeats those flags; wgpu documents a compacted BLAS as one that "may not be rebuilt or compacted", so a BLAS the frame rewrites cannot be one.

The geometry is flagged AccelerationStructureGeometryFlags::OPAQUE: no triangle has an alpha test. wgpu-types 30's doc for the flag recommends it, saying that BLASes without it will not have hits, since naga has no candidate intersections. The shadow mask pass's queries also pass RAY_FLAG_FORCE_OPAQUE, so one rayQueryProceed completes a traversal (the shadow mask pass, One ray).

4 · MeshPool::compact_blases · MeshPool::blas_ready

Compaction, waited for or deferred

A BLAS's compacted size is known only once it is built, and nothing on the GPU orders a TLAS build after the compacted copy, so a BLAS is ready for a TLAS only once the CPU has seen the GPU finish that copy. A spawn's or a Settled frame's loads wait for it on the CPU, twice, in the upload; a streamed load's BLASes are deferred instead, taken a step each frame as polls find the GPU done, and the load is placed once every Mesh it names is ready.

Each BLAS awaiting compaction holds its stage: its build recorded; its compaction prepared, waiting for wgpu to say whether it was built; or its compacted copy submitted, waiting for the GPU to finish it. advance_compaction takes every one as far as the GPU has got:

/// Takes each BLAS awaiting compaction as far as the GPU has got: has
/// its compaction prepared; once built, compacts it; and forgets it once
/// the GPU has finished every submission up to its compacted copy's.
fn advance_compaction(&mut self, queue: &wgpu::Queue) {
    self.awaiting_compaction
        .retain(|awaiting| match &awaiting.stage {
            CompactionStage::Finishing(finished) => !finished.load(Ordering::Acquire),
            _ => true,
        });
    let mut finishing: Option<Arc<AtomicBool>> = None;
    for awaiting in &mut self.awaiting_compaction {
        let index = awaiting.handle.index as usize;
        let Some(blas) = &mut self.blases[index] else {
            continue;
        };
        match &awaiting.stage {
            CompactionStage::Recorded => {
                let prepared = Arc::new(OnceLock::new());
                let outcome = prepared.clone();
                blas.prepare_compaction_async(move |result| {
                    let _ = outcome.set(result.is_ok());
                });
                awaiting.stage = CompactionStage::Building(prepared);
            }
            CompactionStage::Building(prepared) => {
                let Some(&built) = prepared.get() else {
                    continue;
                };
                if built && blas.ready_for_compaction() {
                    *blas = queue.compact_blas(blas);
                    if let Some(allocation) = &mut self.allocations[index] {
                        allocation.blas_compacted = true;
                    }
                    self.uncompacted_blas_bytes -= awaiting.bytes;
                    self.compacted_blas_bytes += awaiting.bytes;
                } else {
                    tracing::warn!(
                        mesh = awaiting.handle.index,
                        "BLAS not compacted: not ready after its build"
                    );
                }
                let finished = finishing.get_or_insert_with(Arc::default).clone();
                awaiting.stage = CompactionStage::Finishing(finished);
            }
            CompactionStage::Finishing(_) => {}
        }
    }
    if let Some(finished) = finishing {
        self.charge_blases();
        // The copies wait in the queue's pending writes until a submit.
        queue.submit(std::iter::empty());
        queue.on_submitted_work_done(move || finished.store(true, Ordering::Release));
    }
}

MeshPool::advance_compaction, src/assets/pools.rs.

  1. Ask for each compacted size. prepare_compaction_async on each BLAS whose build is recorded, and submitted by then, since the upload submits the load staging first; wgpu answers through the callback once a poll finds the GPU has built it.
  2. Replace each built BLAS with its copy. queue.compact_blas returns the compacted BLAS at once and records the copy into the queue's pending writes; the Mesh's allocation is marked compacted, and its built bytes move from the uncompacted sum to the compacted one, which the charge then counts at the adapter's fraction. A BLAS that is not ready keeps its built form, counted as built, and a warning names its Mesh.
  3. Send the copies, and ask to hear when they are done. Pending writes reach the GPU only with a submission, so an empty queue.submit sends them as a submission of their own; on_submitted_work_done sets one flag, shared by every BLAS this call compacted, once the GPU has finished every submission up to it.
  4. Forget the finished ones. The next call drops each BLAS whose flag is set. MeshPool::blas_ready is true for a Mesh with no entry awaiting, or whose entry's flag is set: the GPU has written its compacted BLAS, or its built one where compaction failed.
pub fn compact_blases(&mut self, queue: &wgpu::Queue) -> bool {
    if self.awaiting_compaction.is_empty() {
        return false;
    }
    let waits = (self.awaiting_compaction.iter()).any(|awaiting| !awaiting.deferred);
    self.advance_compaction(queue);
    if !waits {
        return false;
    }
    // One wait ends the builds, the next the compacted copies.
    for _ in 0..2 {
        if let Err(error) = self.device.poll(wgpu::PollType::wait_indefinitely()) {
            tracing::error!(%error, "waiting for BLAS builds and compaction failed");
        }
        self.advance_compaction(queue);
    }
    for awaiting in self.awaiting_compaction.drain(..) {
        tracing::warn!(
            mesh = awaiting.handle.index,
            "BLAS not compacted: not ready after its build"
        );
    }
    true
}

MeshPool::compact_blases, src/assets/pools.rs, without its doc comment, which names the missing barrier: wgpu-core 30.0.2 records none after compact_blas's copy on any backend, and Metal has no acceleration-structure barrier at all (gfx-rs/wgpu#9215).

When any BLAS awaiting is not deferred, compact_blases waits. Its first step asks for the compacted sizes; device.poll(PollType::wait_indefinitely()) then blocks the calling thread, the main thread, until the GPU has finished every submission, the load encoder with its builds among them, so the next step finds every BLAS built and compacts it; the second poll blocks until the copies are written, and the step after it forgets them. It forgets whatever is still awaiting, deferred ones included, with a warning, and returns true. When every BLAS awaiting is deferred, it takes one step and returns false without waiting.

The second wait is there because nothing else orders the copies before the TLAS builds that read them. wgpu-core records no barrier after compact_blas's copy on any backend, and wgpu-hal's Metal backend records no barrier at all; and a GPU queue orders when its work starts, not when it finishes. Without the wait a TLAS built in the next submission could read a BLAS whose copy had not finished, and the Mesh would cast no shadow until that TLAS was next rebuilt. Waiting on the GPU follows the race to its cause. A deferred BLAS meets the same race by not being taken: StaticTlas::entry_changes asserts, in debug builds, that the BLAS of each static Instance it takes is ready.

From Renderer::upload, src/render/renderer.rs, after its first poll retires finished frames.

Who defers is the Chunk streamer. Around each Chunk's or Far proxy's load into the pools it calls MeshPool::defer_blases with true unless the frame is Settled, and with false after it, so a spawn's loads, which run in State::new outside the streamer, are never deferred, and the first frame's upload waits for them. A frame that streams calls MeshPool::poll_blases first, a poll that does not block, so the callbacks of whatever the GPU has finished run; a Settled frame calls MeshPool::wait_for_blases instead, so its upload waits for every BLAS awaiting, the deferred ones too. A loaded Chunk or Far proxy waits for placement until MeshPool::asset_blas_ready holds for each Mesh it names, which takes a few frames: the build, then the copy, each found finished by a later frame's poll. The streamer places the ready ones in the order loaded, and the Chunk counts as loaded only from that frame (the Chunk streamer, Arrivals); a Settled frame places its loads at once, after the wait its upload will make.

A frame that waits records the wait as its CPU stage blas_compaction, and the upload stage leaves that time out, so the bench can read the waits apart (The bench). Those frames are the first, for a spawn's Meshes, and a Settled frame whose loads bring Meshes new to the pool, as captures, Goldens and the bench's frames up to the end of its counter frames are. A frame that streams as a game does records no blas_compaction: its step runs inside upload. Both waits block the main thread, which records and submits the frame, for the whole of the GPU work submitted, the Textures' copies included, since a poll waits for every submission. Refitted BLASes take no part: they are never compacted, and how a frame orders their updates before the dynamic TLAS's build is the BLAS refit's.

5 · blas_bytes · compacted_blas_fraction

Counting bytes

wgpu keeps an acceleration structure's size to itself, so the engine asks the driver the same question wgpu-core asks when it creates one, through wgpu-hal, and counts that answer; only a compacted BLAS's size, which neither wgpu-core nor wgpu-hal gives back, stays an estimate: a fraction of its built size measured once on each kind of adapter.

blas_bytes and tlas_bytes both end in hal_built_bytes, tried on each backend the build has: Metal on Apple targets, Vulkan on Windows, Linux, Android and FreeBSD, DX12 on Windows. Each returns None on a device of another backend, so the one the device runs on answers.

The body of hal_built_bytes, src/render/acceleration_structures.rs; the elided lines give the triangles' indices, a transform only under USE_TRANSFORM, as wgpu-core gives one, and an Instance of zeros.

The geometry it describes is wgpu-core's own: zero first vertex and zero stride, a buffer named in place of wgpu-core's zero buffer, and for a TLAS one Instances entry of its capacity. Metal's query panics without a buffer there, so a caller passes input: the Mesh pool its vertex Arena, the GPU memory ledger a 64-byte buffer it creates for the query and drops at once. A TLAS adds wgpu-core's buffer of its Instances, a record per slot and at least one, each as long as wgpu-hal's encoding of an Instance: 72 bytes on Metal, 64 on Vulkan and DX12.

/// The fraction of its built bytes a compacted BLAS keeps on `adapter`, as
/// measured there: an estimate, since wgpu-core keeps the compacted size it
/// reads crate-private [ref:wgpu-30-blas-compacted-size-private], and reading
/// it again takes a query recorded through wgpu-hal outside wgpu's tracking
/// and another wait. NVIDIA's on an NVIDIA GPU, on any backend; lavapipe's on
/// any other Vulkan adapter, software or not; and the M4 Pro's on any other,
/// as the Budgets' reference machine (ADR 0013).
pub fn compacted_blas_fraction(adapter: &wgpu::AdapterInfo) -> f64 {
    if adapter.vendor == NVIDIA_VENDOR {
        // The RTX 2070 SUPER on Vulkan (NVIDIA 621.01), bytes a triangle by
        // wgpu's allocator report (`docs/performance.md`, Measurements
        // behind the code).
        29.2 / 70.7
    } else if adapter.backend == wgpu::Backend::Vulkan {
        // lavapipe (Mesa 25.2.8) leaves a compacted BLAS as it was built
        // (`docs/research/source-audit.md`, lavapipe's figures).
        1.0
    } else {
        // The M4 Pro on Metal, bytes a triangle by `currentAllocatedSize`
        // (`docs/research/global-illumination-and-lighting.md`).
        45.5 / 94.0
    }
}

compacted_blas_fraction, src/render/acceleration_structures.rs.

fn charge_blases(&mut self) {
    let compacted_bytes =
        (self.compacted_blas_bytes as f64 * self.compacted_blas_fraction).round() as u64;
    let bytes = compacted_bytes + self.uncompacted_blas_bytes;
    self.blas_charge
        .set(GpuMemoryKind::AccelerationStructures, bytes);
}

MeshPool::charge_blases, src/assets/pools.rs.

The Mesh pool keeps two sums of built bytes, compacted and not, and its one charge on the ledger counts the compacted sum at the adapter's fraction, rounded to a whole byte, plus the other. The fraction is picked once, from the adapter, when the ledger is created: an NVIDIA GPU, on Vulkan or DX12, gets the RTX 2070 SUPER's; any other Vulkan adapter gets lavapipe's, whose compaction leaves a BLAS as large as it was; every other adapter, as on Metal, gets the Apple M4 Pro's, the reference machine of ADR 0013. The vendor test reads the PCI vendor ID, which Vulkan and DXGI both report. Each TLAS is counted where it is created, through GpuMemory::create_tlas, at tlas_bytes.

Frame stats carry the acceleration structures' kind and add it into gpu_memory_bytes. For scale, pbr-sweep's sphere, one Mesh of 2,208 triangles shared by every sphere, is built at 207,424 bytes on the M4 Pro and counted at 100,402 once compacted.

8 · ADRs 0013, 0016, 0017, 0020

Why this way

A BLAS per Mesh, at load. ADR 0020 gives each Mesh rays trace a BLAS at load, compacted unless it is loaded to be refitted or rebuilt each frame, and places it through TLAS entries, one per Instance: a Mesh's triangles are built into one structure however many Instances share it, as helmet's and pbr-sweep's do.

LOD 0 alone. ADR 0020 builds every BLAS from its Mesh's LOD 0, a refitted Mesh's included, whichever LOD the main pass draws, so a LOD switch changes no BLAS and starts no static TLAS build; the index Arena, which only BLAS builds and refits read, holds LOD 0's indices alone.

Built from the Arenas in place. ADR 0017 keeps geometry in fixed Arenas that a Pool sub-allocates; the build reads the Mesh's ranges there, so the geometry exists once on the GPU and no staging copy is kept for it. Keeping the index stream only for traced Meshes leaves the index Arena to the Meshes that need it.

No BLAS for a bent Mesh drawn alone. Its BLAS, built from its rest shape, would cast another shape's shadow; the default crowd form casts the figures' shadows through rigid proxies instead, and the refitted form updates a BLAS each frame, which a compacted BLAS cannot be.

Compaction. A BLAS built once is traced for the rest of the run, so a one-time copy at load buys back over half its memory on the M4 Pro and on NVIDIA, the adapters Budgets and comparisons are judged on.

Ordered by the CPU, not on the GPU. Ordering the copies before the TLAS builds on the GPU would need wgpu to record a barrier after the copy, which wgpu-core 30.0.2 does not on any backend, or Metal shared events through wgpu-hal, the route the per-frame refit takes; a wgpu version that orders the copy is a dependency change and the owner's call. So the CPU orders them: the main thread, the one thread that submits and polls under ADR 0016, either waits or holds the Instances back until it has seen the copy finish.

Deferred for a streamed load, waited for otherwise. A wait blocks the main thread for all the GPU work submitted, which a frame that streams Meshes in cannot pay every time it loads; deferring trades it for a few frames before the load is placed, while its Chunk counts as not yet loaded. A spawn's loads keep the wait, so the first frame's Meshes are traced from that frame, and a Settled frame keeps it, so captures, Goldens and the bench's counter frames show the same whatever the GPU's timing.

The driver's size, not a measured rate. ADR 0013's GPU memory Budget and ADR 0017's split of it by kind need acceleration structures counted, and wgpu 30 keeps the sizes it creates them at to itself. wgpu-hal answers the same question wgpu-core asks, so asking it as wgpu-core does counts each structure at the size it is created at, on any adapter, where bytes per triangle and per slot measured on three adapters counted every other adapter by one of theirs.

A compacted size estimated. wgpu-core reads a compacted BLAS's size back into its own buffer and keeps it crate-private. wgpu-hal's command encoder could read it again, but only through commands recorded outside wgpu's tracking, with their own barriers on each backend and another wait on the GPU; a new dependency was ruled out. So the built size, which is exact, is scaled by the compaction measured on each kind of adapter.

9

Limits

A CPU wait for a spawn and for a Settled frame's loads. The upload of the first frame, and of each Settled frame whose loads bring Meshes new to the pool, blocks the main thread twice for all the GPU work submitted, until wgpu orders the copy on every backend. A window renders no Settled frame, so its only wait is the first frame's.

A streamed load placed late. A streamed Chunk's or Far proxy's Instances are not placed until every Mesh it names has its BLAS built and its copy finished, which takes a few frames; until then the Chunk counts as not loaded, so Late Chunks, a Fast travel's hold and the frames until traced count from its placement.

LOD 0 traced. Rays trace LOD 0 wherever a coarser LOD is drawn, so a far Instance's shadow can hold detail its drawn shape has dropped.

Compaction estimated, by kind of adapter. A compacted BLAS counts its built size at a fraction measured on the M4 Pro, the RTX 2070 SUPER or lavapipe: an AMD or Intel GPU on Vulkan is counted with lavapipe's, which counts no saving, and any adapter neither NVIDIA nor on Vulkan with the M4 Pro's.

Sizes, not allocations. The count is the size the driver asks for; what its allocator rounds that up to, or the scratch each build takes and returns, is not counted.

Compaction can fail. One that is not ready after its build keeps its built size, counted as built, with a warning.

Opaque only. No triangle has an alpha test, so a cutout Material would cast a solid shadow.

Freed only for room. MeshPool::free drops a Mesh's BLAS and gives back its bytes, and it refuses a refitted Mesh, whose refit scratch holds a region per refitted BLAS in load order. Outside the tests, only a load refused for room, the Mesh pool's own or the Material pool's, frees one: an unused shared Mesh, least recently used first (MeshPool::free_least_recently_used), which a refitted Mesh never is.

One build per Mesh. Each Mesh's build is its own build_acceleration_structures call on the load encoder; builds are not batched across Meshes.

History

The Mesh pool gained a compacted BLAS per Mesh on 2026-10-20, with the memory estimate, measured then on the M4 Pro and lavapipe and since 2026-10-26 chosen by adapter, with an RTX 2070 SUPER's figures for NVIDIA. The wait for the compaction's copies followed on 2026-10-23, once a test that traced a triangle sometimes missed it under load and the race proved to be the engine's own. The crowd brought the uses: a Mesh drawn alone with no BLAS, and a shadow proxy traced alone, then on 2026-10-26 the refitted Mesh, built to allow updates and never compacted. Since 2026-11-06 each BLAS and TLAS is counted at the size its driver gives through wgpu-hal, and only compaction is estimated; on 2026-11-08 the compaction's wait became a CPU stage of its own. With LOD chains cooked into the Mesh, the BLAS and the index Arena kept LOD 0 from 2026-11-14 while every LOD's Meshlets load; from 2026-11-15 a streamed load's BLASes were deferred and its Instances placed once they are ready, leaving the wait to a spawn and to Settled frames; and on 2026-11-20 Far proxies, streamed since 2026-11-16 and drawn since 2026-11-18, were traced from BLASes of their own use. The race behind the wait is on Waiting on the GPU. This page describes the mechanism as it is.
