The Probe update

A compute pass that traces, each frame, a fixed count of rays from a share of a Cascade's Probes through the Ray scene, and two render passes that blend what the rays found into those Probes' irradiance and depth moments: so far the sky where a ray escapes and nothing where it hits, which is sky light with visibility.

Describes main at ed1139a8 (2026-11-28), with the probes Render switch on; it ships off. A change to the update rewrites this page and moves the commit; nothing is appended. Read first: The shadow mask pass for the other pass that traces the Ray scene, Camera-relative placement for the Anchor and offset a Probe's place is composed from, Light units for the lux a Probe holds.

Interface

Runs
In every frame, with the probes Render switch on: the last passes recorded into the frame's encoder, after the tonemapping pass.
Reads
The Ray scene: the static and the dynamic TLAS, through RAY_SCENE; the camera uniform, for the TLAS's Anchor and the dynamic TLAS's box; the light uniform, for the sky; the update's own uniform, the Cascade's place and the frame's first level; the 128 rays' directions.
Writes
What each ray found, a buffer of 262,144 entries; then, through each render pass's blend, the irradiance and the depth moments of the frame's two levels of Probes.
Dispatches
One, trace_probe_rays: 2 × 2,048 workgroups of 64 invocations, a ray each. Then two draws of one triangle, blend_irradiance and blend_depth_moments, each over its texture's two levels.
Bind groups
The trace: group 2, RAY_SCENE; group 3, PROBE_TRACE_INPUTS. The blends: group 3, PROBE_BLEND_INPUTS.
Shader
probe_trace.wgsl after the common part and ray_scene.wgsl, as the module PROBE_TRACE; probe_blend.wgsl after the common part, hdr.wgsl, probes.wgsl and full_screen.wgsl, as PROBE_BLEND.
Counted
probe_update in GPU time, one Timed pass from the trace's start to the last blend's end; probes_updated and probe_rays_traced in Frame stats; the Cascade, the uniform, the directions and the rays' results in GPU memory under probes; the uniform, each frame, in uploaded_bytes.

Where it sits in the frame

The update reads nothing the frame's other passes write, only the Ray scene and the uniforms, so it is recorded last, after the tonemapping pass, outside ADR 0019's gate; whatever reads the Probes reads them as the frame before left them.

Renderer::render, src/render/renderer.rs.

It is three passes of wgpu, a compute pass and two render passes, and one Timed pass, probe_update: the compute pass writes the start timestamp and the second render pass the end, as PassQueries::span hands them out. The bench lists the pass only where its Renderer's switches can run it (RenderSwitches::can_time), so a Baseline recorded with the Probes off holds no entry for it.

2 · Cascade · ProbeUpdatePass::frame_upload

The Cascade and its levels

One Cascade of 32 × 16 × 32 Probes, 1 m apart, centred where the camera of the first frame stood. Each frame updates two of its 16 levels along Y, the next two each frame, so every Probe is updated once in 8 frames.

Cascade::new in src/render/probes.rs creates the store: each texture one layer, a Probe's map at its Z down the texture and its X across it, the levels side by side. Irradiance is 8 × 8 texels of Rgba16Float a Probe, depth moments 16 × 16 of Rg16Float, both now render attachments too, since the blends write them.

pub fn frame_upload(&mut self, camera: &CameraUniform) -> (&wgpu::Buffer, &[u8]) {
    if !self.placed {
        self.uniform.cascade_anchor = camera.anchor;
        self.uniform.cascade_offset = camera.offset;
        self.placed = true;
    }
    self.uniform.first_level =
        (self.updates % FRAMES_PER_CYCLE) as u32 * PROBE_LEVELS_PER_FRAME;
    (&self.uniform_buffer, bytemuck::bytes_of(&self.uniform))
}

ProbeUpdatePass::frame_upload, src/render/probe_update_pass.rs, called by Renderer::upload, which writes the 32 bytes through frame staging with the frame's other uploads.

The place is the camera's own Anchor and offset, as the camera uniform holds them, so it is never an f32 World position. PROBE_LEVELS_PER_FRAME divides the 16 levels, so a frame's first level is a multiple of it, which the blends read a Probe's rays by. With the Probes on, frame staging's bound grows by the uniform, and the load staging's share of the staging Budget gives up as much (RenderCapacities::load_bytes_per_frame).

3 · trace_probe_rays · first_intersection

The trace

An invocation per ray: it composes its Probe's place into the Ray scene's frame, takes its ray's direction, asks first_intersection, the one tracing function both passes that trace share, for the nearest hit, and writes the sky's radiance where the ray escapes, black where it hits, and the distance.

@compute @workgroup_size(PROBE_TRACE_WORKGROUP_SIZE)
fn trace_probe_rays(@builtin(global_invocation_id) invocation: vec3<u32>) {
    let ray = invocation.x;
    let slot = invocation.y;
    let probes_per_level = PROBE_COUNTS.x * PROBE_COUNTS.z;
    let probe = vec3<u32>(
        slot % PROBE_COUNTS.x,
        probe_update.first_level + slot / probes_per_level,
        slot / PROBE_COUNTS.x % PROBE_COUNTS.z
    );
    let centred = (vec3<f32>(probe) - 0.5 * vec3<f32>(PROBE_COUNTS - 1u)) * PROBE_SPACING_METRES;
    let origin = camera_relative_position(
        probe_update.cascade_anchor,
        probe_update.cascade_offset,
        camera.tlas_anchor,
        vec3<f32>(0.0),
        centred
    );
    let direction = probe_ray_directions[ray].xyz;
    let hit = first_intersection(0u, 0xffu, origin, direction, 0.0, UNBOUNDED_RAY_DISTANCE);
    let missed = hit.kind == RAY_QUERY_INTERSECTION_NONE;
    let radiance = select(vec3<f32>(0.0), light.ambient_illuminance.rgb / PI, missed);
    let distance = select(min(hit.t, PROBE_DEPTH_LIMIT_METRES), PROBE_DEPTH_LIMIT_METRES, missed);
    probe_rays[slot * PROBE_RAYS + ray] = vec4<f32>(radiance, distance);
}

trace_probe_rays, src/render/shaders/probe_trace.wgsl. PROBE_COUNTS, PROBE_SPACING_METRES, PROBE_RAYS and the workgroup size are declared into the WGSL from Rust.

The origin. camera_relative_position composes the Probe as the shadow mask pass composes a surface point: the Cascade's Anchor less the TLAS's, exact in integers, plus the offsets, in the frame whose origin is the corner of the static TLAS's Anchor. When the static TLAS re-anchors, the next frame composes the same Probe into the new frame.

The directions. probe_ray_directions in Rust lays 128 directions along a Fibonacci spiral about Y, evenly over the sphere, and the update creates them once into a uniform buffer the trace and the blends both read. Every update traces the same 128.

One tracing function. first_intersection, in ray_scene.wgsl, traces the static TLAS, then the dynamic TLAS unless it is empty or the ray misses the box that holds it before the static hit. Flags of 0 ask for the nearest hit, which a probe ray wants for its distance; the shadow mask pass asks the same function for the nearest, then any. Its mask takes every instance bit, so a probe ray sees every triangle, Thin Primitives included, as ADR 0020 has it see what a shadow ray sees.

What a ray finds. The sky is the scene's ambient illuminance over π, the same radiance from every direction, so a Probe with nothing around it holds the ambient illuminance from every side. A hit is black for now. A distance is capped at PROBE_DEPTH_LIMIT_METRES, twice the spacing, past a cell's diagonal, the farthest a point a Probe lights lies from it; a miss reads the cap.

4 · blend_irradiance · blend_depth_moments

The blends

On the Capability floor neither fp16 format takes read-write storage, so the blend is the render pass's: a fragment per texel of the frame's levels computes the texel's new value from its Probe's rays, and the blend keeps the hysteresis of the old one, set as the pass's blend constant.

irradiance(n) = π · Σ max(0, n · ωᵢ) Lᵢ / Σ max(0, n · ωᵢ) × 2⁻⁴ moments(n) = Σ wᵢ (dᵢ, dᵢ²) / Σ wᵢ, wᵢ = max(0, n · ωᵢ)¹⁶ stored = (1 − α) · new + α · old, α = 0 in the first 8 frames, 0.5 after

n is the texel's direction, ωᵢ ray i's, Lᵢ its radiance and dᵢ its distance.

fn probe_texel(position: vec2<f32>, side_texels: u32) -> ProbeTexel {
    let texel = vec2<u32>(position);
    let column = texel.x / side_texels;
    let level = column / PROBE_COUNTS.x;
    let slot = ((level % PROBE_LEVELS_PER_FRAME) * PROBE_COUNTS.z + texel.y / side_texels) * PROBE_COUNTS.x
        + column % PROBE_COUNTS.x;
    return ProbeTexel(slot * PROBE_RAYS, probe_map_direction(texel % side_texels, side_texels));
}

// Each ray weighs by its cosine to the texel's direction [ref:majercik-2019-ddgi-probe-update].
@fragment
fn blend_irradiance(@builtin(position) position: vec4<f32>) -> @location(0) vec4<f32> {
    let texel = probe_texel(position.xy, PROBE_IRRADIANCE_SIDE_TEXELS);
    var weighted = vec3<f32>(0.0);
    var weight_sum = 0.0;
    for (var ray = 0u; ray < PROBE_RAYS; ray++) {
        let weight = max(dot(texel.direction, probe_ray_directions[ray].xyz), 0.0);
        weighted += weight * probe_rays[texel.first_ray + ray].rgb;
        weight_sum += weight;
    }
    let irradiance = PI * PROBE_LIGHT_SCALE * weighted / max(weight_sum, 1e-6);
    return vec4<f32>(min(irradiance, vec3<f32>(LARGEST_HALF)), 0.0);
}

probe_texel and blend_irradiance, src/render/shaders/probe_blend.wgsl; blend_depth_moments beside them loops alike with the cos¹⁶ weight. probe_map_direction, in probes.wgsl, decodes the texel's centre through the octahedral map: +Z at the map's centre, −Z at its corners, ±X at the middles of its right and left edges, ±Y of its bottom and top.

A triangle over the levels. Each render pass loads its texture, sets the viewport to the frame's two levels and draws vs_full_screen's one triangle over it, so only those texels run a fragment; a fragment's position, in the texture's texels, names its Probe and its texel.

Irradiance. The cosine-weighted mean of the rays' radiance, times π, is the irradiance a surface facing the texel's direction would receive: under an open sky, the ambient illuminance. It is stored in lux times PROBE_LIGHT_SCALE, 2⁻⁴, and clamped to fp16's largest value, so fp16 holds ten times the sun's illuminance and the Probes are never pre-exposed by the frame's exposure (ADR 0023). A capture reads it back divided by the scale.

Depth moments. The mean distance and squared distance of the rays near the texel's direction, weighted by cos¹⁶, which falls to half its peak 16.8° off the texel's direction, about the 18° between neighbouring rays of 128. A plane d below a Probe reads about 17/16 d.

The hysteresis. The pipelines blend with OneMinusConstant for the new value and Constant for the old; the pass sets the constant to 0 for the first 8 frames, a cycle, so the first update of each Probe fills it, and to PROBE_HYSTERESIS_PER_UPDATE, 0.5, after. An update every 8 frames at 0.5 is about 0.917 a frame, within the 0.85 to 0.98 DDGI sets; 32 frames take 15/16 of a step.

Why this way

A render pass's blend. The store's formats take a render pass's blend on the Capability floor but no read-write storage (ADR 0021), so a compute pass could only blend into a second copy of each texture. One render pass reaches every Probe of a texture, and the viewport limits it to the frame's levels.

One tracing function. ADR 0020 has shadow rays and probe rays read the same Ray scene. Tracing it through first_intersection alone keeps the static-then-dynamic order, the empty-TLAS skip and the box test in one place, so the two passes cannot drift apart; the second pass that binds the TLAS adds wgpu-core's walk of its dependencies at submit, which the frame pays once more.

A share of the levels each frame. A fragment of a blend loops over its Probe's 128 rays, so a frame that updated every Probe would run 128 iterations for each of the Cascade's 5.2 million texels; two levels a frame run an eighth of that, and every Probe is still updated within 8 frames.

Fixed directions. The same 128 directions each update converge a still scene to one value, so nothing flickers while nothing moves. DDGI rotates its spiral stochastically, trading that for noise the hysteresis averages; the deviation is recorded in docs/audit/deviations.md.

Light that is not pre-exposed. house keys its exposure along its camera path, so a Probe pre-exposed by the frame's exposure would change as the camera moves. A fixed scale of 2⁻⁴ lets fp16 hold ten times direct sun at the top and about 0.001 lx at its smallest normal value (ADR 0023).

8

Limits

A hit is black. No Bounce colour, sun or point light lights a hit yet, so a Probe holds the sky and how much of it is hidden, no bounced light.

One Cascade that stays. The Cascade stands where the first frame's camera stood and does not follow it, and nothing reads the Probes yet.

No gutter. A Probe's maps sit edge to edge, without the one-texel border DDGI copies around each, which bilinear sampling across a map's edge would need.

A biased depth. The cos¹⁶ lobe reads a plane about 1/16 farther than it is; a lobe that narrow needs more or rotated rays.

The span's end. The Timed pass ends where the depth moments' blend ends. The irradiance blend, recorded before it, shares nothing it writes, so Metal can run the two side by side; with a quarter of its fragments it is expected to end first, which nothing guarantees.

The first frame. A frame before the static TLAS is first bound traces an empty static TLAS, so the levels it fills hold the sky until their next updates take it out by the hysteresis.

History

The Cascade's store came first, created and counted but filled by nothing; the update then gave it its first rays, the sky with visibility, and with it the Ray scene's tracing became one function the shadow mask pass shares. This page describes the update as it is.
