Praxis · the frame · src/render/culling_pass.rs

The culling pass

A compute pass, run twice a frame, that builds the frame's draw from the Instances: a Meshlet record per Meshlet and a packed index per triangle corner of each Instance it draws, in slot order, which the depth and lit passes draw with one indirect call each. Phase one draws the Instances in view that were visible the frame before; phase two, after the depth pyramid, the others in view that the pyramid does not hide, and it records which Instances are visible for the next frame.

Describes main at fbae12f4 (2026-11-04). A change to the pass rewrites this page and moves the commit; nothing is appended. Read first: The Instance buffer for the slots the pass reads, The depth pyramid pass for what phase two tests against.

Interface

Runs
Twice every frame: phase one first among the frame's passes after the dynamic TLAS's build and the bend pass, phase two between the depth pyramid pass and phase two's depth pass. With the culling Render switch off, which ships on, phase one draws every Instance in use and phase two draws none.
Reads
The Instance buffer and its slot count, the Mesh table, the Meshlets and their triangles, the camera uniform, each slot's visibility bit from the frame before, and in phase two the depth pyramid.
Writes
The frame's draw: the Meshlet records, the packed indices and FrameDraw, the draws' indirect arguments and counts; each slot's offsets; in phase two, each slot's visibility bit.
Dispatches
Four per phase, in one compute pass each: offset_slots, a workgroup per 256 slots; offset_blocks, one workgroup; append_records, an invocation per slot; append_triangles, a workgroup per Meshlet record, sized by indirect dispatch.
Bind groups
Group 0, the frame's camera; group 2, the scene geometry; group 3, FRAME_DRAW, the draw's buffers and the depth pyramid, in two copies that differ in the buffer bound as frame_draw.
Shader
src/render/shaders/culling.wgsl, after the common part; each phase's pipelines set the PHASE_TWO and CULLING overrides.
Counted
culling_phase_one and culling_phase_two in GPU time; instances_drawn, triangles_drawn, phase_two_triangles_drawn and instances_overflowed in counters, read back from FrameDraw; its buffers in GPU memory.

1 · src/render/renderer.rs

Where it sits in the frame

Frame data lists no draws. The GPU chooses what to draw: phase one before the depth pre-pass, from last frame's visibility, and phase two after the depth pyramid, from what phase one drew this frame.

The frame's passes with shadow rays on, in the order the GPU receives them

  1. dynamic TLAS build
  2. bend pass
  3. culling, phase one
  4. Froxel pass
  5. depth pre-pass
  6. depth pyramid pass
  7. culling, phase two
  8. phase two's depth pass
  9. shadow mask pass
  10. lit pass
  11. tonemapping pass

In a frame whose BLASes are refitted, the crowd's refit form on Metal, the commands up to the bend pass are submitted first, with the refits, and the dynamic TLAS's build follows them. The depth pre-pass draws phase one's Instances into depth, the depth pyramid pass reduces that depth, and phase two tests the rest against it. Phase two's own Instances then draw into depth in a pass of their own with shadow rays on, as Praxis ships, or at the start of the lit pass with them off; the lit pass shades both phases' at depth equal. The Froxel pass follows phase one so that ADR 0019's gate, timed from the start of phase one, counts the lights' culling.

Each phase records one compute pass. Phase one first clears FrameDraw; a frame with no slots in use dispatches nothing.

let slots = frame.instance_slot_count;
if slots > 0 {
    // Each slot's offsets are the sum of the earlier slots' Meshlet
    // records and packed indices: summed by block, then the blocks.
    pass.set_pipeline(&pipelines.offset_slots);
    pass.dispatch_workgroups(slots.div_ceil(SCAN_BLOCK_SIZE), 1, 1);
    pass.set_pipeline(&pipelines.offset_blocks);
    pass.dispatch_workgroups(1, 1, 1);
    // An invocation per slot.
    pass.set_pipeline(&pipelines.append_records);
    pass.dispatch_workgroups(slots.div_ceil(SCAN_BLOCK_SIZE), 1, 1);
    // A workgroup per Meshlet record the phase appends.
    pass.set_bind_group(FRAME_DRAW.index, &self.append_bind_group, &[]);
    pass.set_pipeline(&pipelines.append_triangles);
    pass.dispatch_workgroups_indirect(&self.buffers.frame_draw, APPEND_DISPATCH_OFFSET);
}

2 · FrameDraw · pack_index · DrawCapacity

The frame's draw

One indexed draw spans every Instance: each index packs a Meshlet record above six bits of vertex, and the record names the Instance's slot, the Meshlet and the Material to draw it with. The draw has no base vertex, so the vertex shader finds everything from the index.

The cooker cuts each Primitive into Meshlets of at most 64 vertices and 124 triangles; a Meshlet lists its vertices as indices into the vertex Arena and its triangles as three one-byte corners into that list, in cooked order. For each Instance it draws, the pass writes one record per Meshlet of its Mesh, with the Instance's own Material ID where its Renderable overrides its Mesh's Materials and the Meshlet's Primitive's otherwise, and one packed index per corner.

fn pack_index(record: u32, vertex: u32) -> u32 {
    return (record << MESHLET_VERTEX_BITS) | vertex;
}

common.wgsl. MESHLET_VERTEX_BITS is the base-2 logarithm of MESHLET_MAX_VERTICES, 64, declared from Rust: 6, which leaves 26 bits for the record. CullingPass::new asserts the record capacity stays below 226.

The vertex shader unpacks an index, reads its record, reads the Instance from the record's slot, finds the vertex through the Meshlet's list, pulls it from the vertex Arena and composes its position relative to the camera from the Anchors. Both buffers have fixed capacities, provisional until ADR 0013's split of the 8 GB Budget sizes them:

3 · offset_slots · offset_blocks · append_records · append_triangles

Four dispatches, in slot order

Every Instance's place in the draw follows from the slots' order and counts alone: a running sum over the slots gives each drawn Instance where its records and indices start, and only then are they written. The draw is the same from run to run, and the image with it.

offset_slots runs a workgroup per block of 256 slots, SCAN_BLOCK_SIZE. Each invocation decides whether its slot's Instance is drawn in this phase, takes the counts of its Mesh's Meshlet records and packed indices where it is, and joins a Hillis and Steele scan in workgroup memory, which gives each slot the sum of the counts before it in its block. A slot not drawn, freed or culled, takes NOT_DRAWN, all ones, past every capacity; the sums saturate there, so nothing past it can fit either. The block's total goes after every slot's entry.

fn exclusive_scan(invocation: u32, value: vec2<u32>) -> vec2<u32> {
    scan[invocation] = value;
    for (var stride = 1u; stride < SCAN_BLOCK_SIZE; stride *= 2u) {
        workgroupBarrier();
        var before = vec2<u32>(0u);
        if invocation >= stride {
            before = scan[invocation - stride];
        }
        workgroupBarrier();
        scan[invocation] = saturating_add(scan[invocation], before);
    }
    workgroupBarrier();
    var before = vec2<u32>(0u);
    if invocation > 0u {
        before = scan[invocation - 1u];
    }
    return before;
}

culling.wgsl.

offset_blocks runs one workgroup over the blocks' totals: at the Instance buffer's 219 slots, 2,048 blocks, 8 to an invocation, each loop bounded alike in every invocation so the scan's barriers stay in uniform control flow. It turns each block's total into the block's start, from where the phase starts: 0 in phase one, phase one's sums in phase two, which phase one's last invocation leaves in phase_two_offsets. It also sets the draw's instance count to 1, phase two's first index, the phase's range of records and append_triangles's dispatch.

append_records runs an invocation per slot. Each drawn Instance whose records and indices fit writes its records from its block's start plus its own offset, raises the draw's index count to its last index with an atomicMax, and counts itself drawn; one that does not fit counts itself overflowed.

append_triangles runs a workgroup of 32 invocations per record the phase appended, and writes the record's Meshlet's packed indices at the Instance's first index plus the Meshlet's triangles before it in the Mesh, adjacent invocations writing adjacent indices, each triangle's corners as cooked, so the draw rasterises as the cooked index stream does.

Atomics remain only where order cannot matter: the index count's atomicMax, the counts' atomicAdds and the visibility words' atomicOrs end at the same value whatever order invocations run in. Appending through a shared atomic count instead would place each Instance by when its workgroup arrived, and on the Apple M4 Pro, which triangles a draw holds before others changes the implicit derivatives some pixels sample their Textures with, so the image would differ from run to run (Metal quirks).

4 · clip_space_bounds · in_view_frustum

The frustum test

The test runs in clip space on the Mesh's bounds, a box composed relative to the camera as the vertices are. A plane's distance is linear there, so the box reaches furthest inside each plane by its centre's distance plus each half axis's, whole; a box is culled only where it lies wholly beyond one plane.

The view frustum is bounded by four side planes, −w ≤ x ≤ w and −w ≤ y ≤ w, and the near plane, z ≤ w. Under ADR 0015's reverse Z with no far plane every point past the near plane lands at z ≥ 0, so there is no sixth plane. clip_space_bounds composes the box's centre from the Instance's and the camera's Anchors with camera_relative_position, the function the vertex shader places vertices with (ADR 0014), and takes its three half axes, the Instance's rotation-scale columns times the box's half extents, into clip space as directions.

fn in_view_frustum(bounds: ClipBox) -> bool {
    let side_reach = side_plane_distances(bounds.centre)
        + abs(side_plane_distances(bounds.half_axes[0]))
        + abs(side_plane_distances(bounds.half_axes[1]))
        + abs(side_plane_distances(bounds.half_axes[2]));
    let near_reach = near_plane_distance(bounds.centre)
        + abs(near_plane_distance(bounds.half_axes[0]))
        + abs(near_plane_distance(bounds.half_axes[1]))
        + abs(near_plane_distance(bounds.half_axes[2]));
    return all(side_reach >= vec4<f32>(0.0)) && near_reach >= 0.0;
}

culling.wgsl. side_plane_distances returns w + x, w − x, w + y and w − y at once; near_plane_distance returns w − z.

The five planes are tested with neither a branch nor a loop. The culling switch reaches WGSL as the CULLING override, which each pipeline sets from the Renderer's switches, so the shader compiles with it fixed and the shipping pipeline pays for no branch.

5 · offset_slots · visible_before

Two phases

Frames are alike: most Instances visible in one frame are still visible in the next. Phase one draws those, the depth they leave becomes the depth pyramid, and phase two tests every Instance in view against it, draws the visible ones phase one did not, and records visibility for the next frame.

visible = !CULLING || in_view_frustum(bounds);
if PHASE_TWO {
    // Behind what phase one drew, it is not visible.
    visible = visible && !(CULLING && occluded(bounds));
    // Phase one's offsets for the slot, before this phase's replace them.
    drawn = CULLING && visible && all(instance_offsets[slot] == NOT_DRAWN);
} else {
    drawn = visible && (!CULLING || visible_before(slot));
}
// A shadow proxy's Mesh has no Meshlets: rays trace it, no pass
// draws it.
drawn = drawn && mesh.meshlet_count != 0u;

offset_slots, culling.wgsl: each slot's decision.

Phase two tests the Instances phase one drew too, so the bits record what is visible now: an Instance that became hidden is drawn by phase one one last time, loses its bit, and leaves phase one the frame after. It gathers each block's bits with workgroup atomicOrs and writes the block's eight words once. Phase one's offsets for a slot, read before phase two writes its own, tell phase two which Instances phase one drew.

The image stays right. An Instance that shows this frame is either drawn by phase one, or tested by phase two against depth made only of Instances drawn this frame, and drawn if any part of it could be nearer. One that phase one draws although now hidden costs work, and the depth test hides it. The bits start zeroed, so the first frame's phase one draws nothing, the pyramid is all far plane, and phase two draws everything in view. After a camera cut last frame's bits predict little, and phase two draws most of the view.

Phase two's indices follow phase one's in the same buffers, from phase one's totals, so the draw at offset 0 grows across the phases: the depth pre-pass draws it as phase one leaves it, and the lit pass draws it with both. phase_two_draw covers phase two's indices alone, for the depth draw of phase two's Instances. With culling off, phase one draws every Instance in use and phase two draws none and sets the bit of every Instance in use.

6 · occluded

The occlusion test

A box in view is occluded where even its nearest point is farther than the farthest depth phase one drew anywhere its screen rectangle could cover: the minimum of four texels of the depth pyramid, at the level where the rectangle spans at most two per axis. Every step errs towards drawing.

Eight corners, moved nearer. For a box in front of the camera, depth, z over w, and reach across the screen are both extreme at a corner, so the test projects the eight corners and keeps the greatest depth, the box's nearest point under reverse Z. Each corner first moves towards the camera in z and w by 1/16384 of the summed magnitudes of that coordinate over the box's centre and half axes, OCCLUSION_ROUNDING, plus 0.1 mm, COMPOSITION_ERROR, past ADR 0014's worst camera-relative error for the box's composition and the vertices' each, so f32 rounding cannot make the box look farther than its drawn triangles. A box with a corner at or behind the camera's plane is never occluded.

A rectangle grown by a pixel. The corners' x and y over w bound a screen rectangle, which the test takes into texture coordinates, rows top first, and grows by half a level-0 texel, a pixel, past where rasterisation rounds vertices, so every sample a covered pixel holds lies in the texels read.

The level, and its size computed. With e the rectangle's larger side in level-0 texels, the level is min(⌈log2 max(e, 1)⌉, levels − 1), where it spans at most two texels per axis. The level's size is level 0's shifted down, at least 1, as a mip chain halves, rather than queried: lavapipe answers a size query whose level varies across a workgroup's invocations with one invocation's answer. If rounding leaves the rectangle over more than two texels, the box is not occluded.

let size = max(level_zero_texels >> vec2<u32>(level), vec2<u32>(1u));
let first = min(vec2<u32>(first_coordinates * vec2<f32>(size)), size - 1u);
let last = min(vec2<u32>(last_coordinates * vec2<f32>(size)), size - 1u);
if any(last > first + 1u) {
    return false;
}
let farthest = min(
    min(textureLoad(depth_pyramid, first, level).r, textureLoad(depth_pyramid, vec2<u32>(last.x, first.y), level).r),
    min(textureLoad(depth_pyramid, vec2<u32>(first.x, last.y), level).r, textureLoad(depth_pyramid, last, level).r)
);
return nearest_depth < farthest;

The end of occluded, culling.wgsl.

Four texels, compared. The test loads the corners of the block of one or two by one or two texels, takes their minimum, the farthest depth anything drawn reaches there, and culls the box where its nearest depth is less. The pyramid keeps the farthest depth over every sample beneath a texel, the nearest corner stands for the whole box, the margins move it nearer and the rectangle grows: each makes the test keep Instances, never drop a visible one.

7 · offset_blocks · frame_draw_bind_groups

The indirect dispatch and its stand-in

Only the GPU knows, mid-frame, how many records a phase appends, so offset_blocks writes append_triangles's workgroup counts into FrameDraw and the dispatch reads them from there. wgpu checks a dispatch's bindings and its argument buffer as one usage scope, so that dispatch binds a 72-byte stand-in where FrameDraw would go.

A dispatch may launch at most 65,535 workgroups along each dimension, wgpu's default, which the Capability floor takes as its own (ADR 0021); CullingPass::new asserts the device allows it. The draw holds 220 records, so they are laid out in rows:

let records = appended.y - appended.x;
// At least one row, so no records dispatch no workgroups.
let rows = max((records + MAX_WORKGROUPS_PER_DIMENSION - 1u) / MAX_WORKGROUPS_PER_DIMENSION, 1u);
frame_draw.append_dispatch = DispatchIndirect((records + rows - 1u) / rows, rows, 1u);

The end of offset_blocks, culling.wgsl.

Each workgroup of append_triangles finds its record from its position in the rows and returns at once past the phase's last, since x × y can exceed the count. Without the max, zero records would divide by zero rows.

The usage scope is why the stand-in exists. In wgpu-core 30, a dispatch's scope merges every active bind group's uses, then adds the indirect buffer as INDIRECT; a buffer that a bound group writes holds a use that excludes every other, so a dispatch whose arguments are in it fails validation. Group 3 holds FrameDraw read-write besides the offsets, records, indices, visibility and pyramid that append_triangles needs, so the pass builds two copies of group 3 from one layout: the second binds a stand-in buffer, never read, as frame_draw. append_triangles reads its phase's record range from instance_offsets instead, at APPENDED_RECORDS, past every slot's and block's offsets, where offset_blocks put a copy. One function builds both groups, at creation and after every resize, since they hold the depth pyramid.

8 · fits · src/render/readback.rs

Overflow, and what Frame stats count

A phase whose Instances need more records or indices than the draw holds draws those that fit, in slot order, and counts the rest as overflowed; the warning comes from that read-back count, not from the CPU's sums, so culled Instances never warn.

fits checks an Instance's counts against both buffers from its first offsets. Since the offsets are a running sum, once one Instance does not fit, none after it does: the draw ends at the last Instance that fits, and every index before it is written. append_records still writes the records short of the buffer's end of an Instance that does not fit, so every record append_triangles reads is written, and that dispatch skips the indices of any record whose Instance does not fit. Once phase one fills the draw, phase two's Instances count as overflowed.

The GPU stats readback copies FrameDraw each frame into a ring of mapped buffers, a few frames late, and Frame stats report instances_drawn, triangles_drawn, the draw's index count over 3, phase_two_triangles_drawn, the same of phase two's draw, and instances_overflowed. It warns once when a frame read back overflowed, and again only after one has room for all. Frame stats carry no count of Instances in use, so a frame's culled Instances are those in use less the drawn, the overflowed and the shadow proxies, whose Meshes have no Meshlets.

11 · ADRs 0013, 0014, 0015, 0019, 0021

Why this way

The GPU builds the draw. A draw call recorded per Primitive per Instance grows the CPU's work with the scene; ADR 0019 moves the choice to a compute pass whose output one draw_indexed_indirect per pipeline and phase draws, a native call on every backend. Count draws are no alternative: wgpu's Metal backend leaves them empty, and it runs a multi-draw as a CPU loop of single draws.

Slot order, not atomic order. A scan costs two extra dispatches over appending through an atomic counter, and buys a draw that repeats from run to run, so captures are comparable and Goldens hold on the Apple M4 Pro. Wihlidal writes surviving indices in wavefront creation order where order matters, as for translucent rendering; here the reason is the derivatives.

Two phases. Testing against last frame's depth alone leaves newly visible geometry missing for a frame; testing against this frame's needs depth first. Drawing last frame's visible set, building the pyramid from it and testing the rest, as Haar and Aaltonen and later Nanite do, culls in one frame what the frame's own depth hides and fails only under extreme visibility changes, which then cull less and still render right.

Instances, not Meshlets. A test of each Meshlet's bounds against the frustum and the pyramid, and of its normal cone, was built and measured on town: it dropped 4.9% of the triangles and left the gate unchanged, since 71% of its slots draw a Mesh of one Meshlet whose box is the Mesh's and whose cone faces every way. ADR 0019 records that culling tests Instances and that tests per Meshlet wait for a profile that shows the pass raster-bound; Metal quirks keeps what the prototype found of fast math across entry points.

A workgroup per record, 32 wide. The earlier form launched a workgroup of 124 invocations, one per triangle, for every slot in use, which on town spent most of phase two's time appending almost nothing. Launching one per appended record, by indirect dispatch, removed it; 32 is an Apple SIMD group. Spreading each block's records over a workgroup read 55 µs on helmet but cost town about 180 µs. Copying the dispatch's arguments out between two passes, in place of the stand-in, cost about 50 heap allocations a frame.

Visibility in a buffer of its own. The bits are state kept between frames, the rest of group 3 one frame's scratch; folding the bits into the offsets would have saved a binding. They cost the Capability floor its ninth storage buffer per compute stage.

Conservative throughout. Each test is exact for what it can prove and errs towards drawing: the frustum test plane by plane, the occlusion test through the pyramid's farthest depth, nearest corners, rounding margins and a grown rectangle. A wrong cull removes something visible; a missed one costs a little drawing, which the depth test then hides.

12

Limits

Boxes past a frustum's corner. A box outside two planes near where they meet, but wholly beyond neither, is kept and drawn.

Boxes at the camera. A box with a corner at or behind the camera's plane is never occluded, however much hides it.

A fixed draw. The draw holds 225 indices and 220 records whatever the frame needs; past either, the Instances after the last that fits are not drawn that frame, whatever their distance. The capacities are provisional until the GPU memory Budget is split.

Phase order within the draw. An Instance phase two draws sits after all of phase one's for that frame; one slot order across both phases would need a third index list or gaps of degenerate triangles.

Composed twice. The pass composes each box relative to the camera for its tests, and the vertex shader composes every vertex again; handing the composed transform over would need a per-Instance buffer, another storage binding.

History

The pass took its form over the third milestone: one indirect draw of every Instance in slot order, then the frustum test and the switch that turns culling off, then the two phases and the occlusion test against the depth pyramid. A later change split each phase's append into a record per slot and a workgroup per record by indirect dispatch, which grew FrameDraw from 56 to 72 bytes, and a test of each Meshlet was measured and kept out. The Metal paragraphs of that development, slot order against atomic order and fast math across entry points, are on Metal quirks. This page describes the pass as it is.
