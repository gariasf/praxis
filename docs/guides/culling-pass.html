Praxis · the frame · src/render/culling_pass.rs

The culling pass

A compute pass, run in two phases a frame, that builds the frame's draw from the Instances: of each Instance it draws, it selects a LOD and writes a Meshlet record per Meshlet of that LOD and a packed index per triangle corner, in slot order within each phase, which the depth and lit passes draw with one indirect call per pipeline and phase, the lit pass drawing both phases' ordinary indices in one. Phase one draws the Instances in view that were visible the frame before; phase two, after the depth pyramid, the others in view that the pyramid does not hide, and it records which Instances are visible for the next frame. The indices of Thin Primitives and of small Instances go apart, at the end of the same buffer, for the pipelines that write their coverage.

Describes main at 62052fe8 (2026-11-21), with its capacities as the checked-in Budgets leave them. A change to the pass rewrites this page and moves the commit; nothing is appended. Read first: The Instance buffer for the slots the pass reads, The depth pyramid pass for what phase two tests against, The depth pre-pass for how the draws it writes are drawn and widened.

Interface

Runs
Twice every frame, each phase as two compute passes: phase one after the dynamic TLAS's build, the bend pass and, in a frame that refits the crowd's BLASes, the BLAS refit; phase two between the depth pyramid pass and phase two's depth pass. With the culling Render switch off, which ships on, phase one draws every Instance in use and phase two draws none; with forced_lod, which ships unset, every Instance draws the LOD it names.
Reads
The Instance buffer and its slot count, the Mesh table with each LOD's Meshlet range, triangle range and LOD error, the Meshlets and their triangles, the camera uniform with the LOD error allowed and a pixel's size a metre from the camera, each slot's visibility bit from the frame before, and in phase two the depth pyramid.
Writes
The frame's draw: the Meshlet records, the packed indices and FrameDraw, the draws' indirect arguments and counts; each slot's offsets, LOD, whether its Instance is small, and the LOD error of the LOD it draws, which the shadow mask pass reads; in phase two, each slot's visibility bit.
Dispatches
Four per phase. In its pass over the slots: offset_slots, a workgroup per 256 slots; offset_blocks, one workgroup; append_records, an invocation per slot. In its pass over the records: append_triangles, a workgroup per Meshlet record, sized by indirect dispatch.
Bind groups
Group 0, the frame's camera; group 2, the scene geometry; group 3, FRAME_DRAW, the draw's buffers and the depth pyramid, in two copies that differ in the buffer bound as frame_draw.
Shader
src/render/shaders/culling.wgsl, after the common part, compiled with wgpu's runtime checks but its loop bounding; each phase's pipelines set the PHASE_TWO and FORCED_LOD overrides beside the switches' CULLING.
Counted
culling_phase_one_slots, culling_phase_one_triangles, culling_phase_two_slots and culling_phase_two_triangles in GPU time, and the bench's culling_per_slot_microseconds, both phases' passes over the slots; instances_drawn, triangles_drawn, phase_two_triangles_drawn and instances_overflowed in counters, read back from FrameDraw, beside instance_slots_in_use; its buffers in GPU memory, as scene and pass buffers.

Where it sits in the frame

Frame data lists no draws. The GPU chooses what to draw and at which LOD: phase one before the depth pre-pass, from last frame's visibility, and phase two after the depth pyramid, from what phase one drew this frame.

The frame's passes with shadow rays on, in the order the GPU receives them

  1. dynamic TLAS build
  2. bend pass
  3. culling, phase one: slots, then triangles
  4. Froxel pass
  5. depth pre-pass
  6. depth pyramid pass
  7. culling, phase two: slots, then triangles
  8. phase two's depth pass
  9. shadow mask pass
  10. lit pass
  11. tonemapping pass

In a frame whose BLASes are refitted, the crowd's refit form on Metal, the commands up to the bend pass are submitted first, with the refits, and the dynamic TLAS's build follows them. The depth pre-pass draws phase one's Instances into depth, the depth pyramid pass reduces that depth, and phase two tests the rest against it. Phase two's own Instances then draw into depth in a pass of their own with shadow rays on, as Praxis ships, or at the start of the lit pass with them off; the lit pass shades both phases' at depth equal. The Froxel pass follows phase one so that ADR 0019's gate, timed from the start of phase one, counts the lights' culling.

Each phase records two compute passes, each a Timed pass: the per-slot stages, whose time follows the slots in use, then append_triangles, whose time follows the triangles drawn. Phase one first clears FrameDraw; a frame with no slots in use begins both passes and dispatches nothing.

if slots > 0 {
    // Each slot's offsets are the sum of the earlier slots' Meshlet
    // records and packed indices: summed by block, then the blocks.
    pass.set_pipeline(&pipelines.offset_slots);
    pass.dispatch_workgroups(slots.div_ceil(SCAN_BLOCK_SIZE), 1, 1);
    pass.set_pipeline(&pipelines.offset_blocks);
    pass.dispatch_workgroups(1, 1, 1);
    // An invocation per slot.
    pass.set_pipeline(&pipelines.append_records);
    pass.dispatch_workgroups(slots.div_ceil(SCAN_BLOCK_SIZE), 1, 1);
}
drop(pass);

    encoder,
    phase.triangles_label(),
    triangles_timestamp_writes,
    bind_groups,
    &self.append_bind_group,
);
if slots > 0 {
    // A workgroup per Meshlet record the phase appends.
    pass.set_pipeline(&pipelines.append_triangles);
    pass.dispatch_workgroups_indirect(&self.buffers.frame_draw, APPEND_DISPATCH_OFFSET);
}

2 · FrameDraw · pack_index · DrawCapacity

The frame's draw

One index buffer holds every draw: each index packs a Meshlet record above six bits of vertex, and the record names the Instance's slot, the Meshlet and the Material to draw it with. Ordinary indices fill it from the start, both phases in turn; the indices of Thin Primitives and small Instances fill it from the end, each phase's back from the phases' before.

The cooker cuts each LOD of each Primitive into Meshlets of at most 64 vertices and 124 triangles; a Meshlet lists its vertices as indices into the vertex Arena and its triangles as three one-byte corners into that list, in cooked order, and a Mesh's Thin Primitives' Meshlets follow its others in each LOD. For each Instance it draws, the pass writes one record per Meshlet of the LOD it selects, with the Instance's own Material ID where its Renderable overrides its Mesh's Materials and the Meshlet's Primitive's otherwise, and one packed index per corner.

fn pack_index(record: u32, vertex: u32) -> u32 {
    return (record << MESHLET_VERTEX_BITS) | vertex;
}

common.wgsl. MESHLET_VERTEX_BITS is the base-2 logarithm of MESHLET_MAX_VERTICES, 64, declared from Rust: 6, which leaves 26 bits for the record. CullingPass::new asserts the record capacity stays below 226.

The vertex shader unpacks an index, reads its record, reads the Instance from the record's slot and pulls its vertex; what it does with a Thin Primitive's or small Instance's vertices is on the depth pre-pass. The draw's two buffers have fixed capacities, held within the scene and pass buffers' Budget rather than drawn from it, as the Capability floor caps the indices; the offsets and visibility bits follow the Instance slots, which the Budget sizes:

3 · offset_slots · offset_blocks · append_records · append_triangles

Four dispatches, in slot order

Every Instance's place in the draw follows from the slots' order and counts alone: a running sum over the slots of three counts, Meshlet records, ordinary indices and Thin Primitives' indices, gives each drawn Instance where its records and indices start, and only then are they written. The draw is the same from run to run, and the image with it.

offset_slots runs a workgroup per block of 256 slots, SCAN_BLOCK_SIZE. Each invocation decides whether its slot's Instance is drawn in this phase and at which LOD, takes that LOD's counts where it is, and joins a Hillis and Steele scan in workgroup memory, which gives each slot the sums of the counts before it in its block. A slot not drawn, freed or culled, takes NOT_DRAWN, all ones, past every capacity; the sums saturate there, so nothing past it can fit either. The block's total goes after every slot's entry.

fn exclusive_scan(invocation: u32, value: vec3<u32>) -> vec3<u32> {
    scan[invocation] = value;
    for (var stride = 1u; stride < SCAN_BLOCK_SIZE; stride *= 2u) {
        workgroupBarrier();
        var before = vec3<u32>(0u);
        if invocation >= stride {
            before = scan[invocation - stride];
        }
        workgroupBarrier();
        scan[invocation] = saturating_add(scan[invocation], before);
    }
    workgroupBarrier();
    var before = vec3<u32>(0u);
    if invocation > 0u {
        before = scan[invocation - 1u];
    }
    return before;
}

culling.wgsl.

offset_blocks runs one workgroup over the blocks' totals: at the Instance buffer's 488,448 slots, 1,908 blocks, 8 to an invocation, each loop bounded alike in every invocation so the scan's barriers stay in uniform control flow. It turns each block's total into the block's start, from where the phase starts: 0 in phase one, phase one's sums in phase two, which phase one's last invocation leaves in phase_two_offsets. It also sets the draws' instance counts to 1, phase two's first index, each phase's first thin index, the phase's range of records and of Thin Primitives' sums, and append_triangles's dispatch.

append_records runs an invocation per slot. Each drawn Instance whose records and indices fit writes the records of its LOD's Meshlets from its block's start plus its own offset, raises the draws' index counts to its last index and its last thin index with atomicMax, phase two's own draws' too in phase two, and counts itself drawn; one that does not fit counts itself overflowed.

append_triangles runs a workgroup of 32 invocations per record the phase appended. It writes the record's Meshlet's packed indices at the Instance's first index plus the Meshlet's triangles before it in the LOD; for a Thin Primitive's Meshlet, or any Meshlet of a small Instance, at the Instance's first thin index plus the LOD's thin triangles before it. Adjacent invocations write adjacent indices, each triangle's corners as cooked, so the draw rasterises as the cooked index stream does.

Atomics remain only where order cannot matter: the index counts' atomicMax, the counts' atomicAdds and the visibility words' atomicOrs end at the same value whatever order invocations run in. Appending through a shared atomic count instead would place each Instance by when its workgroup arrived, and on the Apple M4 Pro, which triangles a draw holds before others changes the implicit derivatives some pixels sample their Textures with, so the image would differ from run to run (Metal quirks).

4 · clip_space_bounds · small_instance_coverage

Bounds as they draw

The tests take an Instance's Mesh bounds as the vertex stage will draw them, not as they were cooked: grown by the radius a Thin Primitive widens to, or, for a small Instance, scaled across the view as its vertices are. A test of the cooked box would cull a tube whose widening alone reaches the view, or a small Instance drawn a pixel wide.

clip_space_bounds composes the box's centre from the Instance's and the camera's Anchors with camera_relative_position, the function the vertex shader places vertices with (ADR 0014), and takes its three half axes, the Instance's rotation-scale columns times the box's half extents, into clip space as directions. Where the Mesh has a Thin Primitive, each half axis then lengthens by the radius a tube draws at the box's farthest corner, half a pixel there over 0.75, as thin_drawn_radius gives it for a tube of no width:

let farthest_w = centre.w
    + abs(clip_half_axes[0].w)
    + abs(clip_half_axes[1].w)
    + abs(clip_half_axes[2].w);
let widening_metres = select(
    0.0,
    thin_drawn_radius(0.0, camera.pixel_size_per_metre * max(farthest_w, 0.0)),
    mesh.thin_triangle_counts[0] != 0u
);
let half_lengths = vec3<f32>(length(half_axes[0]), length(half_axes[1]), length(half_axes[2]));
let growth = 1.0 + widening_metres / max(half_lengths, vec3<f32>(1e-30));

clip_space_bounds, culling.wgsl. Clip w is the depth along the view axis, so camera.pixel_size_per_metre times it is a pixel's size there; the widening moves a vertex out of the Mesh bounds by less than the radius it draws at the farthest corner.

A Mesh with no Thin Primitive may make a small Instance: one whose Mesh bounds cover under a pixel's area. small_instance_coverage gives that share, the area the box's faces cover seen from the camera over a pixel's, raised to at least the square of the sphere about the box's diameter over four pixels, and 1 where it reaches a pixel or the box's centre is at or behind the camera's plane. The tests then widen the box as the vertex stage scales the Instance, by small_instance_scale, the inverse square root of the coverage, stopping at an eighth:

var coverage = 1.0;
// vs_thin takes a Meshlet with a radius as a Thin Primitive's, whatever its Instance.
if mesh.thin_triangle_counts[0] == 0u {
    coverage = instance_coverage(instance, mesh, bounds.centre.w);
    // The tests below take the bounds as vs_thin draws them: wider across the view, as deep.
    let widening = vec4<f32>(vec3<f32>(small_instance_scale(coverage)), 1.0);
    bounds.half_axes = mat3x4<f32>(
        bounds.half_axes[0] * widening,
        bounds.half_axes[1] * widening,
        bounds.half_axes[2] * widening
    );
}
small = coverage < 1.0;

offset_slots, culling.wgsl. Every such slot works out its coverage, culled or not, so whether a small Instance is drawn does not follow the frame before (ADR 0027).

A small Instance's every Meshlet counts as a Thin Primitive's: its triangles go to the thin indices, and the slot's offsets keep a bit that says so for the stages after. How the vertex stage scales it, and the samples its fragments keep, are on the depth pre-pass.

5 · in_view_frustum

The frustum test

The test runs in clip space on the box as it draws. A plane's distance is linear there, so the box reaches furthest inside each plane by its centre's distance plus each half axis's, whole; a box is culled only where it lies wholly beyond one plane.

The view frustum is bounded by four side planes, −w ≤ x ≤ w and −w ≤ y ≤ w, and the near plane, z ≤ w. Under ADR 0015's reverse Z with no far plane every point past the near plane lands at z ≥ 0, so there is no sixth plane.

fn in_view_frustum(bounds: ClipBox) -> bool {
    let side_reach = side_plane_distances(bounds.centre)
        + abs(side_plane_distances(bounds.half_axes[0]))
        + abs(side_plane_distances(bounds.half_axes[1]))
        + abs(side_plane_distances(bounds.half_axes[2]));
    let near_reach = near_plane_distance(bounds.centre)
        + abs(near_plane_distance(bounds.half_axes[0]))
        + abs(near_plane_distance(bounds.half_axes[1]))
        + abs(near_plane_distance(bounds.half_axes[2]));
    return all(side_reach >= vec4<f32>(0.0)) && near_reach >= 0.0;
}

culling.wgsl. side_plane_distances returns w + x, w − x, w + y and w − y at once; near_plane_distance returns w − z.

The five planes are tested with neither a branch nor a loop. The culling switch reaches WGSL as the CULLING override, which each pipeline sets from the Renderer's switches, so the shader compiles with it fixed and the shipping pipeline pays for no branch.

6 · offset_slots · visible_before

Two phases

Frames are alike: most Instances visible in one frame are still visible in the next. Phase one draws those, the depth they leave becomes the depth pyramid, and phase two tests every Instance in view against it, draws the visible ones phase one did not, and records visibility for the next frame.

visible = !CULLING || in_view_frustum(bounds);
if PHASE_TWO {
    // Behind what phase one drew, it is not visible.
    visible = visible && !(CULLING && occluded(bounds));
    // Phase one's offsets for the slot, before this phase's replace them.
    drawn = CULLING && visible && all(instance_offsets[slot].xyz == NOT_DRAWN);
} else {
    drawn = visible && (!CULLING || visible_before(slot));
}
// A shadow proxy's Mesh has no Meshlets: rays trace it, no pass
// draws it.
drawn = drawn && mesh.meshlet_counts[0] != 0u;
drawn = drawn && (!CULLING || thin_kept_samples(coverage) != 0u);
if drawn && CULLING && mesh.thin_triangle_counts[0] == mesh.triangle_counts[0] {
    drawn = thin_kept_samples(widest_tube_coverage(instance, mesh, bounds)) != 0u;
}

offset_slots, culling.wgsl: each slot's decision. The last three lines are the drops of section 8.

Phase two tests the Instances phase one drew too, so the bits record what is visible now: an Instance that became hidden is drawn by phase one one last time, loses its bit, and leaves phase one the frame after. It gathers each block's bits with workgroup atomicOrs and writes the block's eight words once. Phase one's offsets for a slot, read before phase two writes its own, tell phase two which Instances phase one drew.

The image stays right. An Instance that shows this frame is either drawn by phase one, or tested by phase two against depth made only of Instances drawn this frame, and drawn if any part of it could be nearer. One that phase one draws although now hidden costs work, and the depth test hides it. The bits start zeroed, so the first frame's phase one draws nothing, the pyramid is all far plane, and phase two draws everything in view. After a camera cut last frame's bits predict little, and phase two draws most of the view.

Phase two's indices follow phase one's in the same buffer, from phase one's totals, so the draw at offset 0 grows across the phases: the depth pre-pass draws it as phase one leaves it, and the lit pass draws it with both. phase_two_draw covers phase two's ordinary indices alone, for the depth draw of phase two's Instances, and each phase's thin draw its own. With culling off, phase one draws every Instance in use and phase two draws none and sets the bit of every Instance in use.

7 · occluded

The occlusion test

A box in view is occluded where even its nearest point is farther than the farthest depth phase one drew anywhere its screen rectangle could cover: the minimum of four texels of the depth pyramid, at the level where the rectangle spans at most two per axis. Every step errs towards drawing.

Eight corners, moved nearer. For a box in front of the camera, depth, z over w, and reach across the screen are both extreme at a corner, so the test projects the eight corners of the box as it draws and keeps the greatest depth, the box's nearest point under reverse Z. Each corner first moves towards the camera in z and w by 1/16384 of the summed magnitudes of that coordinate over the box's centre and half axes, OCCLUSION_ROUNDING, plus 0.1 mm, COMPOSITION_ERROR, past ADR 0014's worst camera-relative error for the box's composition and the vertices' each, so f32 rounding cannot make the box look farther than its drawn triangles. A box with a corner at or behind the camera's plane is never occluded.

A rectangle grown by a pixel. The corners' x and y over w bound a screen rectangle, which the test takes into texture coordinates, rows top first, and grows by half a level-0 texel, a pixel, past where rasterisation rounds vertices, so every sample a covered pixel holds lies in the texels read.

The level, and its size computed. With e the rectangle's larger side in level-0 texels, the level is min(⌈log2 max(e, 1)⌉, levels − 1), where it spans at most two texels per axis. The level's size is level 0's shifted down, at least 1, as a mip chain halves, rather than queried: lavapipe answers a size query whose level varies across a workgroup's invocations with one invocation's answer. If rounding leaves the rectangle over more than two texels, the box is not occluded.

let size = max(level_zero_texels >> vec2<u32>(level), vec2<u32>(1u));
let first = min(vec2<u32>(first_coordinates * vec2<f32>(size)), size - 1u);
let last = min(vec2<u32>(last_coordinates * vec2<f32>(size)), size - 1u);
if any(last > first + 1u) {
    return false;
}
let farthest = min(
    min(textureLoad(depth_pyramid, first, level).r, textureLoad(depth_pyramid, vec2<u32>(last.x, first.y), level).r),
    min(textureLoad(depth_pyramid, vec2<u32>(first.x, last.y), level).r, textureLoad(depth_pyramid, last, level).r)
);
return nearest_depth < farthest;

The end of occluded, culling.wgsl.

Four texels, compared. The test loads the corners of the block of one or two by one or two texels, takes their minimum, the farthest depth anything drawn reaches there, and culls the box where its nearest depth is less. The pyramid keeps the farthest depth over every sample beneath a texel, the nearest corner stands for the whole box, the margins move it nearer and the rectangle grows: each makes the test keep Instances, never drop a visible one.

8 · thin_kept_samples · widest_tube_coverage

No sample, no draw

A fragment of a Thin Primitive or a small Instance keeps the share of a pixel's four samples its coverage rounds to, and none under an eighth. With culling on, the pass leaves out an Instance that would keep none: a small Instance at that coverage, and an Instance of a Mesh that is all tubes once its widest tube keeps none at the box's nearest depth.

The samples kept follow from the count alone, the coverage times four rounded to the nearest, so every fragment of a pixel keeps the same ones (ADR 0027). The pass reads the same function the depth passes write their mask with:

fn thin_kept_samples(coverage: f32) -> u32 {
    let count = u32(saturate(coverage) * 4.0 + 0.5);
    return (0xfb910u >> (4u * count)) & 15u;
}

common.wgsl: no sample, then sample 0, samples 0 and 3, then 0, 1 and 3, then all four.

A small Instance is tested with the coverage its bounds give. An Instance whose Mesh has no Thin Primitive and covers a pixel or more has coverage 1 and passes.

A Mesh that is all Thin Primitives, such as town's wires and top rails, takes a second test, run only for a slot otherwise drawn, as it walks the Mesh's LOD 0 Meshlets for the widest tube radius:

fn widest_tube_coverage(instance: InstanceData, mesh: MeshData, bounds: ClipBox) -> f32 {
    let nearest_view_depth_metres = bounds.centre.w
        - abs(bounds.half_axes[0].w) - abs(bounds.half_axes[1].w) - abs(bounds.half_axes[2].w);
    let pixel_metres = camera.pixel_size_per_metre * nearest_view_depth_metres;
    var radius_metres = 0.0;
    for (var meshlet_in_lod = 0u; meshlet_in_lod < mesh.meshlet_counts[0]; meshlet_in_lod++) {
        radius_metres = max(radius_metres, meshlets[mesh.first_meshlets[0] + meshlet_in_lod].thin_radius_metres);
    }
    radius_metres *= instance_scale(instance);
    // At or behind the camera's plane vs_thin leaves the tube as it is.
    if pixel_metres <= 0.0 || radius_metres <= 0.0 {
        return 1.0;
    }
    return radius_metres / thin_drawn_radius(radius_metres, pixel_metres);
}

culling.wgsl. A tube's coverage is its true radius over the radius it draws; at the nearest depth its pixel is smallest and its coverage greatest, so no fragment of the Instance could keep a sample the test says it cannot.

A Mesh that mixes tubes and ordinary Primitives, such as town's lamp, keeps drawing whatever its tubes keep. With culling off neither drop runs, so the unculled image draws these Instances too and their fragments keep no sample, which is how the Goldens test checks that culled and unculled images agree.

9 · instance_lod · selected_lod · SLOT_LOD_SHIFT

LOD selection

Each Instance draws the coarsest LOD whose LOD error, at the Instance's largest scale, spans under the LOD threshold, one pixel, at the distance to the sphere about its Mesh bounds. It reads the camera and the Instance alone, so both phases draw an Instance's same LOD, no earlier frame decides it, and the switch is hard.

The camera uniform carries lod_error_per_metre, the error the threshold allows a metre from the camera: LOD_THRESHOLD_PIXELS, 1, times a pixel's size a metre away, 2 tan(fov/2) over the target's height, recomputed on resize. instance_lod takes the Instance's largest axis scale, the sphere about the Mesh bounds at that scale, and the distance from the camera to that sphere, 0 inside it:

let scale = instance_scale(instance);
let radius = 0.5 * length(bounds_max - bounds_min) * scale;
let distance_metres = max(length(bounds_centre(instance, bounds_min, bounds_max)) - radius, 0.0);

instance_lod, culling.wgsl, after the forced LOD's early return.

var selected = 0u;
for (var lod = 1u; lod < min(lod_count, MESH_MAX_LODS); lod++) {
    if lod_errors_metres[lod] * scale < error_per_metre * distance_metres {
        selected = lod;
    }
}
return selected;

selected_lod, common.wgsl. A Mesh holds at most MESH_MAX_LODS, 8, each with its own Meshlet range, triangle range, thin triangle count and LOD error in the Mesh table.

With the forced_lod switch, FORCED_LOD holds the LOD it names, and each Instance draws it or the coarsest its Mesh has; unset, it holds MESH_MAX_LODS and selection runs. The bounds, the coverage and the drops above read the Mesh's bounds and LOD 0, so the LOD changes which triangles are drawn, never whether the Instance is.

Where the LOD goes. The scans' first sum, a slot's first record within its block, needs at most 27 bits, so the slot's first offset word also holds its LOD from bit 28, SLOT_LOD_SHIFT, and whether it is small in bit 27; append_records and append_triangles read both back. No LOD fills the top four bits, so no drawn slot reads NOT_DRAWN. The fourth word holds the LOD error of the LOD the Instance draws, in metres at its scale:

if slot < instance_slot_count {
    let record_small_and_lod = min(offset.x, SLOT_RECORD_MASK)
        | (u32(small) << SLOT_SMALL_SHIFT)
        | (lod << SLOT_LOD_SHIFT);
    if PHASE_TWO {
        lod_error_metres = bitcast<f32>(instance_offsets[slot].w);
    }
    instance_offsets[slot] = vec4<u32>(
        select(NOT_DRAWN, vec3<u32>(record_small_and_lod, offset.yz), drawn),
        bitcast<u32>(lod_error_metres)
    );
}

offset_slots, culling.wgsl. CullingPass::new asserts the record capacity stays below 227 − 1, and a const assertion that MESH_MAX_LODS fits the bits above.

Phase one works out that error for every Instance in use, drawn or culled, and phase two keeps it, so the shadow mask pass, which reads it through its own binding of instance_offsets to pass a ray's back face within the error, sees the same value whatever is culled.

10 · offset_blocks · frame_draw_bind_groups

The indirect dispatch and its stand-in

Only the GPU knows, mid-frame, how many records a phase appends, so offset_blocks writes append_triangles's workgroup counts into FrameDraw and the dispatch reads them from there. wgpu checks a dispatch's bindings and its argument buffer as one usage scope, so that dispatch binds a 112-byte stand-in where FrameDraw would go.

A dispatch may launch at most 65,535 workgroups along each dimension, wgpu's default, which the Capability floor takes as its own (ADR 0021); CullingPass::new asserts the device allows it. The draw holds 220 records, so they are laid out in rows:

let records = appended.y - appended.x;
// At least one row, so no records dispatch no workgroups.
let rows = max((records + MAX_WORKGROUPS_PER_DIMENSION - 1u) / MAX_WORKGROUPS_PER_DIMENSION, 1u);
frame_draw.append_dispatch = DispatchIndirect((records + rows - 1u) / rows, rows, 1u);

offset_blocks, culling.wgsl.

Each workgroup of append_triangles finds its record from its position in the rows and returns at once past the phase's last, since x × y can exceed the count. Without the max, zero records would divide by zero rows.

The usage scope is why the stand-in exists. In wgpu-core 30, a dispatch's scope merges every active bind group's uses, then adds the indirect buffer as INDIRECT; a buffer that a bound group writes holds a use that excludes every other, so a dispatch whose arguments are in it fails validation. Group 3 holds FrameDraw read-write besides the offsets, records, indices, visibility and pyramid that append_triangles needs, so the pass builds two copies of group 3 from one layout: the second binds a stand-in buffer, never read, as frame_draw. append_triangles reads its phase's record range from instance_offsets instead, at APPENDED_RECORDS, and its range of Thin Primitives' sums at THIN_INDICES, the two entries past every slot's and block's offsets, where offset_blocks put them. One function builds both groups, at creation and after every resize, since they hold the depth pyramid.

11 · fits · src/render/readback.rs

Overflow, and what Frame stats count

A phase whose Instances need more records or indices than the draw holds draws those that fit, in slot order, and counts the rest as overflowed; the warning comes from that read-back count, not from the CPU's sums, so culled Instances never warn.

fn fits(first: vec3<u32>, counts: vec3<u32>) -> bool {
    let thin_indices_end = instance_offsets[THIN_INDICES].y;
    let index_capacity = arrayLength(&packed_indices);
    if thin_indices_end > index_capacity {
        return false;
    }
    let capacity = vec2<u32>(arrayLength(&meshlet_records), index_capacity - thin_indices_end);
    return all(first.xy <= capacity) && all(counts.xy <= capacity - first.xy);
}

culling.wgsl.

The thin indices of the phases so far are set aside at the buffer's end first, and an Instance's records and ordinary indices must fit in what they leave. Since the offsets are a running sum, once one Instance does not fit, none after it does: the draw ends at the last Instance that fits, and every index before it is written. append_records still writes the records short of the buffer's end of an Instance that does not fit, so every record append_triangles reads is written, and that dispatch skips the indices of any record whose Instance does not fit. Once phase one fills the draw, phase two's Instances count as overflowed.

The GPU stats readback copies FrameDraw each frame into a ring of mapped buffers, a few frames late, and Frame stats report instances_drawn; triangles_drawn, the ordinary draw's and both thin draws' index counts over 3; phase_two_triangles_drawn, the same of phase two's two draws; and instances_overflowed. It warns once when a frame read back overflowed, and again only after one has room for all. Frame stats also count instance_slots_in_use, so a frame's culled Instances are those in use less the drawn, the overflowed and the shadow proxies, whose Meshes have no Meshlets.

14 · ADRs 0013, 0014, 0015, 0019, 0021, 0027

Why this way

The GPU builds the draw. A draw call recorded per Primitive per Instance grows the CPU's work with the scene; ADR 0019 moves the choice to a compute pass whose output one draw_indexed_indirect per pipeline and phase draws, a native call on every backend. Count draws are no alternative: wgpu's Metal backend leaves them empty, and it runs a multi-draw as a CPU loop of single draws.

Slot order, not atomic order. A scan costs two extra dispatches over appending through an atomic counter, and buys a draw that repeats from run to run, so captures are comparable and Goldens hold on the Apple M4 Pro. Wihlidal writes surviving indices in wavefront creation order where order matters, as for translucent rendering; here the reason is the derivatives.

Two phases. Testing against last frame's depth alone leaves newly visible geometry missing for a frame; testing against this frame's needs depth first. Drawing last frame's visible set, building the pyramid from it and testing the rest, as Haar and Aaltonen and later Nanite do, culls in one frame what the frame's own depth hides and fails only under extreme visibility changes, which then cull less and still render right.

Instances, not Meshlets. A test of each Meshlet's bounds against the frustum and the pyramid, and of its normal cone, was built and measured on town: ADR 0019 records that it dropped 4.9% of the triangles and left the gate unchanged, since most of its Instances draw a Mesh of one Meshlet. ADR 0019 records that culling tests Instances and that tests per Meshlet wait for a profile that shows the pass raster-bound; Metal quirks keeps what the prototype found of fast math across entry points.

Discrete LOD per Instance, chosen here. ADR 0019 keeps discrete LOD for dense static meshes and sets virtual geometry aside: Nanite and Bevy's meshlets have no MSAA, Nanite hides its LOD switches with temporal antialiasing, and wgpu 30 has no cluster acceleration structures, so a BLAS that follows the cut means rebuilding a worst-case one whenever the cut changes. The pass selects from the camera and the Instance alone, as meshoptimizer's example does from the distance to the bounding sphere, so neither phase, nor the frame before, nor what is culled moves the choice, and the shadow mask reads the same LOD error the draw used. The switch is hard: no Instance draws two LODs.

Coverage decided per Instance, drawn through twins. ADR 0027 carries partial coverage as a written sample_mask through pipelines of their own, so no other geometry pays for it, and the pass lists that geometry apart. The pass's compute stage already binds the nine storage buffers the Capability floor allows (ADR 0021), so the twins' indices share the frame's draw's buffer, from its end, rather than a buffer of their own. A small Instance's and a tube's coverage reads the camera and the Instance alone, so the culled image is the unculled one less Instances that keep no sample.

A workgroup per record, 32 wide. A workgroup per slot in use, one invocation per triangle, would launch work for every slot whatever it appends; launching one per appended record, by indirect dispatch, follows the triangles drawn. 32 is an Apple SIMD group, and wider workgroups wrote a dense scene's draw slower, as APPEND_WORKGROUP_SIZE's comment records.

Two passes a phase, timed apart. ADR 0013 keeps a guard on the per-slot stages, past which the decision to cull Instances with no hierarchy reopens; timing them apart from append_triangles needs a pass boundary, as timestamps inside a pass stay optional at the Capability floor (ADR 0021). The split runs in every frame, so what the bench times is what ships.

Loops left unbounded by wgpu. wgpu bounds every shader loop at runtime unless told the module has no infinite loop. The culling module is compiled without that bound, and every_loop_wgpu_leaves_unbounded_ends checks from the parts' text that each loop ends whatever its buffers hold, which is why append_triangles' loop takes its bound from min(meshlet.triangle_count, MESHLET_MAX_TRIANGLES).

Visibility in a buffer of its own. The bits are state kept between frames, the rest of group 3 one frame's scratch; folding the bits into the offsets would have saved a binding at the price of mixing the two.

Conservative throughout. Each test is exact for what it can prove and errs towards drawing: the frustum test plane by plane, on bounds grown to what draws; the occlusion test through the pyramid's farthest depth, nearest corners, rounding margins and a grown rectangle; the tube's drop at its nearest depth. A wrong cull removes something visible; a missed one costs a little drawing, which the depth test then hides.

15

Limits

Boxes past a frustum's corner. A box outside two planes near where they meet, but wholly beyond neither, is kept and drawn.

Boxes at the camera. A box with a corner at or behind the camera's plane is never occluded, however much hides it.

Sheared Instances. Lengthening each half axis by a tube's widening holds every widened vertex, and the largest column scale gives a tube's widest radius, only while the Instance's axes are orthogonal. No scene has a sheared Instance with a Thin Primitive.

A hard LOD switch. An Instance changes LOD in one frame, and from inside the sphere about its bounds it draws LOD 0. The forced LOD is the only other choice.

A fixed draw. The draw holds 225 indices and 220 records whatever the frame needs; past either, the Instances after the last that fits are not drawn that frame, whatever their distance. The thin indices of the phases so far are set aside first, so a phase whose Thin Primitives' indices alone pass the buffer draws none of its Instances. The capacities are fixed, not drawn from the GPU memory Budgets.

Phase order within the draw. An Instance phase two draws sits after all of phase one's for that frame; one slot order across both phases would need a third index list or gaps of degenerate triangles.

Work for every slot. Every Instance whose Mesh has no Thin Primitive works out its coverage, culled or not, and phase one works out every Instance's LOD; a Mesh that is all tubes walks its LOD 0 Meshlets for its widest radius, as the Mesh table holds none.

Composed twice. The pass composes each box relative to the camera for its tests, and the vertex shader composes every vertex again; handing the composed transform over would need a per-Instance buffer, another storage binding.

History

The pass took its form over the third milestone: one indirect draw of every Instance in slot order, then the frustum test and the switch that turns culling off, then the two phases and the occlusion test against the depth pyramid, then each phase's append split into a record per slot and a workgroup per record by indirect dispatch; a test of each Meshlet was measured and kept out. Over the fifth, each phase became two compute passes, so its per-slot stages are timed against ADR 0013's guard; the pass came to select each Instance's LOD and keep its LOD error for the shadow mask; it took on the culling side of Thin Primitives and small Instances, growing bounds to what draws, listing their indices apart from the buffer's end and leaving out Instances that keep no sample; and its module came to be compiled without wgpu's loop bounding. FrameDraw grew from 72 to 112 bytes and a slot's offsets from two words to four. The Metal paragraphs of that development, slot order against atomic order and fast math across entry points, are on Metal quirks. This page describes the pass as it is.
