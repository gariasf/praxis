# Persistent Instance buffer

Transform-propagation results live in one GPU buffer, the Instance buffer, in a slot per Renderable, and are updated incrementally through dirty flags; there are no per-entity uniform buffers. GPU-driven rendering, ray-tracing TLAS rebuilds and instancing all consume exactly this shape. Implemented (#121): each Renderable keeps a slot in the Instance buffer until it stops being a Renderable, and a freed slot is taken again before a fresh one; the buffer holds a fixed number of slots, past which a Renderable is refused, warned about once, counted in Frame stats and retried every frame (#190); the number is sized at device creation from the scene and pass buffers' GPU memory Budget (amended 2026-11-06, [#626](https://github.com/gariasf/praxis/issues/626)), 30% of it at 136 bytes a slot, its Instance, offsets and visibility bit, in whole 256-slot scan blocks of the culling pass: 517,376 slots at the Budgets M4 set (amended 2026-11-09, [#671](https://github.com/gariasf/praxis/issues/671)); prepare writes only the slots of new Renderables and of those whose World transform, Mesh or Material changed, found by bevy_ecs change detection, through the per-frame staging path, so camera motion writes no Instance. A freed slot is written an Instance with no Mesh, which the GPU does not draw, and is taken again from the next frame (amended 2026-10-20, [#194](https://github.com/gariasf/praxis/issues/194)). Refined by ADR 0014: the buffer stores an integer anchor plus an f32 offset per Renderable. Refined by ADRs 0022 and 0020: prepare also rewrites every Moving Instance each frame, changed or not, since its drawn transform is blended by the frame's blend weight and the dynamic TLAS is rebuilt from the Moving Instances (amended 2026-11-04, [#543](https://github.com/gariasf/praxis/issues/543)). On the frame after the Mesh or Material pool frees an entry, prepare rewrites every Instance, since an unchanged one may name the freed index, which a later Asset may take (amended 2026-11-06, [#619](https://github.com/gariasf/praxis/issues/619)). A Placement has no entity: each loaded Chunk owns a contiguous range of slots, one per Placement, taken on the first frame prepare sees the Chunk, before new Renderables take theirs, and kept until it unloads; its Placements' Instances are written there in the order the Chunk holds them, on that frame and again whenever every Instance is rewritten, and its point lights join the frame's lights. A Placement whose Handles find nothing, or that lacks a Material Handle its Mesh needs, is written an Instance with no Mesh and, unlike a Renderable, not retried, since its Chunk's load returned those Handles. A Chunk the buffer has no room for is refused, warned about once and its Placements counted as refused every frame. An entity's slot is still per entity (amended 2026-11-07, [#654](https://github.com/gariasf/praxis/issues/654)). A range is the first free range long enough, else fresh slots past the highest taken; an unloaded Chunk's range is written Instances with no Mesh and joins the free ranges the next frame, merged with those it touches, so a refused Chunk takes a range once one fits. A held Chunk keeps its range, written Instances with no Mesh until it is drawn again, and its point lights stay out of the frame's (amended 2026-11-08, [#659](https://github.com/gariasf/praxis/issues/659)).
