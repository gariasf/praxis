# Persistent Instance buffer

Transform-propagation results live in one GPU buffer, the Instance buffer, in a slot per Renderable, and are updated incrementally through dirty flags; there are no per-entity uniform buffers. GPU-driven rendering, ray-tracing TLAS rebuilds and instancing all consume exactly this shape. Implemented (#121): each Renderable keeps a slot in the Instance buffer until it stops being a Renderable, and a freed slot is taken again before a fresh one; the buffer holds a fixed 524,288 slots, past which a Renderable is refused, warned about once, counted in Frame stats and retried every frame (#190); prepare writes only the slots of new Renderables and of those whose World transform, Mesh or Material changed, found by bevy_ecs change detection, through the per-frame staging path, so camera motion writes no Instance. A freed slot is written an Instance with no Mesh, which the GPU does not draw, and is taken again from the next frame (amended 2026-10-20, [#194](https://github.com/gariasf/praxis/issues/194)). Refined by ADR 0014: the buffer stores an integer anchor plus an f32 offset per Renderable.
