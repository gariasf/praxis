# Persistent Instance buffer

Transform-propagation results live in one GPU buffer, the Instance buffer, in a slot per Renderable, and are updated incrementally through dirty flags; there are no per-entity uniform buffers. GPU-driven rendering, ray-tracing TLAS rebuilds and instancing all consume exactly this shape. Implemented (#121): each Renderable keeps a slot in the Instance buffer until it stops being a Renderable, and a freed slot is taken again before a fresh one; the buffer holds a fixed number of slots, past which a Renderable is refused, warned about once, counted in Frame stats and retried every frame (#190); the number is sized at device creation from the scene and pass buffers' GPU memory Budget, a slot per 256 bytes of it, rounded down to a power of two of the culling pass's 256-slot scan blocks, which keeps the 524,288 it was until the Budget split sets the bytes per slot (amended 2026-11-06, [#626](https://github.com/gariasf/praxis/issues/626)); prepare writes only the slots of new Renderables and of those whose World transform, Mesh or Material changed, found by bevy_ecs change detection, through the per-frame staging path, so camera motion writes no Instance. A freed slot is written an Instance with no Mesh, which the GPU does not draw, and is taken again from the next frame (amended 2026-10-20, [#194](https://github.com/gariasf/praxis/issues/194)). Refined by ADR 0014: the buffer stores an integer anchor plus an f32 offset per Renderable. Refined by ADRs 0022 and 0020: prepare also rewrites every Moving Instance each frame, changed or not, since its drawn transform is blended by the frame's blend weight and the dynamic TLAS is rebuilt from the Moving Instances (amended 2026-11-04, [#543](https://github.com/gariasf/praxis/issues/543)). On the frame after the Mesh or Material pool frees an entry, prepare rewrites every Instance, since an unchanged one may name the freed index, which a later Asset may take (amended 2026-11-06, [#619](https://github.com/gariasf/praxis/issues/619)).
