# Textures stream by mip, geometry lives in fixed arenas

Textures are ordinary mip chains streamed whole mip at a time in wgpu's safe API, chosen by CPU heuristics; vertices and indices live in fixed arenas sized from the Budget at device creation and sub-allocated by an offset allocator. This is option A of `docs/research/gpu-memory-residency-streaming.md`: the only option that keeps hardware trilinear and anisotropic filtering unchanged and adds no new artefact class (a late mip shows as blur, never as a crack or a capped anisotropy), and it needs only Tier 1 bindless. Accepted 2026-10-12 ([#21](https://github.com/gariasf/praxis/issues/21)). Planned; today the Material pool is 5 Channels × 8 Layers of RGBA8 2048² arrays without mips, 640 MiB allocated eagerly, and the mega-buffers grow by CPU re-upload.

## Considered options

- Software virtual texturing: a fixed page cache, but the tile border caps anisotropy (a 4-texel border allows 8x), mips smaller than a tile are missing, and pages arrive a frame or more late.
- Hardware sparse textures through wgpu-hal: per-backend native code that wgpu-core does not track, never tried, and Intel's sample shows black cracks where anisotropic sampling reaches unmapped tiles. It stays the fallback if the bind-group cost below fails its gate.
- Virtual geometry pages: they depend on the rasterization path, so they belong to [Visibility strategy for the main pass](https://github.com/gariasf/praxis/issues/22); if it picks virtual geometry, the vertex arena becomes a page pool there.
- Arena growth, by CPU re-upload (today) or GPU copy: growth briefly holds the old and new buffers, and the CPU re-upload keeps a shadow of every vertex.

## Consequences

- Each Channel is one partially bound texture binding array (`TEXTURE_BINDING_ARRAY`, `PARTIALLY_BOUND_BINDING_ARRAY`) in one bind group; a Layer is an index into its Channel's array, Layer 0 stays the neutral default, and the fixed 8 Layers per Channel go. Residency changes are batched so that bind group is rebuilt at most once per frame. Gate on the implementing ticket: the rebuild plus Metal's per-texture `useResource` on each `set_bind_group`, measured at 10k textures on the M4 Pro, fits ADR 0013's 6 ms critical path; if not, batch over several frames, then hardware sparse.
- Priority is computed on the CPU: the finest mip any visible Instance needs, from distance and the Mesh's UV texel density (stored at cook time) against the 1440p pixel footprint; Chunks inside the load radius are requested ahead. No GPU feedback readback until a measured miss rate asks for it.
- Each texture's Resident tail (mips of 64 KiB and smaller) never leaves. When a request would exceed the texture pool's capacity, which is set from its Budget, the finest mip of the lowest-priority texture goes first, least recently used breaking ties; a mip loads at priority p and is evicted only below p − 1, so it does not thrash.
- One vertex arena and one index arena, each at most 2^31 − 1 bytes (the DX12 and Linux non-NVIDIA Vulkan buffer limit), sub-allocated with the `offset-allocator` crate (TLSF, MIT; new dependency, justified in the implementing PR). No growth at runtime: a load that does not fit is refused and logged. The CPU shadow of vertex and index data goes.
- The 8 GB of ADR 0013 splits into Budgets for geometry arenas, the texture pool, Resident tails, render targets, acceleration structures and staging; their sizes are provisional until the first Baseline. A `TRANSIENT_ATTACHMENT` counts as zero only when `transient_saves_memory` is `Some(true)`. Acceleration structures join the ledger: 94 bytes per BLAS triangle (45.5 compacted) and 288.5 per TLAS instance on the M4 Pro.
- Streaming uploads go through a `StagingBelt`, never `write_texture`, which allocates fresh staging on every call. The belt's `chunk_size` is only its allocation unit (it allocates more chunks on demand), so the engine caps the bytes written into it per frame at the staging Budget, and an upload past the cap waits for a later frame; the IO pool (ADR 0016) decodes into CPU memory and the main thread copies it into the belt.
- The cooked format (ADR 0011) stores each mip as a separately loadable blob with the Resident tail as one blob, and each Mesh's UV texel density.
