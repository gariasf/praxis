# Clustered forward main pass with 4x MSAA

The opaque main pass is clustered forward: a 4x MSAA reverse-Z depth pre-pass, then a lit pass at depth equal that loops over its Froxel's lights and reads each one's shadow from a shadow mask, which a compute pass traces from the depth target before it, one ray per pixel and light (amended 2026-10-23, [#260](https://github.com/gariasf/praxis/issues/260): traced inline, the rays cost the M4 Pro's GPU frame 2.4 to 12.9 times as much at 1440p on the Reference scenes but texture-wall, which spends its frame in its Textures, and a ray query left in the lit pass's shader cost it 0.9 to 3.9 ms even where it never ran). Geometric edges get 4x MSAA (the Apple9 maximum), with alpha-to-coverage for masked materials. This is option A of `docs/research/visibility-and-gpu-driven-main-pass.md`: the forward shapes are the only ones whose MSAA costs no more memory than its 4x depth, 58,982,400 bytes at 1440p, which the pre-pass stores for the Hi-Z pyramid and the lit pass, while 4x colour needs none when the lit and transparent passes share one render pass and resolve in it (SMAA 1x cannot reconstruct sub-pixel geometry), and A writes nothing that no decided pass reads. Accepted 2026-10-12 ([#22](https://github.com/gariasf/praxis/issues/22)). Planned; today a compute pass appends the Meshlets of each Instance whose Mesh bounds reach into the view frustum to the compacted index buffer in slot order, in two phases. Phase one appends those visible the frame before, one bit per slot, and a depth pre-pass draws them into 4x MSAA reverse-Z `Depth32Float` cleared to 0 (ADR 0015) and stores it. A compute pass reduces that depth into the Hi-Z pyramid, each texel the minimum of every sample below it. Phase two appends the others whose bounds lie anywhere nearer than the pyramid's minimum over the texels their screen rectangle covers, and rewrites the bits. Phase two's Instances draw into depth: with shadow rays off, at the start of the lit pass; with them on, in a pass of their own, after which a compute pass traces, from each pixel's nearest sample, one shadow ray toward each light that reaches it and keeps whether it is hidden in the shadow mask ([#260](https://github.com/gariasf/praxis/issues/260)). A lit pass draws both phases' at depth equal into a transient 4x colour attachment, memoryless on Apple GPUs, that it resolves into the `Rgba16Float` HDR target, which a tonemapping pass then writes into the target (#200), with one `draw_indexed_indirect` per phase for the depth pipeline and one of both phases for the lit pipeline, lit by every directional light and by the point lights of each pixel's Froxel, which a compute pass at the start of the frame lists from a light buffer of fixed capacity: those whose range reaches into the Froxel's bounds ([#201](https://github.com/gariasf/praxis/issues/201)), each hidden where the shadow mask says so, the directional lights' rays first ([#203](https://github.com/gariasf/praxis/issues/203)), then those point lights' ([#205](https://github.com/gariasf/praxis/issues/205)), up to 59 lights per pixel; a light past them casts no shadow there and is counted ([decision](https://github.com/gariasf/praxis/issues/17#issuecomment-6369952061)).

## Considered options

- Forward with a visibility pre-pass (option B): A plus a 32-bit Instance-and-triangle ID per sample (59 MB at 4x and 1440p), and `primitive_index` made the ID pass 19 to 24% slower on the M4 Pro. Nothing decided reads the IDs; it is A plus one attachment, so it is taken when a compute pass needs per-pixel geometry.
- Deferred G-buffer (option C) and visibility buffer with compute materials (option D): MSAA only with per-sample storage or per-sample shading at edges, otherwise SMAA 1x. Lighting every sample at 4x cost deferred 1.2 to 3.7 times forward 4x on the M4 Pro.
- Virtual geometry beside A (option E): no MSAA in Nanite or Bevy, Nanite hides its LOD switches with TAA, and wgpu 30 cannot build an acceleration structure that follows the cut, so shadow rays against proxy geometry self-shadow. Reopens only when wgpu can build or refit one that follows the cut and a non-temporal method keeps sub-pixel switches stable. Dense static meshes use discrete LOD.
- Per-pixel class-c lighting (ReSTIR, Lumen, MegaLights), which needs a G-buffer or visibility buffer, motion vectors and a temporal denoiser: excluded by ADR 0008. Lighting is ADR 0020 ([#65](https://github.com/gariasf/praxis/issues/65)), which shades from position and normal.
- Tiled 2.5D light culling and Z-binning: 2.5D culling bounds each tile's lights by the opaque depth, so transparent surfaces in front of it need lists of their own, and Z-binning intersects tile and depth bins per pixel at shading time. Froxels, each with its own list built once against its bounds, serve the opaque and transparent passes alike.

## Consequences

- One compute culling pass composes each Instance's camera-relative transform (ADR 0014), tests the frustum and a two-phase Hi-Z pyramid of minimum reverse-Z depth (ADR 0015), and writes a compacted index buffer drawn with one `draw_indexed_indirect` per pipeline and Hi-Z phase, one native call on every backend. No count draws: Metal has none, and runs `multi_draw_indirect` as a CPU loop. One draw spans every Instance because each index packs a Meshlet record in its high bits and a vertex within that Meshlet in its low six: the cooker builds Meshlets of at most 64 vertices into each Mesh Blob, and the vertex shader reads the record for its Instance, Material and vertex base, then pulls its vertex from the vertex Arena. Each Primitive draws with its own Material unless its Instance overrides it. Culling tests Instances; tests per Meshlet wait for a profile that shows the pass raster-bound (amended 2026-10-19, [decision](https://github.com/gariasf/praxis/issues/17#issuecomment-6273209752)).
- The depth pre-pass writes 4x MSAA depth only; it seeds the Hi-Z pyramid and the lit pass's depth-equal test, and restores front-to-back cost when the culling pass writes draws out of order. With phase two's added, the shadow mask pass rebuilds each pixel's position and face normal from it, so shadow rays need no G-buffer; at an edge pixel, every surface's fragment reads the bits traced from its nearest sample.
- Lights are culled into Froxels, each with its own light list built against the Froxel's bounds; today's up to four point lights become a light buffer.
- Transparency is a sorted forward pass after the opaque pass, sharing the Froxel lists, MSAA and the opaque depth. Order-independent transparency waits for content that per-Instance sorting cannot fix.
- Render pipelines are vertex pipelines. Metal forbids ray queries in mesh-shaded pipelines, which kept the lit pass from being one until #260 moved its rays into the shadow mask pass, a compute pass; a mesh-shaded pre-pass returns with Meshlet culling, which needs the cooked format (ADR 0011).
- Reopen when either holds: on a Reference scene at 1440p with 4x MSAA, the opaque main pass takes more than 6 ms of GPU, half of ADR 0013's 12 ms, as the median over the scene's camera path, timed from the first culling dispatch to the end of the lit pass with shadow rays off, since every option traces the same rays; then B and D are prototyped on that scene before anything changes. Or lighting (ADR 0020) comes to need per-pixel G-buffer inputs. Shadow-ray time is reported beside the gate as its own line (amended 2026-10-19, [decision](https://github.com/gariasf/praxis/issues/17#issuecomment-6273209752)). The 6 ms is provisional, as ADR 0013's budgets are.
