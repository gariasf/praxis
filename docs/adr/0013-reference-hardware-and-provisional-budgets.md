# Reference hardware and provisional budgets

Budgets are judged on an Apple M4 Pro until a Windows GPU machine exists; that machine gets its own ADR. Budgets and scale targets, provisional until the first Baseline of a Reference scene at 100k visible Instances and about 5M visible triangles, M3's dense scene (accepted 2026-10-12; trigger amended 2026-10-19, [decision](https://github.com/gariasf/praxis/issues/17#issuecomment-6268956869)): 60 fps at 1440p native with CPU at most 6 ms and GPU at most 12 ms per frame, where the 6 ms bounds the wall time of each pipeline stage's critical path, waits on worker threads included, and CPU time summed across threads is measured and reported but not budgeted until then; Input latency at most 2 frame periods (33.3 ms at 60 fps) for input that drives the camera and 2 frame periods plus one Tick (49.0 ms) for input the simulation consumes, judged at p95 (amended 2026-10-12, [#20](https://github.com/gariasf/praxis/issues/20); amended 2026-10-13, ADR 0022); 100k visible Instances, about 5M visible triangles, a 10 by 10 km streamed Game world, a 2 km LOD'd view distance, and GPU memory at most 8 GB at 1440p, counted as the bytes of the buffers and textures the engine has created, summed by the engine itself on every backend, because wgpu has no allocator report on Metal (29.0.1 and 30.0.1 [ref:wgpu-hal-30-allocator-report-default]; amended 2026-10-13, [#95](https://github.com/gariasf/praxis/issues/95)); the GPU stats readback's buffers are left out of that sum, since they measure the frame rather than hold it (amended 2026-10-28, [#349](https://github.com/gariasf/praxis/issues/349)); wgpu's allocator report and Metal's `currentAllocatedSize` [ref:apple-mtldevice-current-allocated-size] are diagnostics only (unified memory has no separate VRAM pool, `docs/research/gpu-memory-residency-streaming.md`; amended 2026-10-12, `docs/research/wgpu-capability-matrix.md`); the 8 GB splits into Budgets for geometry arenas, the texture pool, Resident tails, render targets, acceleration structures and staging, whose sizes M4 sets ([decision](https://github.com/gariasf/praxis/issues/17#issuecomment-6169534752)), and acceleration structures join the count (amended 2026-10-12, ADR 0017). At M3's exit the Budgets were re-decided against that first Baseline, `town`'s at 2560×1440 with 4x MSAA on the M4 Pro (CPU frame 5.80 ms at the median and 6.21 ms at p95, GPU frame 20.1 ms, GPU memory 764 MB): each stays as written and is no longer provisional, and so do the dynamic TLAS's ceilings of 1.1 ms of CPU and 1.0 ms of GPU; what `town` breaches is ticketed as an offender, not budgeted away (amended 2026-10-30, [decision](https://github.com/gariasf/praxis/issues/211#issuecomment-6528039522)). A budget moves down freely and up only through an ADR or a map comment (`docs/agents/workflow.md`).
