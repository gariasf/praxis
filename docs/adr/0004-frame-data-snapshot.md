# Frame data snapshot

The renderer never reads the ECS World mid-frame: a prepare pass builds Frame data (the Instances that changed, lights, camera) and the renderer consumes only that; it lists no draws, since the GPU builds the frame's draw from the Instances (amended 2026-10-20, [#194](https://github.com/gariasf/praxis/issues/194)). The Instance buffer persists across frames (ADR 0003), so every Frame data must reach the renderer, in order. Frame data is an owned, `Send` value with no borrow into the ECS World (amended 2026-10-12, ADR 0016). A render-thread split then becomes a channel send, and the renderer can be tested headless without an ECS World. Today prepare (`src/render/prepare.rs`) fills Frame data from the ECS World on the main thread, and the `Renderer`, which owns the Mesh and Material pools, draws it without reading the ECS World.
