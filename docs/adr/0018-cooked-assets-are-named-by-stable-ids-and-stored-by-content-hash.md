# Cooked Assets are named by stable IDs and stored by content hash

Cooked data is a disposable cache. Every format inside it can change by bumping a version and re-cooking. Identity is different: Asset IDs are written into Materials, Chunks, Scenes and saves, and changing them breaks every reference. So each source file gets a 128-bit GUID, written once into its `assets/manifest.json` entry. An Asset ID is the first 128 bits of SHA-256 over (GUID, Asset kind, glTF name, Channel for a Texture). The glTF index replaces the name when the name is missing or not unique. A cooked Asset is a Blob named by the SHA-256 of its bytes, found through a cook index that maps Asset ID to Blob, and rebuilt when its Cook key changes. This is option A of `docs/research/asset-compression-and-cooked-data.md`. Accepted 2026-10-12 ([#23](https://github.com/gariasf/praxis/issues/23)). Partly implemented: `praxis cook` and every dev launch cook Materials, Textures and Meshes into Blobs (#146 to #149), and the runtime loads Materials and Textures (#150) and Meshes (#151), with their Meshlets (#192), from them by Asset ID.

## Considered options

- Source paths as identity: moving or renaming a file breaks every reference to it.
- A GUID in a sidecar beside each source (Unity's `.meta`): fetched sources live in git-ignored folders, so their sidecars could not be committed. The manifest already has one committed entry per source file.
- Content hashes as identity: every edit to a source would change its ID and every reference to it.
- An engine archive of content-addressed 64 KiB blocks (survey option B): few files and aligned reads, but an archive writer and reader to own before anything ships. The runtime reads Blobs through one store interface, so an archive can replace per-Asset files behind it later.
- Basis UASTC transcoded at load (option C): lands 2.1 to 2.5 dB under a direct BC7 encode (measured), for portability a desktop-only engine (ADR 0010) does not need.
- Neural texture sets decoded at load (option D): minutes of compression per Material, no Metal decoder, and no shipped title in the sources read.
- BLAKE3 or XXH3 for hashing: BLAKE3 is slower than SHA-256 on one M4 Pro core (2.39 against 2.89 GB/s) and a new dependency; XXH3 is not cryptographic.

## Consequences

- A glTF mesh renamed in Blender gets a new Asset ID. The cooker warns when an ID that something references no longer exists.
- Cook key: SHA-256 over the source bytes, the Cook keys of its dependencies, every cook setting, the format version and the encoder versions. The metallic-roughness Texture depends on the normal Texture (Toksvig, below). Each dev launch recomputes the keys of the Assets it references (hashing about 30 MB of SciFiHelmet takes about 10 ms) and cooks only the stale ones. The Cooked cache lives in git-ignored `cooked/` and is never evicted. Deleting it is always safe.
- The runtime loads Blobs only (ADR 0011). Each Blob starts with a magic and a format version (inside KTX2's key-value data for Textures). A mismatch is refused with a re-cook message; there is no migration code.
- Textures are KTX2 with every level zstd-supercompressed, stored smallest mip first, so the Resident tail (mips of 64 KiB and smaller, ADR 0017) is one contiguous byte range. KTX2 is a standard container (ADR 0011). Rows are stored unpadded, and the loader re-pitches them to 256 bytes as it writes into the `StagingBelt`.
- Formats per Channel, without RDO: albedo and emissive BC7 sRGB, normal BC5 (z rebuilt in the shader), metallic-roughness BC5 linear, occlusion BC4. BC6H waits for HDR. The encoder is `intel_tex_2` at its basic profile (BC7 measured 44.7 to 57.2 dB on DamagedHelmet's five textures, and 52.86 dB on SciFiHelmet's base colour; slow buys 0.1 to 0.7 dB for about 3.5x the time). On SciFiHelmet the BC5 and BC4 Channels measured 44.11 dB (normal), 42.71 (metallic-roughness) and 44.06 (occlusion) over their stored colour components (#96).
- Mips: a 2×2 box filter in linear light, with normals renormalised per mip. Toksvig widens each mip's roughness from the normal Texture's variance: a cook-time, non-temporal answer to specular aliasing (ADR 0008). The cooker refuses a Texture whose size is not a multiple of 4 or exceeds 8192, rather than resizing it.
- Meshes: a 28-byte vertex (position `Float32x3`, UV `Float32x2`, normal, tangent and bitangent sign as a QTangent in `Snorm16x4`, its w kept non-zero so the sign survives) against the 48 bytes before #151, and u32 indices. Positions stay f32 because 16 bits over a 256 m pivot range is 3.9 mm, far outside ADR 0014's render bar. `meshopt` reorders for vertex cache, overdraw and fetch, then encodes, then zstd compresses. Each Primitive's triangles are cut, in that order, into Meshlets of at most 64 vertices, because a packed index carries the vertex within its Meshlet in six bits (ADR 0019), and at most 124 triangles, as many as a closed mesh of 64 vertices has. Each Meshlet is the longest run the limits allow, as meshoptimizer's scan builder cuts them: its spatial builder reorders the triangles, the index codec then rotates them differently, and Goldens changed. A Meshlet is stored as one byte, its triangle count; the reader rebuilds its vertex remap and local triangles from its run of the index stream, which BLAS builds read. SciFiHelmet's Mesh Blob is 13.82 bytes per triangle this way, against 16.51 to 16.70 measured with spatial Meshlets whose remaps and local triangles are stored. The Blob also holds the Mesh's bounding box for culling; per-Meshlet bounds and cones wait for per-Meshlet tests (amended 2026-10-19, [#192](https://github.com/gariasf/praxis/issues/192)). Each Primitive stores its UV texel density, because each Primitive's Material has its own Textures (amends ADR 0017, which said per Mesh).
- A Material is its own Asset: PBR factors plus one Texture Asset ID per Channel. Primitives reference it by ID.
- A Chunk's edge is 256 m (4 by 4 cells of ADR 0014's 64 m grid; 40 by 40 Chunks cover 10 km). A v1 Chunk is a list of Placements. Each holds a Mesh Asset ID, an f64 translation from the Chunk origin, and f32 rotation and scale; f64 because f32 heights fail the simulation bar above 1024 m.
- The cooker lives in `src/cook/` behind the `praxis cook` command, with its encoder dependencies behind a default-on `cook` feature that a shipping build turns off. Procedural Reference scenes cook too, under Asset IDs derived from the scene name, so Goldens test the cooked path. Goldens regenerate once, and CI cooks before the golden test.
- New dependencies, each justified in its implementing PR: `intel_tex_2` (MIT or Apache-2.0, prebuilt ISPC kernels), `ktx2` (Apache-2.0), `meshopt` (MIT or Apache-2.0), `zstd` (BSD-3-Clause); `sha2` moves from dev-dependency to dependency.
